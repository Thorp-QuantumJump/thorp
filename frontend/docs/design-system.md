# Thorp 프론트엔드 디자인 시스템

> Jira: `FE-191`
> 적용 범위: `frontend/`
> 기준 소스: `frontend/src/index.css`, 현재 페이지와 공통 컴포넌트의 CSS Module

이 문서는 Thorp 화면의 시각적 일관성을 위한 기준이다. 구현 구조와 코드 품질 규칙은
`frontend/docs/frontend-guidelines.md`를 따르고, 이 문서는 색상, 타이포그래피, 레이아웃,
경계, 차트, 모션처럼 사용자에게 보이는 규칙에 집중한다.

문서에 적힌 값은 현재 코드에서 확인된 토큰과 반복 패턴을 기준으로 한다. 현재 코드에 공통 기준이
없거나 서로 다른 값이 사용되는 항목은 임의로 하나를 정하지 않고 **정리 필요**로 표시한다.

## 1. 디자인 방향

Thorp는 **검정에 가까운 짙은 녹색 바탕과 선명한 초록색을 사용하는 시장 분석 도구**다.
화려한 카드 모음보다 정보의 순서, 수치, 차트가 먼저 보이는 편집형 화면을 지향한다.

- 기본 배경은 `--thorp-background`를 사용한다. 옅은 회색이나 아이보리색을 페이지 배경으로 사용하지 않는다.
- 핵심 행동과 현재 선택은 `--thorp-accent`로 강조한다.
- 정보 묶음은 둥근 카드와 큰 그림자보다 얇은 선, 간격, 정렬로 구분한다.
- 장식은 시장의 흐름을 연상시키는 격자, 궤도, 은은한 초록빛처럼 콘텐츠를 가리지 않는 수준으로 사용한다.
- 수치의 의미를 색상만으로 전달하지 않고 레이블, 부호, 아이콘 또는 문장과 함께 표시한다.
- 한 화면에서 가장 중요한 행동은 하나가 먼저 보이게 한다. 이는 Constitution의 “화면마다 가장 중요한
  행동 버튼을 하나만 정한다”는 원칙을 따른다.

## 2. 색상 체계

공통 색상은 `frontend/src/index.css`의 `--thorp-*` 토큰을 사용한다. 같은 의미의 색을 CSS Module에
다시 하드코딩하지 않는다.

### 2.1 핵심 토큰

| 토큰 | 현재 값 | 용도 |
|---|---:|---|
| `--thorp-brand-primary` | `rgb(3 199 90)` | 테마와 무관한 Thorp 브랜드 원색 |
| `--thorp-brand-soft` | `#86f2a8` | 브랜드 보조 원색 |
| `--thorp-background` | `#030805` | 페이지 최하단 배경 |
| `--thorp-surface` | `#07110b` | 내비게이션, 입력, 기본 표면 |
| `--thorp-surface-raised` | `#0b1710` | 패널, 팝오버, 떠 있는 표면 |
| `--thorp-surface-muted` | `#0e1c14` | 보조 상태 영역, 약한 강조 |
| `--thorp-foreground` | `#f2f7f3` | 제목과 핵심 수치 |
| `--thorp-copy` | `#a6b5ab` | 본문과 보조 설명 |
| `--thorp-muted` | `#718278` | 메타데이터, 비활성 정보 |
| `--thorp-line` | `rgb(134 242 168 / 14%)` | 약한 구분선과 격자 |
| `--thorp-line-strong` | `rgb(134 242 168 / 24%)` | 입력 테두리와 강한 경계 |
| `--thorp-accent` | `var(--thorp-brand-primary)` | 핵심 행동과 현재 테마의 강조색 |
| `--thorp-accent-soft` | `var(--thorp-brand-soft)` | 어두운 배경 위 강조 텍스트 |
| `--thorp-accent-muted` | `rgb(3 199 90 / 12%)` | 선택 배경과 약한 강조 |
| `--thorp-action-foreground` | `#021108` | 밝은 주요 행동 표면 위 전경 |
| `--thorp-positive` | `#63dc8a` | 긍정 상태와 상승 의미 |
| `--thorp-negative` | `#ef8a68` | 부정 상태, 하락, 오류 |
| `--thorp-warning` | `#e8bd72` | 경고, 주의, 위험 상태 |
| `--thorp-neutral` | `#8fa198` | 방향성이 없는 변화 |
| `--thorp-shadow` | `0 22px 58px rgb(0 0 0 / 34%)` | 실제로 떠 있어야 하는 표면 |

글꼴은 `--thorp-font-body`, `--thorp-font-display`, `--thorp-font-mono`로 역할을 구분한다. 포커스는
`--thorp-focus-outline*`, `--thorp-focus-offset*`, `--thorp-focus-shadow*` 토큰을 사용한다.

### 2.2 표면과 텍스트 계층

```text
페이지 배경       --thorp-background
  ├─ 기본 표면    --thorp-surface
  ├─ 강조 표면    --thorp-surface-raised
  └─ 보조 표면    --thorp-surface-muted

핵심 제목·수치    --thorp-foreground
본문 설명         --thorp-copy
메타·비활성 정보  --thorp-muted
```

- 표면을 구분할 때 먼저 `--thorp-line`과 간격을 사용한다.
- 배경 단계가 꼭 필요한 입력, 팝오버, 상태 메시지에만 별도 표면색을 사용한다.
- 핵심 초록색 위의 텍스트는 `--thorp-action-foreground`를 사용한다. Tailwind의
  `--primary-foreground`도 이 토큰을 참조한다.
- 본문에 `--thorp-muted`를 사용할 때는 작은 크기와 낮은 대비가 겹치지 않도록 확인한다.

### 2.3 상태 색상

| 의미 | 토큰 | 표현 원칙 |
|---|---|---|
| 긍정·상승·완료 | `--thorp-positive` | 부호, 레이블 또는 완료 아이콘을 함께 표시한다. |
| 부정·하락·오류 | `--thorp-negative` | 오류 문장과 입력의 `aria-invalid`를 함께 사용한다. |
| 경고·주의 | `--thorp-warning` | 위험 또는 지연 이유를 짧은 문장으로 표시한다. |
| 중립·비교 기준 | `--thorp-neutral` | 방향성이 없는 값과 벤치마크에 사용한다. |
| 로딩·오래된 값·연결 실패 | `--thorp-muted` | 상태 이름과 마지막 갱신 시각을 함께 표시한다. |

금융 수치의 상승이 항상 사용자에게 좋은 결과는 아니다. 따라서 색상은 데이터 방향과 평가 의미를
혼용하지 않고 컴포넌트가 표시하는 레이블의 의미에 맞춰 사용한다.

## 3. 타이포그래피

### 3.1 글꼴

- 전역 본문은 `--thorp-font-body`의 `Pretendard`와 시스템 UI 글꼴 순서를 사용한다.
- 랜딩처럼 큰 메시지가 중심인 화면은 `--thorp-font-display`의 `Geist Variable`을 사용한다.
- Tailwind의 `--font-sans`와 `--font-heading`은 각각 본문과 디스플레이 토큰을 참조한다.
- 수치 표와 지표 값은 `font-variant-numeric: tabular-nums`를 사용해 자릿수를 정렬한다.
- 차트 축과 특정 시장 수치는 `--thorp-font-mono`를 사용한다.
- 한 컴포넌트 안에서 장식 목적 없이 서로 다른 본문 글꼴을 섞지 않는다.

### 3.2 현재 확인된 계층

| 역할 | 현재 사용 범위 | 특징 |
|---|---|---|
| 랜딩·인증 대형 제목 | `clamp(2.5rem, …, 7.1rem)` | 짧은 문장, 촘촘한 자간, 약 `0.98` 행간 |
| 시장 섹션 제목 | `clamp(1.75rem, 3vw, 2.8rem)` | 섹션의 핵심 문장 |
| 페이지 요약 제목 | `clamp(1.15rem, 2vw, 1.45rem)` | 컴팩트한 시장 상태 요약 |
| 패널·카드 제목 | 약 `0.88rem`~`1.5rem` | 내용 밀도에 따라 사용 |
| 본문·설명 | 약 `0.72rem`~`0.9rem` | `--thorp-copy`, 행간 `1.45`~`1.8` |
| 메타·캡션 | 약 `0.62rem`~`0.72rem` | `--thorp-muted`, 짧은 정보에 한정 |
| 지표·성과 수치 | 약 `1.05rem`~`1.5rem` | 굵게, 고정폭 숫자 정렬 |

- 제목은 `--thorp-foreground`, 설명은 `--thorp-copy`, 출처와 시각은 `--thorp-muted`를 기본으로 한다.
- 대형 제목은 랜딩, 인증 진입, 빈 상태처럼 문장이 화면의 주인공인 경우에만 사용한다.
- 데이터 화면에서는 큰 제목보다 차트와 핵심 수치가 먼저 보이도록 제목 높이를 제한한다.
- 작은 메타 글자는 핵심 행동, 오류 원인, 입력 안내의 유일한 전달 수단으로 사용하지 않는다.

## 4. 레이아웃과 간격

### 4.1 페이지 폭

현재 화면은 목적에 따라 다음 최대 폭을 사용한다.

| 화면 | 현재 최대 폭 |
|---|---:|
| 랜딩·홈·인증 | `1320px` 중심 |
| 공통 헤더 | `1440px` |
| 대시보드 | `1400px` |
| 백테스트 | `1520px` |
| 내 기록 진입 | `960px` |

- 새 화면은 가장 가까운 기존 화면의 컨테이너를 재사용한다.
- 한 페이지 안에서 서로 다른 최대 폭을 임의로 추가하지 않는다.
- 좌우 여백은 데스크톱에서 현재 주로 `40px` 또는 `56px`, 모바일에서 `28px`를 확보한다.
- 데이터가 많은 영역에는 `min-width: 0`을 적용해 Grid/Flex 자식의 넘침을 막는다.
- 전체 페이지는 `overflow-x: clip` 또는 실제 콘텐츠의 반응형 재배치로 불필요한 가로 스크롤을 막는다.

### 4.2 간격과 밀도

- 현재 일반 UI의 내부 간격은 대체로 `4px`~`22px`, 페이지 섹션 간격은 `48px`~`92px` 범위다.
- 컴팩트 데이터 화면은 제목, 차트, 핵심 수치, 결과 비교가 한 화면에 최대한 함께 보이도록 구성한다.
- 같은 정보 묶음에서는 간격을 일정하게 유지하고, 다른 묶음의 시작은 간격 또는 구분선으로 명확히 한다.
- 고정 높이보다 콘텐츠와 뷰포트에 반응하는 `clamp()`와 `svh`를 우선 고려한다.
- 화면을 단순히 축소하지 않고 좁은 화면에서는 열을 줄이거나 세로로 재배치한다.

## 5. 경계, 모서리, 그림자

### 5.1 기본 원칙

**정보 구분의 기본 수단은 1px 선과 간격이다.** 모든 정보 묶음을 독립된 둥근 카드로 만들지 않는다.

- 큰 섹션은 `border-top`, `border-bottom`, `border-left`와 여백으로 구분한다.
- 연속된 지표나 성과 값은 하나의 Grid 안에서 인접 항목 사이에만 선을 둔다.
- 페이지 바탕과 같은 위계의 영역에는 그림자를 사용하지 않는다.
- 팝오버, 드로어, 스크롤된 헤더, 모달처럼 실제로 떠 있는 요소에만 그림자를 사용한다.

### 5.2 현재 모서리 사용

| 형태 | 현재 용도 |
|---|---|
| `0` | 선택 탭 밑줄, 연속 데이터 셀, 컴팩트 카드 |
| `3px`~`5px` | 입력, 버튼, 링크 포커스, 작은 상태 영역 |
| `6px`~`8px` | 선택기, 보조 버튼, 독립 패널 |
| `10px`~`13px` | 떠 있는 헤더, 캐러셀, 오버레이 카드 |
| `50%`, `99px`, `999px` | 점, 원형 장식, 진행 배지처럼 형태상 필요한 경우 |
| 큰 상단 곡선 | 홈 콘텐츠 경계의 시각적 장식에 한정 |

새 기능 화면에서는 `3px`~`8px`의 작은 모서리와 선 구분을 기본으로 한다. 큰 둥근 모서리와 강한
그림자는 기능적 위계 또는 의도된 장식이 있을 때만 사용한다.

## 6. 공통 UI 규칙

### 6.1 헤더와 내비게이션

- Thorp 워드마크는 홈 또는 서비스 시작점으로 이동한다.
- 데스크톱 내비게이션은 중앙 정렬하고 현재 경로는 초록색 밑줄과 텍스트로 표시한다.
- 스크롤 전 헤더는 투명하고, 스크롤 후에만 반투명 표면, 경계, 약한 그림자를 사용한다.
- 모바일에서는 중앙 내비게이션을 숨기고 드로어로 제공한다.
- 메뉴, 로그인, 내 기록처럼 아이콘만 남는 좁은 화면에서는 접근 가능한 이름을 유지한다.

### 6.2 버튼과 링크

| 종류 | 표현 |
|---|---|
| 주요 버튼 | 초록 배경, 어두운 전경, 명확한 한 개의 핵심 행동 |
| 보조 버튼 | 투명 배경, 강한 구분선, 밝은 전경 |
| 텍스트 링크 | 배경 없이 본문 또는 초록 텍스트, 필요한 경우 화살표 |
| 위험 행동 | 부정 색상을 사용하되 행동 내용을 텍스트로 명시 |

- 버튼은 실제 `button` 또는 이동 목적의 `a`/React Router `Link`를 사용한다.
- 처리 중과 비활성 상태는 실제 `disabled` 속성과 상태 문구로 나타낸다.
- 현재 버튼 높이는 주로 `38px`~`48px`다. 같은 폼 안에서는 높이를 통일한다.
- Hover의 이동은 현재 `translateY(-1px)` 수준이며 레이아웃을 흔들지 않는다.

### 6.3 입력과 폼

- 입력은 연결된 `label`, 안내 문구, 필드 오류 영역을 갖는다.
- 기본 입력은 `--thorp-surface` 계열 배경, `--thorp-line-strong` 테두리, 약 `5px` 모서리를 사용한다.
- 포커스는 초록 테두리와 약한 초록 링으로 표시한다.
- 오류는 `--thorp-negative`, `aria-invalid`, 구체적인 오류 문장을 함께 사용한다.
- 요청 중에는 중복 제출을 막고 버튼 문구 또는 상태 영역으로 진행 중임을 알린다.
- 성공, 오류, 네트워크 상태는 `AuthStatus`처럼 테두리·배경·아이콘·문장을 함께 사용한다.

### 6.4 패널과 데이터 묶음

- 요약 지표는 하나의 가로 Grid와 셀 사이 구분선을 우선한다.
- 독립적으로 선택하거나 확대하는 콘텐츠만 별도 패널로 분리한다.
- 카드 내부 순서는 이름 → 핵심 값 → 변화 → 해석 또는 출처다.
- 반복 카드의 제목, 수치, 메타데이터 기준선을 맞춘다.
- 설명이 길면 카드 높이를 무한히 늘리지 않고 사용 목적에 맞게 줄 수를 제한하거나 상세 화면으로 연결한다.

## 7. 차트와 데이터 시각화

차트 공통값은 `frontend/src/index.css`의 `--chart-*` 토큰을 사용한다.

| 토큰 | 용도 |
|---|---|
| `--chart-background` | 차트 배경 |
| `--chart-foreground` | 주요 축과 전경 |
| `--chart-foreground-muted` | 보조 축과 메타 정보 |
| `--chart-line-primary` | 첫 번째 핵심 계열 |
| `--chart-line-secondary` | 두 번째 비교 계열 |
| `--chart-grid` | 격자 |
| `--chart-crosshair` | 커서 기준선 |
| `--chart-tooltip-background` | 툴팁 배경 |
| `--chart-tooltip-foreground` | 툴팁 핵심 값 |
| `--chart-tooltip-muted` | 툴팁 보조 값 |
| `--chart-marker-*` | 시점과 데이터 마커 |
| `--chart-scale-01`~`05` | 강도 단계 또는 히트맵 |

- 격자는 데이터보다 먼저 보이지 않도록 `--thorp-line` 수준의 낮은 대비를 유지한다.
- 범례의 색과 차트 선 색은 동일한 토큰 또는 동일한 데이터 설정에서 가져온다.
- 툴팁은 날짜, 계열 이름, 실제 값과 단위를 표시한다.
- 여러 계열은 색상뿐 아니라 이름, 마커, 선 형태처럼 확인 가능한 단서를 함께 제공한다.
- 작은 Sparkline은 추세 보조 정보이며 핵심 값을 대신하지 않는다.
- 차트가 컨테이너를 뚫지 않도록 부모와 차트에 `min-width: 0`, 반응형 크기 계산, 필요한 clip을 확인한다.
- 상승·하락 색은 차트 의미에 맞게 사용하고, 벤치마크는 `--thorp-neutral`을 기본으로 한다.

## 8. 모션과 피드백

### 8.1 현재 모션 범위

- 입력, 버튼, 링크의 짧은 전환은 주로 `160ms`~`220ms`다.
- 스크롤 헤더의 위치와 모서리 전환은 약 `220ms`~`280ms`다.
- 콘텐츠 Reveal은 약 `900ms`, 배경 호흡과 자동 순환은 `4s`~`38s` 범위의 장식 모션을 사용한다.
- React 기반 복합 애니메이션은 현재 설치된 `motion/react`를 우선 사용하고, `App.tsx`의 최상위
  `MotionConfig reducedMotion="user"` 설정을 공유한다.

### 8.2 사용 원칙

- 짧은 조작 피드백은 빠르게 끝나며 버튼 활성화나 화면 이동을 지연하지 않는다.
- 자동 순환 모션은 사용자가 콘텐츠를 읽거나 조작하는 것을 방해하지 않아야 한다.
- 타이머, Observer, 이벤트 listener, WebGPU 자원은 컴포넌트 해제 시 정리한다.
- `prefers-reduced-motion: reduce`에서는 불필요한 transition과 animation을 제거하거나 정적 상태를 제공한다.
- 축소 모션에서도 정보, 현재 선택, 탐색 기능은 그대로 유지한다.

## 9. 접근성

- 모든 입력에는 보이는 `label`을 연결한다.
- 아이콘 버튼에는 `aria-label` 또는 보이는 이름을 제공한다.
- 주요 흐름은 Tab, Enter, Space와 필요한 방향키로 수행할 수 있어야 한다.
- 현재 포커스는 초록색 `2px`~`3px` outline 또는 ring과 `2px`~`4px` offset을 사용한다.
- 포커스 표시는 제거하지 않고 배경 및 테두리와 구분되게 유지한다.
- 모달과 드로어는 Escape 닫기, 초기 포커스, 배경 포커스 제한, 닫은 후 포커스 복원을 확인한다.
- 중요한 비동기 상태는 필요한 경우 `aria-live`를 사용한다.
- 장식 이미지와 배경은 보조기술에서 제외하고 의미 있는 이미지는 대체 텍스트를 제공한다.
- 성공·오류·상승·하락을 색만으로 구분하지 않는다.
- CSS 색상값만 보고 대비 준수를 단정하지 않고 변경한 조합을 실제 도구와 화면에서 확인한다.

## 10. 반응형 기준

- 현재 레이아웃 전환은 주로 `1050px`~`1180px`, `720px`~`900px`, `420px`~`600px` 구간에서 일어난다.
- 좁은 화면에서는 다열 Grid를 줄이고, 헤더 내비게이션은 드로어로 바꾸며, 폼은 한 열로 배치한다.
- 지표 Strip은 화면 폭이 부족할 때 최소 셀 폭과 가로 스크롤을 사용하고 `scroll-snap`으로 탐색을 돕는다.
- Sticky 또는 Fixed 요소가 모바일 뷰포트를 벗어나거나 콘텐츠를 가리지 않는지 확인한다.
- `100vh`보다 모바일 브라우저 UI를 고려한 `100svh`를 우선 검토한다.
- 최소 검증 화면에는 데스크톱과 `360px` 모바일을 포함한다.
- 높이가 짧은 화면에서는 큰 최소 높이를 해제해 주요 행동이 화면 밖에 고정되지 않게 한다.

## 11. 스타일 구현 책임

| 영역 | 기본 방식 | 책임 |
|---|---|---|
| `frontend/src/index.css` | 전역 CSS | 공통 토큰, Tailwind 연결, 최소 Reset |
| 프로젝트 페이지·기능 컴포넌트 | CSS Module | 해당 화면의 레이아웃과 전용 상태 |
| shadcn/Bklit 범용 UI | Tailwind utility | 레지스트리 구조와 범용 UI 스타일 |
| 런타임 계산값 | 인라인 스타일 | 좌표, 크기, 데이터 기반 색상, CSS 변수 전달 |

- 페이지 전용 선택자와 애니메이션을 `index.css`에 추가하지 않는다.
- CSS Module 컴포넌트에 이유 없이 Tailwind utility를 혼합하지 않는다.
- 반복되는 의미 색상은 먼저 공통 토큰을 사용한다.
- 레지스트리 원본은 업데이트 호환성을 고려하고 제품 전용 디자인은 Wrapper 또는 Props 조합으로 적용한다.
- `!important`와 임의의 큰 `z-index`로 구조 문제를 덮지 않는다.
- 현재 공통 계층은 `base 0`, `header 10`, `dropdown 20`, `overlay 40`, `modal 50`, `toast 60`을 기준으로 한다.

## 12. 정리 필요

FE-193에서 `.dark`의 회색·파란색 재정의, 랜딩의 공통 의미 색상 중복, 글꼴 역할, 포커스 토큰과
주요 행동 전경을 정리했다. 랜딩의 Glow·Gradient 등 장식 전용 색은 의도적으로 유지한다. 다음 항목은
아직 일관된 단일 기준을 확인할 수 없어 임의로 확정하지 않는다.

1. **타이포그래피 단계 과다**: `0.62rem`~`0.78rem` 사이에 유사한 크기가 다수 존재한다. 접근성 검증과
   함께 공통 단계로 줄일 필요가 있다.
2. **간격 토큰 부재**: 반복 간격이 숫자로 직접 작성되어 있으나 공통 Spacing Token은 없다.
   실제 반복 빈도와 화면 밀도를 검토한 뒤 별도 작업으로 정해야 한다.
3. **컨테이너 폭 분산**: `1320px`, `1400px`, `1440px`, `1520px`이 화면별로 사용된다. 목적에 따른
   차이인지 과거 구현 차이인지 확인하기 전에는 일괄 통일하지 않는다.
4. **브레이크포인트 분산**: `420px`부터 `1180px`까지 많은 값이 사용된다. 기존 화면을 깨지 않도록
   시각 회귀 검증과 함께 공통 구간을 정해야 한다.
5. **모서리 값 분산**: `3px`~`13px`와 여러 Pill 값이 혼재한다. 정보 패널과 떠 있는 Overlay를 구분한
   뒤 의미 토큰 도입을 검토한다.
6. **터치 영역 최소 기준 미확정**: 현재 조작 요소 높이는 약 `28px`~`48px`로 다양하다. 모바일 접근성에
    사용할 팀 공통 최소값은 별도 합의가 필요하다.

남은 항목은 기능 변경과 분리된 Jira Task와 브랜치로
진행하고, 관련 화면의 시각 회귀와 접근성 검증을 함께 수행한다.
