# Feature Specification: 가상투자

**Feature Branch**: `010-paper-trading`

**Created**: 2026-09-03

**Status**: Draft

**Input**: User description: "F10. 가상투자 — Thorp에서 백테스트로 검증한 전략을 실제 시장 데이터에 가상으로 적용하고 이후 성과를 추적한다. 시작 이후 제공된 데이터만 순차 반영하며 전략과 조건을 소급 변경하지 않고, 가상 주문·거래·자산 변화와 과거 백테스트 대비 성과를 명확히 구분해 제공한다. 실제 주문·자금 관리, 특정 데이터 공급자·브로커 연동, 랭킹 및 구체적인 이벤트 처리 구조는 제외한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 검증한 전략으로 가상투자 시작 (Priority: P1)

사용자는 자신이 조회할 수 있는 완료된 백테스트에서 전략과 조건을 선택하고, 가상투자의 실제 시작 시점,
초기 가상 자산, 대상 종목 및 가상 체결 조건을 확인한 뒤 실행을 시작한다. 시작 시 확정된 전략 버전과 전체
파라미터는 해당 실행이 끝날 때까지 고정되며 실제 자금이나 증권사 주문에는 연결되지 않는다.

**Why this priority**: 과거 검증 결과와 연결된 조건을 변경 없이 고정하고 미래 방향 실행의 출발점을 남기는
것이 가상투자의 신뢰성과 이후 추적의 전제다.

**Independent Test**: 접근 가능한 완료 백테스트를 선택해 가상투자를 시작하고, 출처 결과·전략 버전·전체
파라미터·대상·초기 가상 자산·가상 체결 조건과 실제 시작 시점이 기록되는지 확인한다. 시작 시점을 과거로
지정하거나 불완전한 조건을 사용하면 실행이 생성되지 않는지, 실제 주문이 발생하지 않는지도 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 조회할 수 있는 완료 백테스트, **When** 가상투자 시작 전 조건을 확인하고 시작하면,
   **Then** 고유한 가상투자 실행이 생성되고 출처 백테스트, 고정된 전략·조건, 초기 가상 자산과 실제 시작
   시점이 표시된다.
2. **Given** 시작 확인 화면, **When** 사용자가 주문 성격을 확인하면, **Then** 모든 주문과 거래가 가상이며
   실제 계좌·자금·증권사 주문에 영향을 주지 않는다는 사실을 명확히 알 수 있다.
3. **Given** 진행 중이거나 실패한 백테스트 또는 재사용에 필요한 조건이 불완전한 결과, **When** 사용자가
   가상투자를 시작하려 하면, **Then** 시작이 거부되고 충족하지 못한 조건이 구체적으로 표시된다.
4. **Given** 현재 시점보다 과거인 시작 시점, **When** 사용자가 소급 시작을 시도하면, **Then** 요청한
   과거 시점으로 실행되지 않고 시작은 실제 활성화된 시점으로만 확정된다.
5. **Given** 같은 시작 요청이 재전달된 상황, **When** 시스템이 이를 처리하면, **Then** 중복 실행을 만들지
   않고 원래 생성된 가상투자를 제공한다.

### User Story 2 - 이후 시장 데이터에 따른 성과 추적 (Priority: P2)

가상투자가 시작되면 사용자는 시장 데이터가 새로 제공될 때마다 어느 시점까지 반영되었는지, 현재 실행
상태와 가상 현금·보유 수량·평가 자산·손익 및 공통 성과지표가 어떻게 변했는지 확인한다. 시장 휴장이나
데이터 지연도 실패로 오해하지 않도록 마지막 반영 시점과 최신성 상태를 확인할 수 있다.

**Why this priority**: 실제 자금을 쓰지 않고 전략의 미래 방향 성과를 관찰한다는 핵심 가치는 새 데이터가
시간 순서대로 반영되고 현재 자산 상태가 계속 추적될 때 성립한다.

**Independent Test**: 가상투자 시작 후 시간 순서가 명확한 여러 시장 관측값을 제공해 각 관측값이 한 번씩만
반영되는지, 상태·현금·보유 수량·평가 자산·성과지표와 마지막 반영 시점이 일관되게 갱신되는지 확인한다.
중복, 누락, 순서가 뒤바뀐 데이터와 휴장일도 각각 시험한다.

**Acceptance Scenarios**:

1. **Given** 실행 중인 가상투자, **When** 시작 이후의 완결된 새 시장 데이터가 제공되면, **Then** 이전
   데이터 다음 순서로 한 번만 반영되고 현재 자산 상태와 마지막 반영 시점이 갱신된다.
2. **Given** 아직 새 시장 데이터가 없거나 시장이 휴장인 경우, **When** 사용자가 현황을 열면, **Then**
   실행을 실패로 표시하지 않고 마지막 반영 시점과 새 데이터 대기 상태를 보여준다.
3. **Given** 같은 시장 데이터나 처리 요청이 반복 제공된 경우, **When** 실행이 갱신되면, **Then** 중복
   신호·주문·거래·자산 변화를 만들지 않는다.
4. **Given** 선행 데이터가 누락되었거나 순서가 뒤바뀐 데이터가 도착한 경우, **When** 반영을 시도하면,
   **Then** 잘못된 순서로 전략을 진행하지 않고 대기 또는 실패 사유와 마지막 정상 반영 지점을 표시한다.
5. **Given** 가상투자가 실행 중인 동안 사용자가 화면을 닫거나 연결이 끊긴 경우, **When** 나중에 다시
   조회하면, **Then** 실행은 요청 생명주기와 독립적으로 이어졌으며 최신 상태와 누적 기록을 확인할 수 있다.

### User Story 3 - 가상 주문·거래와 자산 변화 감사 (Priority: P3)

사용자는 전략이 언제 어떤 가상 주문을 만들었고 주문이 체결·거부되거나 아직 처리되지 않은 이유가 무엇인지
확인한다. 각 가상 거래가 현금과 보유 수량, 평가 자산에 준 변화를 시간 순서로 추적하며, 판단에 사용된
시장 데이터 범위와 실행 조건까지 거슬러 올라갈 수 있다.

**Why this priority**: 성과 수치만으로는 전략이 기대대로 동작했는지 검증할 수 없다. 주문에서 거래와 자산
변화로 이어지는 근거를 추적할 수 있어야 사용자가 결과를 신뢰하고 이상을 발견할 수 있다.

**Independent Test**: 매수·매도·미체결·거부 신호가 포함된 알려진 시나리오를 실행해 모든 가상 주문과
거래의 시점·종목·방향·수량·가격·상태·근거가 보이는지 확인한다. 각 거래 전후 현금·보유 수량·자산 변화가
일치하고 모든 기록에 가상 표시가 있는지도 검증한다.

**Acceptance Scenarios**:

1. **Given** 전략이 매매 신호를 만든 실행, **When** 사용자가 주문 내역을 열면, **Then** 주문별 판단 시점,
   종목, 매수·매도 방향, 수량, 주문 조건, 참조 데이터 마감 시점, 상태와 상태 사유를 확인할 수 있다.
2. **Given** 가상 주문이 체결된 경우, **When** 거래 상세를 열면, **Then** 연결된 주문, 가상 체결 시점·가격·
   수량·금액·비용 가정과 거래 전후 자산 변화를 추적할 수 있다.
3. **Given** 가상 현금 또는 보유 수량이 부족한 주문, **When** 체결 여부를 판단하면, **Then** 사전에 확정된
   규칙에 따라 주문이 거부되거나 제한되고 그 이유가 기록되며 음수 자산을 조용히 만들지 않는다.
4. **Given** 가상 주문·거래·자산 기록을 보는 어느 화면, **When** 사용자가 기록의 성격을 확인하면,
   **Then** 실제 주문과 혼동할 수 없도록 각 항목과 화면 전체에 가상임이 명확히 표시된다.
5. **Given** 처리 중 오류 후 같은 단계가 재시도된 경우, **When** 사용자가 기록을 확인하면, **Then** 이미
   확정된 주문이나 거래가 중복되지 않고 오류와 복구 결과를 추적할 수 있다.

### User Story 4 - 백테스트와 가상투자 성과 비교 (Priority: P4)

사용자는 출처 백테스트의 과거 기간과 가상투자의 이후 기간을 나란히 보고 공통 기준의 성과와 위험 특성을
비교한다. 두 기간과 데이터 경계, 진행 중인 가상투자 지표의 잠정성, 서로 다른 결과가 생길 수 있는 이유 및
미래 수익을 보장하지 않는다는 안내를 함께 확인한다.

**Why this priority**: 과거 성과와 이후 관찰 결과를 분리해 비교해야 과적합이나 시장 변화 가능성을 인지하고,
가상 성과를 실제 수익 보장으로 오해하지 않을 수 있다.

**Independent Test**: 출처 백테스트와 후속 가상투자에 알려진 자산 시계열을 사용해 동일한 지표 정의와 단위로
각 기간의 값이 별도 계산·표시되는지 확인한다. 두 기간을 하나의 연속 수익률로 합치거나 미래 수익 보장·
투자 권유로 표현하지 않는지도 확인한다.

**Acceptance Scenarios**:

1. **Given** 하나 이상의 시장 데이터가 반영된 가상투자, **When** 비교 화면을 열면, **Then** 출처
   백테스트와 가상투자의 기간·데이터 경계·초기 조건·성과지표가 구분된 영역에 동일한 정의와 단위로 표시된다.
2. **Given** 실행 중인 가상투자, **When** 성과지표를 확인하면, **Then** 가상투자 시작 이후 데이터만으로
   계산되며 종료 전 값은 잠정적이라는 사실이 표시된다.
3. **Given** 백테스트와 가상투자 성과가 크게 다른 경우, **When** 사용자가 차이를 살펴보면, **Then** 기간,
   시장 환경, 관측 길이와 가상 체결 조건 등 확인 가능한 차이 요인을 추적할 수 있다.
4. **Given** 가상투자 비교 또는 상세 화면, **When** 사용자가 결과 설명을 읽으면, **Then** 가상 결과가 실제
   수익 또는 같은 시장 전개의 보장이 아니며 투자 자문이 아니라는 안내를 확인할 수 있다.
5. **Given** 사용자가 진행 중인 실행을 종료한 경우, **When** 이후 새 데이터가 제공되면, **Then** 종료
   시점 이후 데이터는 기존 실행에 반영되지 않고 최종 기간과 지표가 고정된다.

### Edge Cases

- 가상투자 시작 시점과 출처 백테스트 종료 시점 사이에 빈 기간이 있어도 그 빈 기간을 소급 실행하지 않는다.
  실제 시작 이후 처음 제공된 완결 데이터부터 미래 방향으로 관찰한다.
- 전략 지표 계산에 과거 관측값이 필요한 경우 시작 시 확정된 준비 데이터는 초기화에만 사용한다. 준비
  데이터로 시작 전 주문·거래·성과를 만들거나 시작 후 전략·파라미터를 재선택해서는 안 된다.
- 가상투자 시작과 같은 시각에 시장 데이터가 제공되면 데이터의 사전 정의된 이용 가능 시점이 실제 시작보다
  늦은 경우에만 반영한다. 동일 날짜라는 이유만으로 시작 전에 알 수 없던 데이터를 사용하지 않는다.
- 시장 데이터가 불완전하거나 품질 검증을 통과하지 못하면 해당 관측값을 조용히 건너뛰지 않는다. 영향을
  받는 실행, 사유와 마지막 정상 반영 지점을 표시한다.
- 늦게 도착한 정정 데이터는 이미 확정된 과거 판단·주문·거래·성과를 소급 변경하지 않는다. 정정 사실과
  향후 판단에 적용되는 기준을 기록해 사용자가 확인할 수 있게 한다.
- 거래 정지, 상장 폐지, 가격 부재 등으로 가상 체결 가격을 결정할 수 없으면 임의 가격으로 체결하지 않고
  주문 상태와 사유를 남긴다.
- 분할·배당 등 자산 상태에 영향을 주는 시장 사건은 해당 시점에 이용 가능했던 정보와 사전에 확정된 처리
  규칙에 따라 반영하고, 조정 내용과 자산 변화를 추적할 수 있게 한다.
- 동일 전략과 조건으로 여러 가상투자를 시작할 수 있지만 각 실행은 고유 식별자와 실제 시작 시점으로
  구분한다. 같은 요청의 재시도로 생성된 중복 실행은 허용하지 않는다.
- 실행 중 전략 버전, 파라미터, 대상 또는 체결 조건을 바꾸려 하면 기존 실행은 변경하지 않는다. 사용자는
  기존 실행을 종료하고 새 백테스트로 검증한 조건에서 별도 가상투자를 시작해야 한다.
- 실행을 종료하는 순간 처리 중인 시장 관측값이 있으면 사전에 정한 경계까지 완결해 반영하거나 반영하지
  않는 한 가지 규칙을 일관되게 적용하고, 최종 반영 시점을 표시한다.
- 성과지표 계산에 필요한 관측 기간이나 거래가 부족하면 0이나 임의값으로 대체하지 않고 계산 불가 사유를
  표시한다.
- 권한이 없는 사용자가 가상투자 식별자를 추측해 조회하면 실행 존재 여부, 전략, 주문·거래 또는 자산 정보를
  노출하지 않고 접근을 거부한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 인증된 사용자는 자신이 조회할 수 있는 완료된 백테스트 결과의 전략과 조건을 가상투자 대상으로
  선택할 수 있어야 한다.
- **FR-002**: 가상투자 시작에 사용하는 백테스트는 성공적으로 완료되어야 하며 전략 식별자와 버전, 전체
  파라미터, 대상 종목, 백테스트 기간·초기 자산, 데이터 기준과 실행 조건을 완전하게 식별할 수 있어야 한다.
- **FR-003**: 시작 전에 사용자는 출처 백테스트, 고정될 전략·전체 파라미터·대상, 실제 시작 기준, 초기 가상
  현금과 보유 자산, 가상 주문·체결·비용 조건을 확인하고 명시적으로 시작해야 한다.
- **FR-004**: 가상투자 시작 시점은 실행이 실제 활성화된 시점으로 확정되어야 하며 과거 시점으로 소급 지정할
  수 없어야 한다. 확정된 시작 시점은 출처 백테스트 종료 시점보다 뒤여야 한다.
- **FR-005**: 전략 계산에 준비 데이터가 필요한 경우 시작 시 확정한 준비 데이터의 범위·기준을 기록해야 한다.
  준비 데이터는 초기화에만 사용하며 시작 전 주문·거래·성과를 생성해서는 안 된다.
- **FR-006**: 필수 조건이 누락되었거나 전략·데이터·가상 체결 조건을 재현할 수 없으면 가상투자를 만들지
  않고 사용자가 바로잡을 수 있도록 실패 항목을 표시해야 한다.
- **FR-007**: 시작된 가상투자는 고유 식별자를 가져야 하며 사용자는 식별자로 실행 상태와 누적 결과를 나중에
  다시 조회할 수 있어야 한다. 화면을 닫거나 연결이 끊겨도 실행에 영향을 주어서는 안 된다.
- **FR-008**: 가상투자 실행 상태는 최소한 `시작 대기`, `실행 중`, `종료`, `실패`를 구분해야 한다. 각 상태의
  전이 시점과 사유를 기록하고 사용자가 확인할 수 있어야 한다.
- **FR-009**: 사용자는 시작 대기 또는 실행 중인 가상투자를 종료할 수 있어야 한다. 종료된 실행은 다시
  활성화하거나 이후 데이터를 반영할 수 없으며, 계속 관찰하려면 새 실행을 시작해야 한다.
- **FR-010**: 시작 후 전략 버전, 파라미터, 대상 종목, 초기 자산, 준비 데이터 기준 또는 가상 주문·체결·비용
  조건을 변경해서는 안 된다. 변경이 필요한 경우 새 백테스트 검증과 별도 가상투자를 요구해야 한다.
- **FR-011**: 가상투자는 실제 시작 이후 사용자에게 이용 가능해진 완결 시장 데이터만 처리해야 한다. 각 시장
  관측값의 시장 시점, 이용 가능 시점, 적용 시점과 데이터 버전을 추적할 수 있어야 한다.
- **FR-012**: 시장 데이터는 실행별 마지막 정상 반영 지점 다음의 시간 순서로 처리해야 하며, 선행 데이터가
  없거나 품질 검증을 통과하지 못한 데이터를 조용히 건너뛰고 이후 데이터를 처리해서는 안 된다.
- **FR-013**: 동일한 시작 요청, 시장 관측값 또는 처리 단계의 재전달·재시도는 중복 실행, 신호, 가상 주문,
  가상 거래 또는 자산 변화를 만들지 않아야 한다.
- **FR-014**: 늦게 도착한 데이터나 정정은 이미 확정된 과거 전략 판단, 주문, 거래와 성과를 소급 변경해서는
  안 된다. 정정 여부, 발견 시점, 영향과 이후 적용 기준을 기록해 사용자에게 제공해야 한다.
- **FR-015**: 시장 휴장이나 새 데이터 부재는 실행 실패와 구분해야 한다. 실행 현황에는 마지막 정상 반영
  시장 시점·적용 시점과 현재 최신성 상태를 표시해야 한다.
- **FR-016**: 데이터 또는 실행 오류가 발생하면 이미 확정된 기록을 보존하고 영향받은 실행의 상태, 오류가
  발생한 단계, 사유와 마지막 정상 반영 지점을 사용자가 확인할 수 있어야 한다.
- **FR-017**: 가상 주문과 체결은 시작 시 확정한 규칙으로만 판단해야 한다. 규칙에는 주문 판단 시점, 가상
  체결 가격 기준, 비용 가정, 현금·보유 수량 제한 및 체결 불가 처리 기준이 포함되어야 한다.
- **FR-018**: 가상 주문은 고유 식별자, 가상투자 실행, 판단 시점, 종목, 방향, 수량, 주문 조건, 근거 신호,
  참조한 데이터 마감 시점, 상태와 상태 사유를 포함해야 한다.
- **FR-019**: 가상 주문 상태는 최소한 대기, 가상 체결, 일부 가상 체결, 취소 및 거부를 구분해야 한다. 가상
  현금·보유 수량 부족이나 가격 부재로 처리할 수 없으면 그 사유를 기록해야 한다.
- **FR-020**: 가상 거래는 연결된 가상 주문, 가상 체결 시점·가격·수량·금액·비용, 거래 전후 가상 현금과
  보유 수량 변화를 포함해야 한다.
- **FR-021**: 모든 가상투자, 주문, 거래와 자산 화면 및 내보내는 기록에는 실제 주문과 혼동할 수 없도록
  `가상`임을 명확하게 표시해야 한다. 실제 계좌·자금·주문을 생성하거나 변경해서는 안 된다.
- **FR-022**: 가상투자 실행은 시장 관측값별 가상 현금, 종목별 보유 수량·평가액, 총평가자산, 누적 손익과
  그 변화를 시간 순서로 보존하고 조회할 수 있어야 한다.
- **FR-023**: 가상투자 성과는 가상투자 시작 이후 반영된 데이터와 거래만으로 계산해야 하며, 수익률·최대
  낙폭·위험조정 성과 등 지원하는 공통 지표에 백테스트 결과와 같은 정의·단위·계산 불가 기준을 적용해야 한다.
- **FR-024**: 실행 중 성과지표는 잠정 값으로, 종료된 실행의 성과지표는 최종 값으로 구분해야 한다. 필요한
  관측값이 부족하면 임의값 대신 계산 불가 사유를 표시해야 한다.
- **FR-025**: 사용자는 출처 백테스트와 가상투자를 나란히 비교할 수 있어야 한다. 각각의 기간, 데이터 기준,
  초기 조건, 성과·위험 지표를 분리해 표시하고 두 기간을 하나의 연속 성과나 단일 수익률로 합쳐서는 안 된다.
- **FR-026**: 비교 화면은 백테스트 종료, 가상투자 시작, 마지막 반영 또는 종료 시점의 경계를 명시하고,
  기간·관측 길이·시장 환경·가상 체결 조건 등 확인 가능한 차이 요인을 추적할 수 있게 해야 한다.
- **FR-027**: 모든 가상투자 결과에서 출처 백테스트, 전략 식별자·버전, 전체 파라미터, 대상, 준비 데이터,
  시작·종료 시점, 적용 데이터 버전, 가상 체결 조건 및 공통 지표 정의를 추적할 수 있어야 한다.
- **FR-028**: 확정된 가상 주문·거래·자산 기록은 이후 조회할 때 동일해야 한다. 수정이나 정정 기록이 있으면
  원래 기록, 사유, 시점과 영향을 구분해 감사할 수 있어야 한다.
- **FR-029**: 사용자는 자신이 시작했거나 명시적으로 접근 권한을 가진 가상투자만 조회·종료할 수 있어야 한다.
  권한 없는 요청은 실행 존재 여부나 전략·거래·자산 정보를 노출하지 않고 거부해야 한다.
- **FR-030**: 가상투자와 비교 결과에는 실제 시장의 체결·비용·유동성과 차이가 있을 수 있으며 미래 수익이나
  동일한 시장 전개를 보장하지 않고 투자 자문이 아니라는 안내를 제공해야 한다.
- **FR-031**: 이 기능은 검증된 전략의 미래 방향 가상 실행, 상태·가상 주문·거래·자산·성과 추적과 출처
  백테스트 비교까지만 제공한다. 실제 증권사 주문, 실제 자금 관리, 특정 실시간 데이터 공급자나 브로커 연동,
  가상투자 랭킹, 전략 추천 및 구체적인 이벤트 처리·분산 처리 기술 선택은 포함하지 않는다.

### Key Entities *(include if feature involves data)*

- **가상투자 실행(Paper Trading Run)**: 완료 백테스트의 고정된 전략과 조건을 미래 방향 시장 데이터에
  가상 적용하는 장기 실행. 고유 식별자, 소유자, 출처, 실제 시작·종료 시점, 상태, 마지막 정상 반영 지점과
  실패 사유를 가진다.
- **실행 조건 스냅샷(Run Condition Snapshot)**: 시작 시 고정되어 변경되지 않는 전략 식별자·버전, 전체
  파라미터, 대상, 초기 가상 자산, 준비 데이터 범위와 가상 주문·체결·비용 규칙을 나타낸다.
- **시장 관측 기록(Market Observation Record)**: 실행이 검토한 시장 데이터 단위. 시장 시점, 이용 가능
  시점, 적용 시점, 완결·품질 상태, 데이터 버전과 실행별 처리 결과를 가진다.
- **가상 주문(Virtual Order)**: 전략 판단으로 생성된 실제 효력이 없는 주문 기록. 판단 시점, 종목, 방향,
  수량, 주문 조건, 근거 신호·데이터 마감 시점, 상태와 사유를 가진다.
- **가상 거래(Virtual Trade)**: 확정된 규칙에 따라 가상 체결된 주문의 전부 또는 일부. 주문 연결, 체결
  시점·가격·수량·금액·비용과 전후 자산 변화를 가진다.
- **가상 자산 스냅샷(Virtual Portfolio Snapshot)**: 각 반영 시점의 가상 현금, 종목별 보유 수량·평가액,
  총평가자산, 누적 손익과 직전 스냅샷 관계를 나타낸다.
- **성과 비교(Performance Comparison)**: 출처 백테스트와 후속 가상투자의 서로 분리된 기간·조건·성과·위험
  지표를 공통 정의와 단위로 연결한 조회 결과다.
- **정정·실행 기록(Correction and Execution Record)**: 지연·정정 데이터, 오류, 재시도, 상태 전이와 종료를
  누가 언제 어떤 근거로 처리했는지 보존하는 감사 정보다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 생성된 가상투자의 100%에서 완료된 출처 백테스트, 전략 버전, 전체 파라미터, 대상, 초기 가상
  자산, 준비 데이터 범위, 실제 시작 시점과 가상 체결 조건을 추적할 수 있다.
- **SC-002**: 가상투자 시작 전 데이터 또는 해당 판단 시점에 이용 가능하지 않았던 데이터로 생성된 가상
  주문·거래 사례가 0건이다.
- **SC-003**: 시작 후 전략·파라미터·대상·초기 조건을 소급 변경하거나 늦은 정정 데이터로 이미 확정된 판단·
  주문·거래·성과를 다시 쓴 사례가 0건이다.
- **SC-004**: 동일한 시작 요청, 시장 관측값 또는 처리 단계가 반복되어도 중복 실행·가상 주문·가상 거래·
  자산 변화가 발생한 사례가 0건이다.
- **SC-005**: 가상 주문과 거래 기록의 100%에서 근거 신호와 데이터 마감 시점, 적용 규칙, 주문부터 거래와
  자산 변화까지의 관계를 추적할 수 있다.
- **SC-006**: 가상투자 화면과 제공 기록의 100%가 `가상`임을 명확히 표시하며, 이 기능으로 실제 주문이나
  실제 자금 변화가 발생한 사례가 0건이다.
- **SC-007**: 100개의 가상투자가 동시에 실행 중이고 각각 완결된 일별 시장 관측값 1건을 받을 때, 95% 이상이
  데이터 이용 가능 시점부터 5분 이내에 사용자에게 최신 상태·자산·마지막 반영 시점을 제공한다.
- **SC-008**: 실행 현황·가상 주문·거래·자산 또는 비교 조회의 95%에서 사용자는 요청 후 3초 이내에 최신
  확정 기록이나 명확한 대기·오류 상태를 확인한다.
- **SC-009**: 백테스트와 가상투자를 비교한 결과의 100%에서 두 기간과 데이터 경계가 분리되고, 동일한 공통
  지표 정의·단위가 사용되며 두 기간을 합친 성과가 제공되지 않는다.
- **SC-010**: 사용성 검증에서 대상 사용자의 90% 이상이 3분 이내에 완료 백테스트를 선택하고 고정 조건과
  가상 주문의 성격을 확인한 뒤 가상투자를 시작할 수 있다.
- **SC-011**: 사용성 검증에서 대상 사용자의 85% 이상이 백테스트와 가상투자 기간의 차이, 진행 중 지표의
  잠정성, 가상 성과가 실제 수익을 보장하지 않는다는 점을 추가 도움 없이 정확히 설명할 수 있다.

## Assumptions

- 대상 사용자는 인증된 Thorp 사용자이며 자신이 조회할 수 있는 완료 백테스트만 가상투자 출처로
  선택한다. 다른 사용자의 가상투자 공유와 공개는 이번 범위에 포함하지 않는다.
- “백테스트로 검증한 전략”은 성공적으로 완료되어 전략 버전, 전체 설정, 사용 데이터와 실행 조건을 추적할
  수 있는 전략을 뜻한다. 특정 성과 기준을 넘었다는 뜻은 아니며 가상투자 시작 전 사용자가 직접 선택한다.
- 하나의 가상투자는 하나의 완료 백테스트 조건을 그대로 고정한다. 다른 초기 자산, 파라미터 또는 체결 조건을
  시험하려면 변경된 조건으로 새 백테스트를 완료한 뒤 별도 가상투자를 시작한다.
- 초기 가상 현금과 보유 자산 및 가상 체결·비용 조건은 출처 백테스트와 같은 기준을 사용한다. 비교 가능한
  조건을 복원할 수 없는 오래된 결과는 가상투자 출처로 사용할 수 없다.
- 시장 데이터의 기본 관측 주기와 거래일 기준은 대상 시장 및 전략이 사용하는 완결 데이터 기준을 따른다.
  특정 실시간 데이터 공급자, 수집 지연 보장 또는 장중 실행은 계획 단계에서 자동 포함하지 않는다.
- 준비 데이터는 이동 평균 등 전략 상태 초기화에 필요한 시작 이전 관측값이다. 그 범위는 시작 시 확정하며
  시작 전 거래나 성과로 간주하지 않는다.
- 종료는 사용자의 명시적 종료 또는 복구할 수 없는 실패로 발생한다. 일시적인 휴장·데이터 부재는 종료나
  실패가 아니며, 종료된 실행은 읽기 전용 기록으로 보존한다.
- 백테스트와 가상투자 비교에는 기존 공통 성과지표 정의를 재사용한다. 관측 기간 차이 때문에 직접 해석하기
  어려운 지표는 숨기지 않고 계산 불가 또는 주의 사유를 함께 표시한다.
- 시장 데이터의 수집 방식, 장기 실행 방식, 상태 전달 방식, 저장 방식과 처리 확장 기술은 계획 단계에서
  측정 목표와 현재 규모를 근거로 결정한다.

## Constitution Alignment

- **원칙 I·II (독립 실행 경계와 추적성)**: FR-007~FR-009와 FR-016은 장기 가상투자가 화면 요청과
  독립적으로 지속되고 고유 식별자, 명시적 상태 전이와 누적 결과로 추적되도록 요구한다. 구체적인 실행·상태
  전달 구조는 명세하지 않는다.
- **원칙 III (실측 후 기술 도입)**: FR-031은 이벤트·분산 처리 기술을 범위에서 제외한다. SC-007·SC-008의
  처리량과 사용자 응답 목표를 측정한 후 현재 요구를 만족하는 가장 단순한 기술을 계획한다.
- **원칙 IV (파트 경계 계약)**: 실행 조건, 시장 관측값, 상태, 가상 주문·거래·자산과 성과 비교는 생산자와
  소비자가 공유할 계약이다. 구체적 필드·전이·호환성은 계획 단계에서 문서화하고 함께 변경해야 한다.
- **원칙 V (신뢰성)**: FR-010~FR-014가 미래 데이터 참조와 소급 변경을 금지하고 재시도 시 중복을 막는다.
  FR-023~FR-027은 동일한 지표 정의, 기간 분리와 전체 조건 추적을 통해 재현성과 비교 가능성을 보장한다.
- **보안·데이터 제약**: FR-029가 소유 범위 밖 실행의 정보 노출을 막고, 실행 조건과 사용자 표시에는 비밀값을
  포함하지 않는 기존 프로젝트 정책을 적용한다.
- 원칙에서 벗어나는 요구사항은 없다.
