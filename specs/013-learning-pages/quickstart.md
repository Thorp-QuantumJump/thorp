# Quickstart: 배우기 검증

**Spec**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Date**: 2026-09-16 · 2판 2026-10-05

구현이 spec을 만족하는지 재현하는 검증 가이드다. 계약·필드의 정의는 [contracts/](contracts/)와 [data-model.md](data-model.md)를 본다. 이 문서는 무엇을 실행하고 무엇이 나와야 하는지만 적는다.

- §2~§5는 9월 판(B01~B06) 확인이며 2판 뒤에도 **첫 단계 공개 전 상태의 회귀 확인**으로 그대로 쓴다. B06 실행 결과는 [validation.md](validation.md)에 있다.
- §6~§13은 2판(B07~B16) 확인이다. 각 절 머리에 해당 묶음을 적는다. 실행 결과는 B15가 `validation.md`에 2판 절로 더한다.

## 0. 준비

- Java 21, Node.js·npm, Docker(PostgreSQL Testcontainers와 로컬 DB)
- 로컬 DB `localhost:5432/thorp`와 014 로그인이 동작하는 상태
- 001의 열린 대응표. 없으면 예시 판정은 `SECTOR_MAP_NOT_READY`가 된다(§3-4에서 이 경우를 따로 확인한다)
- 관리 권한을 줄 로그인 계정 하나. 그 계정의 사용자 ID를 `THORP_LEARNING_ADMIN_USER_IDS`로 넘긴다([research](research.md) R5)
- **(2판)** 나의 학습을 확인할 일반 계정 둘(A·B). B는 기록이 쌓인 계정으로 쓴다(SC-005 관찰용 시험 계정과 같은 방식)

**로컬 프로필 주의**: `application-local.yml`은 Flyway를 끄고 Hibernate가 스키마를 만든다. 이 상태에서는 마이그레이션이 넣는 **초기 자리(9월 판 아홉 글·열네 용어, 2판 여섯 단계·새 글 18편)가 생기지 않는다.** 초기 자리를 확인하려면 아래처럼 Flyway를 켠다. **(2판)** 나의 학습 네 테이블(`learning_progress`·`learning_answer`·`learning_exp_entry`·`learning_badge_award`)은 JPA 엔티티 없이 JdbcTemplate으로만 쓰므로 이 상태에서는 테이블 자체가 생기지 않아 `/learning/me`가 실패한다. 그래서 §6 이후의 2판 확인은 아래 명령으로 Flyway를 켜고 한다.

```bash
SPRING_PROFILES_ACTIVE=local SPRING_FLYWAY_ENABLED=true SPRING_JPA_HIBERNATE_DDL_AUTO=validate SPRING_SESSION_JDBC_INITIALIZE_SCHEMA=never THORP_LEARNING_ADMIN_USER_IDS=1 ./gradlew bootRun
```

Flyway가 Spring Session 테이블도 만들므로 이 확인에서는 별도 세션 스키마 초기화를 끈다. `backend/.env`의 메일 설정도 필요하다([backend/CLAUDE.md](../../backend/CLAUDE.md)). 메일을 보내지 않는 검증에는 더미 값을 쓴다. 아래의 게시·단계 공개·대응표 변경은 **합성 자료 전용 로컬 DB에서** 한다. 단계 공개는 되돌릴 수 없으므로 운영 DB에서 시험하지 않는다.

**(2판) 원고**: §7 이후는 합성 원고가 필요하다. `docs/learning-content/README.md`(B14)의 형식으로 만든 시험용 원고를 쓰고, 운영 원고나 추천 예시를 쓰지 않는다.

## 2. 공개 조회 (비로그인, 9월 판 회귀)

아래 `curl`은 백엔드 경로를 직접 부른다. 브라우저에서는 `/api` 접두사가 붙는다.

### 2-1. 게시 전 빈 목록

```bash
curl -s localhost:8080/learning/articles
```

**기대**: `success: true`, `data.articles: []`. 오류가 아니다(spec Edge Cases).

### 2-2. 없는 글과 준비 안 된 용어

```bash
curl -s -o /dev/null -w "%{http_code}\n" localhost:8080/learning/articles/returns-and-losses
curl -s localhost:8080/learning/terms/max-drawdown
```

**기대**: 첫 줄 `404`, 둘째는 `error.code: LEARNING_TERM_NOT_READY`. 초안 자리가 있어도 공개되지 않는다.

## 3. 관리 흐름 (관리 계정 로그인, 9월 판 회귀)

브라우저에서 §0의 관리 계정으로 로그인한 뒤 `/admin/learning`을 연다. 이 절은 단계를 하나도 공개하지 않은 상태에서 V1 초안(기존 아홉 글)으로 한다. 2판 뒤에는 이 게시가 '이전 판 고치기'다(R16).

### 3-1. 권한

| 계정 | `/admin/learning` | 기대 |
|---|---|---|
| 비로그인 | 로그인 안내로 이동 | 401 처리(FR-016) |
| 허용 목록에 없는 로그인 계정 | 관리 화면이 그려지지 않음 | access 404. 일반 화면 어디에도 편집 수단이 없음(US5 시나리오 1) |
| 허용 목록의 계정 | 아홉 글 목록(2판 뒤에는 27편), 모두 초안 | |

### 3-2. 검사에 걸리는 게시 (US5 시나리오 3)

`returns-and-losses`를 열어 아래처럼 저장한 뒤 게시한다.

먼저 제목·질문·설명 문단·예시 두 섹터를 채우고, 이 글의 두 용어(`max-drawdown`·`net-total-return`)에 이름·문장을 넣어 각각 본문의 `term` 블록에 한 번씩 연결한다. 이 준비 없이 초기 초안을 바로 게시하면 아래 세 항목 외에 필수 항목 검사도 걸린다.

- 예시 섹터 두 개, 비중 50.0%·45.0%
- `paragraph` 블록에 `추천 비중` 포함
- 용어 `max-drawdown` 문장에 `-30%` 포함

**기대**: 게시되지 않는다. 화면에 세 항목(`EXAMPLE_WEIGHT_SUM`·`FORBIDDEN_EXPRESSION`·`RESULT_NUMBER_OUTSIDE_HYPOTHETICAL`)이 각각의 위치와 함께 보인다. 공개 조회는 §2-2 결과 그대로다.

### 3-3. 통과하는 게시 (US5 시나리오 2·5)

세 문제를 고친다. 비중은 50.0%·50.0%로 맞추고, 숫자는 `hypothetical` 블록으로 옮기고, 금지 표현은 지운다. `max-drawdown`·`net-total-return` 용어가 본문에 `term` 블록으로 한 번씩 들어가게 한 뒤 게시한다.

**기대**:
- 게시 성공, `revisionNo: 1`, **(2판)** `edition: LEGACY`, `checkVersion: learning-publish-checks-v1`
- 로그아웃한 탭에서 `/learn`에 글이 보이고, `/learn/returns-and-losses`의 용어 블록 문장이 `GET /learning/terms/max-drawdown`의 `sentence`와 같다(SC-003)
- 관리 목록에 마지막 게시 기록과 게시한 사용자 ID가 보인다(FR-018)

### 3-4. 대응표가 준비되지 않았을 때

001 대응표가 없는 DB에서 §3-3의 게시를 시도한다.

**기대**: `EXAMPLE_SECTOR_IN_MAP`으로 거절된다. 판정할 수 없는 것을 통과로 세지 않는다(원칙 VI).

### 3-5. 게시된 글을 고치는 동안 (SC-006)

게시된 글의 문단 하나를 고쳐 **저장만** 한다.

**기대**: 공개 조회 응답이 바뀌지 않는다. 관리 목록에 `hasUnpublishedChanges: true`가 보인다.

### 3-6. 덮어쓰기 방지 (R12)

같은 글을 두 탭에서 연다. 한 탭에서 저장한 뒤 다른 탭에서 저장한다.

**기대**: 두 번째 탭이 `LEARNING_DRAFT_CHANGED`를 받고, 입력한 내용이 화면에 남은 채 새로 불러오라는 안내가 보인다.

### 3-7. 편집 중 만료 (spec Edge Cases)

편집 중에 서버 세션을 끝낸다(다른 탭에서 로그아웃). 그 뒤 저장을 누른다.

**기대**: 재로그인 안내가 보인다. 재로그인 뒤 같은 글을 열면 저장하지 못한 내용을 복원할지 묻는다.

### 3-8. 게시 취소 (US5 시나리오 6)

`returns-and-losses`를 게시 취소한다.

**기대**:
- `/learn` 목록에서 사라진다
- `/learn/returns-and-losses` 주소로 들어가면 오류 화면이 아니라 "지금은 볼 수 없는 글" 한 문장과 목록 연결이 보인다
- `GET /learning/terms/max-drawdown`이 `LEARNING_TERM_NOT_READY`다
- 관리 목록의 마지막 기록이 `UNPUBLISH`다

게시 취소를 한 번 더 누른다. **기대**: 200이고 기록이 늘지 않는다.

## 4. 배우기 화면 (비로그인, §3-3 게시 상태, 9월 판 회귀)

### 4-1. 목록과 글 (US1)

`/learn`을 연다.

**기대**:
- 설문·숙련도 질문 없이 목록이 바로 보인다(시나리오 5)
- 글을 열면 질문 하나와 설명이 보이고, `hypothetical` 블록에 '가상의 계산 예' 표시가 있다(시나리오 6)
- 예시 비중이 투자 권고가 아니라는 표시가 있다(시나리오 4)
- 브라우저 저장소에 학습 기록이 생기지 않는다(FR-012, FR-020). **(2판)** 첫 단계 공개 전에는 보기 전환이 없으므로 화면 상태 키도 생기지 않는다
- **(2판)** 첫 단계 공개 전이므로 9월 판과 같은 목록이다. 단계·'이전 판'·'준비 중'·'나의 학습'이 보이지 않는다(FR-031 "지금 모습 그대로")

### 4-2. 불러오지 못함 (US1 시나리오 7, SC-007)

개발자 도구에서 `/api/learning/*` 요청을 막고 `/learn`을 새로 고친다.

**기대**: 빈 목록이 아니라 불러오지 못했다는 한 문장과 다시 시도 버튼이 보인다. 상단 메뉴의 '전략 진단'은 그대로 있다. 요청 막기를 풀기 전에는 자동으로 다시 요청하지 않는다.

### 4-3. 예시로 진단 시작 (US2)

글에서 '이 예시로 전략 진단하기'를 누른다.

| 먼저 해 둔 것 | 기대 | 근거 |
|---|---|---|
| 아무것도 입력하지 않음 | 섹터·비중 화면에 예시 50.0%·50.0%가 채워지고 예시 표시가 있다 | 002 FR-012 |
| 002에서 다른 섹터를 이미 고름 | 덮어쓸지 먼저 묻는다. 거절하면 기존 값이 남는다 | 002 FR-012 |

### 4-4. 대응표에서 사라진 예시 섹터 (US2 시나리오 3)

게시 뒤 열린 대응표에서 예시 섹터 하나를 뺀 판을 연다.

- 핵심 요약 두 줄, 소제목 둘
- 본문 약 1,500자(3분)
- 확인 문제 하나, 정답 둘인 문제
- 문단에 `-30%`(괄호 밖), 제도 안내에 기준 시점 없음

**기대**: `KEY_SUMMARY`·`HEADING_COUNT`·`READING_TIME`·`QUIZ`(두 항목)·`RESULT_NUMBER_OUTSIDE_HYPOTHETICAL`·`ELEMENT_FORMAT`이 위치와 함께 모두 보인다. `READING_TIME`의 문장에 계산한 분과 글자 수가 있다.

### 7-3. 예외 자리 (FR-005, FR-017, FR-026)

아래만 남기고 나머지를 고쳐 다시 미리 검사한다.

- 오해의 틀린 생각 칸에 `확률`, 확인 문제 틀린 보기에 `추천합니다`
- 문단에 `(예: 왕복 약 0.19%)`, 비교 표 칸에 `12%`, 확인 문제 질문에 `20%`

**기대**: 걸리는 항목이 없다. 같은 표현을 오해의 바로잡기 칸이나 정답 보기에 쓰면 `FORBIDDEN_EXPRESSION`으로 걸린다. `(예:` 없이 괄호 안에 쓴 `0.19%`는 걸린다.

같은 초안을 '미리 보기'로 연다.

**기대**: §9의 독자 화면과 같은 부품으로 그려지고, 학습 기록·완료 카드 없이 확인 문제가 비로그인 모드로 보인다. 공개 조회와 나의 학습 테이블은 바뀌지 않는다.

### 7-5. 같은 문제 판정 (spec Edge Cases)

`volatility-is-not-loss`가 공개된 뒤(§8-4) 계정 A가 q1·q2에 답한 상태에서 관리 화면으로 고친다: q1은 질문 글자만, q2는 정답 보기를 다른 보기로 바꾸고 게시한다.

**기대**: 게시 응답의 `renamedQuestions`에 q2만 있다. 계정 A의 글 화면에서 q1은 첫 답 결과 그대로, q2 자리에는 새 식별자의 답하지 않은 문제가 보인다. 계정 A의 경험치는 줄지 않는다. 게시 직후 같은 편집 화면에서 q1의 질문 글자를 한 번 더 고쳐 저장하면 거절 없이 저장되고, 저장 요청의 q2 자리 식별자는 `renamedQuestions`의 새 식별자다.

## 8. 단계 공개 (B08·B14)

### 8-1. 순서 (US5 시나리오 7)

1단계를 공개하지 않은 채 2단계를 '단계 공개'한다.

**기대**: 409 `LEARNING_STAGE_ORDER`. 아무 글도 게시되지 않는다.

### 8-2. 미리 검사는 아무것도 바꾸지 않는다 (R23)

1단계의 글 가운데 하나를 일부러 검사에 걸리게 두고 `GET /admin/learning/stages/etf-market-basics/readiness`를 부른다.

**기대**: `ready: false`, 그 글의 항목이 보인다. 공개 조회·관리 목록·변경 기록이 그대로다.

### 8-3. 하나라도 걸리면 아무것도 게시하지 않는다 (US5 시나리오 8)

같은 상태에서 '단계 공개'를 누른다.

**기대**: 422 `LEARNING_STAGE_CHECK_FAILED`, 글마다 이유. 1단계의 다른 글도 게시되지 않고 `released_at`·변경 기록이 없다.

### 8-4. 공개 (US5 시나리오 9, FR-031)

걸린 글을 고쳐 1단계를 공개한 뒤, 2단계 글 넷(기존 `returns-and-losses` 포함)을 준비해 2단계도 공개한다.

**기대**:
- 커리큘럼: 1·2단계 `OPEN`, 글 번호 `1-1`…`1-4`, `2-1`…`2-4`. 3~6단계 `PREPARING`, 새 글 제목·편수·날짜가 없다. 3~5단계의 기존 글이 `previousEditionArticles`에 있다
- `changeLog` 두 줄, 2단계 줄은 `newCount: 3`, `rewrittenCount: 1`, `rewrittenTitles: ["수익과 손실"]`
- 공개된 글은 `edition: CURRENT`, 3단계 기존 글은 `edition: PREVIOUS`
- 화면: 공개 경계 한 줄 '지금 공개된 단계는 1·2단계입니다. 3~6단계는 준비 중입니다.'

### 8-5. 용어 넘기기 (R24)

2단계 공개 전에 `/strategy`의 '변동성 관측 기간' 도움말을 연다. 2단계 공개 뒤 다시 연다.

**기대**: 공개 전에는 `inverse-volatility` 글로 가는 연결과 그 글의 문장, 공개 뒤에는 `volatility-is-not-loss` 글과 뜻 문장. 그 사이 '설명 준비 중'이 보이는 순간이 없다. 관리 목록에서 `inverse-volatility`의 초안에 남은 `volatility` 용어 블록은 다음 이전 판 고치기 게시에서 `TERM_BLOCKS_MATCH`로 걸린다.

### 8-6. 공개된 단계에 글 더하기 (FR-031)

관리 API로 1단계에 새 V2 글을 만들어 글마다 게시한다.

**기대**: 커리큘럼에 `1-5`로 나타나고 `notices`·`changeLog`에 `ARTICLE_ADDED` 한 줄. 같은 글을 게시 취소했다가 다시 게시해도 줄이 늘지 않는다.

### 8-7. 글이 0편이 된 공개 단계 (FR-031)

시험 DB에서 2단계의 글을 모두 게시 취소한다.

**기대**: 2단계 `status: REPREPARING`, 점선 모습과 '이 단계의 글을 다시 준비하고 있습니다. 글이 게시되면 이 자리에 보입니다.'. 공개 경계 한 줄은 여전히 2단계까지를 공개된 단계로 센다. 다시 게시해도 단계 공개를 다시 하지 않고 공개일이 그대로다.

### 9-5. 이전 판 (FR-031, US6 시나리오 12)

`/learn/weights-and-rebalancing`(3단계, 공개 전)을 연다.

**기대**: 글 머리에 '이전 판', 번호 없음, 글 끝에 '이 글은 새 기준으로 다시 쓰기 전의 판입니다. 그래서 읽은 기록과 확인 문제를 남기지 않습니다.'와 '배우기 목록으로'만 있다.

| 끝 표지 위치 | 예시 블록 앞. 진단 버튼 아래까지 내리지 않아도 완료된다 |

### 10-2. 읽은 위치와 이어서 읽기 (FR-020, US6 시나리오 5)

글을 62% 근처까지 읽고 (가) 다른 메뉴로 옮긴 경우와 (나) 탭을 닫은 경우를 각각 확인한다.

**기대**: 두 경우 모두 위치 요청이 한 번 가고, (나)는 `keepalive` 요청에 `X-XSRF-TOKEN` 헤더가 있다. 더 내리지 않고 다시 열었다 떠나도 요청이 가고, 그 글이 '이어서 읽기'의 대상이 된다. 열자마자(0%) 떠난 글은 '읽는 중'이 된다. 목록에 '62% 읽는 중', 목록에서 글을 누르면 맨 위에서 열리고 '62%까지 읽었습니다 · 이어서 읽기' 한 줄이 있다. '이어서 읽기'로 열면 그 위치에서 열린다. 계정 A로 다른 브라우저에서 들어와도 같다.

### 10-3. 저장한 뒤 공개 (FR-022, US6 시나리오 3·9)

| 행동 | 기대 |
|---|---|
| 확인 문제에 답함 | 고른 보기가 잠기고, 저장 응답 뒤에 맞았는지와 정답·풀이가 보인다 |
| `/api/learning/me/*`를 막고 답함 | 정답·풀이가 보이지 않고 '기록되지 않았습니다'와 '다시 시도'. 다시 시도는 같은 보기를 보낸다 |
| 두 탭에서 같은 문제에 다른 보기로 답함 | 늦은 탭이 앞 탭의 첫 답을 받아 그대로 보인다(첫 답 한 번) |
| 완료를 막고 글 끝까지 읽음 | 완료 카드와 확인 문제 대신 '기록되지 않았습니다'와 '다시 시도'. 글 읽기와 상단 메뉴의 진단 진입은 그대로다 |

### 10-4. 다시 풀기와 끈기 (FR-022)

두 문제를 모두 틀린다.

**기대**: 맞힌 개수 '2문제 중 0개'와 '다시 풀기'. 다시 풀어 하나를 맞히면 그 글의 용어가 익힘이 되고 '끈기' 배지 알림이 조용히 보인다. 경험치는 늘지 않는다.

### 10-5. 경험치 상한 (FR-028, SC-015)

| 상황 | 기대 경험치 |
|---|---|
| 세 문제 글을 완료하고 모두 맞힘 | 20 + 60 + 20 = 100 |
| 두 문제 글에서 하나만 맞힘 | 20 + 30 = 50 |
| 모두 답한 글에 운영자가 문제를 더함 → 새 문제를 맞힘 | 0. 정답 배지 개수에는 든다 |
| 세 문제 중 하나만 답한 상태에서 운영자가 정답을 바꿔 새 문제가 됨 → 나머지를 모두 맞힘 | 정답 몫 합 60을 넘지 않는다 |

### 10-6. 단계 완주와 배지 (FR-024, US6 시나리오 4·8)

1단계 글을 모두 완료한다.

**기대**: 마지막 글의 완료 카드에 단계 완주 50과 '1단계 완주' 배지가 조용한 알림으로 보인다(폭죽·소리·화면 덮기 없음). 그 뒤 관리 계정이 1단계에 글을 더하면 배지는 그대로이고 단계 진행이 '5편 중 4편 읽음'이 된다.

### 10-7. 운영자 변경으로 채워진 기준 (FR-024, spec Edge Cases)

계정 B가 2단계 글 넷 가운데 셋을 완료한 상태에서 관리 계정이 남은 한 편을 게시 취소한다.

**기대**: 계정 B가 다음에 배우기 목록(요약 패널)이나 '나의 학습'을 열 때 '2단계 완주' 배지와 50이 생기고, 그때가 획득 날짜다.

### 10-8. 레벨 문구 (FR-029)

1·2단계만 공개된 상태(8편)에서 '나의 학습'을 연다.

**기대**: 레벨 길이 레벨 4까지 실선, 그 뒤 점선과 '레벨 5부터는 단계가 더 공개된 뒤 닿을 수 있습니다.'. '최고 레벨' 표시가 없다.

### 10-9. 학습 초기화 (FR-025, US6 시나리오 11)

`/account/profile`에서 '학습 초기화'를 누른다.

**기대**: 지워지는 것과 되살릴 수 없다는 안내로 확인을 받는다. 확인하면 모든 글이 '안 읽음', 레벨 1, 받은 배지 0. 같은 글로 경험치를 처음부터 다시 받는다. '나의 학습' 화면에는 이 단추가 없다. 계정 B의 기록은 그대로다.

### 10-10. 로그인 상태 (spec Edge Cases, R33)

| 상황 | 기대 |
|---|---|
| 새로 고친 직후(로그인 확인 중) | 나의 학습·완료 카드·확인 문제가 잠깐도 '안 읽음'·레벨 1로 보이지 않는다 |
| 로그아웃 누름 | 그 즉시 나의 학습이 사라지고 브라우저 저장소에 남지 않는다 |
| 서버 세션 만료 뒤 글 완료 | '기록되지 않았습니다'와 '다시 시도', 014 FR-012의 재로그인 안내. 다시 로그인하면 보던 배우기 화면으로 돌아온다 |
| 비로그인으로 글을 열고 확인 문제에 답한 뒤 다른 탭에서 로그인 | 그 글의 글 끝과 머문 시간이 처음부터 다시 시작한다. 로그인 전 답은 계정에 없고, 계정에서 답하지 않은 문제는 답하지 않은 문제로 보인다 |
| 로그인한 채 글 화면(확인 문제에 답한 뒤)이나 배우기 목록을 열어 두고 다른 탭에 갔다 돌아옴 | 확인하는 동안 나의 학습·완료 카드·확인 문제가 보이지 않다가 같은 계정으로 확인되면 답한 결과·완료 카드·요약 패널이 그대로 다시 보인다. 나의 학습을 다시 요청하지 않고, 머문 시간을 처음부터 세지 않으며, 화면이 밀리지 않는다 |
| 배우기 목록의 '로그인' 연결로 로그인 | 로그인 뒤 그 배우기 화면으로 돌아온다 |

### 10-11. 비로그인은 아무것도 남지 않는다 (SC-009, SC-010)

로그아웃한 탭에서 글 세 편을 읽고 문제에 답한 뒤 계정 A로 로그인한다.

**기대**: DB의 나의 학습 테이블에 그 사이 행이 없다. 계정 A의 기록에 로그인 전 것이 더해지지 않는다. 비로그인 배우기 목록에 '로그인하면 학습 기록이 남습니다' 한 줄이 있다.

## 11. 목록과 나의 학습 화면 (B11·B13)

### 11-1. 보기 전환 (FR-023)

**기대**: 기본은 커리큘럼 보기(여정 지도). 목록 보기로 바꾸면 새로 고침·같은 탭 이동·로그인 왕복 뒤에도 목록 보기다. 새 탭은 커리큘럼 보기로 시작한다. 두 보기 모두 어느 글도 잠기지 않는다. 목록 보기는 1280px에서 표(단계마다 구분 줄), 720px 미만에서 목록이다.

### 11-2. 공개 안내 (FR-031)

**기대**:
- 2단계 공개일부터 7일 동안 목록 위에 한 줄 안내와 '2단계 보기'·'변경 기록'·[닫기]가 있다
- 로그인 사용자에게만 '지금까지의 읽은 기록, 경험치, 배지는 그대로입니다.'가 붙는다. 1단계만 공개된 때의 안내에는 붙지 않는다
- [닫기] 뒤 그 탭에서는 새로 고쳐도 다시 보이지 않고 새 탭에서는 보인다. 서버 요청이 없다
- 7일이 지나면(시험 DB에서 `occurred_at`을 8일 전으로 둔다) 안내가 없고 변경 기록에만 있다
- 배우기 밖 화면과 상단 메뉴에는 공개 알림이 없다

### 11-3. 요약 패널과 떠 있는 단추 (FR-020)

**기대**: 로그인 사용자의 목록 위에 레벨 표장·다음 레벨까지 남은 경험치·'읽은 글 3편'·'익힌 용어 4개'(분모 없음)·'이어서 읽기'·'모두 보기'. 커리큘럼 보기에서 패널의 '이어서 읽기'가 화면 밖으로 나가면 오른쪽 아래에 떠 있는 '이어서 읽기'가 나타나고, 깜빡이지 않는다. 목록 보기에는 떠 있는 단추가 없다. 기록을 불러오지 못했거나 공개된 글을 모두 읽었으면 단추가 없다. 레벨에 닿은 지 7일 안이면 패널의 레벨 옆에 '새'가 있고, 받은 지 7일 안의 배지(레벨 갈래 제외)가 있으면 '새 배지: 1단계 완주'처럼 한 줄과 '새'가 있으며, 없으면 그 줄이 없다.

### 11-4. 기록을 불러오지 못함 (FR-020, SC-007)

`/api/learning/me`만 막고 목록을 연다.

**기대**: 글 목록은 보이고, 요약 패널 자리에 '학습 기록을 불러오지 못했습니다'와 '다시 시도' 한 번. 글별 상태·익힌 용어 수·단계별 완료 수 자리는 비어 있고 '안 읽음'·0편·레벨 1로 채워지지 않는다. 다시 시도로 받으면 함께 채워진다.

### 11-5. '나의 학습' 화면 (FR-020, FR-024, US6 시나리오 4)

`/learn/me`를 연다.

**기대**:
- 순서: 레벨 카드 → 숫자 줄('받은 배지 5개' 포함, 아래에 '지금 공개된 글은 8편입니다') → 단계별 진행(다 읽은 단계는 '완주 · 4편') → 이어서 읽기 → 익힌 용어(누르면 그 글로) → 배지 → 변경 기록
- 배지 상태: 받음(색·획득 날짜), 아직(회색 실선·n/m), 준비 중(점선·사유 문구). 같은 갈래의 준비 중은 사유가 같은 것끼리 한 줄로 묶인다. 단계 완주 여섯은 낱장이다
- 7일 안에 받은 배지·레벨에 '새' 표시. 닫기 단추가 없다
- 경험치 내역이 없다

### 11-6. 비로그인 (FR-020, US4 시나리오 3)

로그아웃하고 `/learn`과 `/learn/me`를 연다.

**기대**: 요약 패널 자리에 견본 그림과 '로그인하면 학습 기록이 남습니다'·로그인 연결. `/learn/me`에는 같은 한 줄과 '나의 학습에 쌓이는 것' 세 칸(숫자·상태 없음). 글 노드는 상태 모양이 아니라 중립 모양이다. 진단 화면 어디에도 학습을 권하는 문구가 없다.

### 11-7. 쓰지 않는 말과 색 (FR-031 표시 규칙, SC-017)

```bash
grep -rnE "잠김|해금|열립니다|공개 예정|Coming soon|NEW" frontend/src/components/learning frontend/src/pages/Learning*.tsx
```

**기대**: 화면 문구에 걸리는 것이 없다(주석·테스트의 금지 확인 문장 제외). 화면 검토로 자물쇠 아이콘이 없고, 배우기 화면의 상태 표시에 값의 오르내림을 뜻하는 빨강·파랑(`--thorp-up`·`--thorp-down`)을 쓰지 않는 것을 확인한다. '곧'은 일반 낱말과 섞이므로 화면 검토로 본다.

## 13. 접근성·움직임·좁은 화면 (B10~B13)

**기대**:
- Tab만으로 보기 전환, 글 이동, '이 예시로 전략 진단하기', 확인 문제 답하기·다시 풀기, 다시 시도, 공개 안내 [닫기], '이어서 읽기'에 모두 닿는다(SC-008)
- 스크린 리더가 글 상태('완료'·'62% 읽는 중'·'안 읽음'), 배지 이름·기준·상태, '준비 중' 사유, 도식 설명 문장, 표 머리 칸, '(*출처)'의 출처 이름과 외부 링크임, ⚠️를 '주의'로 읽는다. 그림·진행 링·메달은 읽지 않는다(`aria-hidden`)
- 새 배지·레벨 알림은 초점을 옮기지 않는 상태 알림으로 한 번 읽힌다. 공개 안내는 상태 알림으로 읽히지 않는다
- 운영체제의 움직임 줄이기를 켜면 길 그리기·도장 찍기·메달 채우기·숫자 넘어가기가 모두 없고 최종 모습이 바로 보인다. 끄면 화면을 열 때의 움직임이 1초 안에 끝나고 반복하지 않는다
- 375px 폭에서 가로 스크롤이 없고, 누르는 곳은 44×44px 이상이다. Windows 헤드리스 Chrome은 창 폭이 약 500px 아래로 줄지 않으므로 375px 캡처는 iframe 하네스로 잰다
- 강제 색 모드에서 '준비 중'(점선)과 '아직 하지 않음'(실선)이 선 모양으로 구분된다

## 14. 이 문서로 확인하지 않는 것

- **SC-002의 충분성.** 금지 표현·결과성 숫자 검사는 패턴 검사다. 검사를 통과했다는 사실이 권고 표현 0건을 증명하지 않는다([research](research.md) R7·R19). 원고 MR 검토가 맡는다.
- **SC-012(FR-027) Thorp 동작 설명의 정확성.** 원고 MR 검토와 첫 단계 공개 점검표([plan](plan.md) "첫 단계 공개 조건")가 맡는다.
- **SC-013의 언급 표시 빠짐과 SC-014의 출처 빠짐.** 다른 글이 소유한 용어가 나오는 자리를 용어 언급 조각으로 표시했는지, 출처가 필요한 세 경우에 '(*출처)'를 달았는지는 원고 MR 검토가 본다. 이 문서는 표시된 언급이 처음 나오는 자리 규칙대로 그려지는지만 확인한다(§9-2·§9-3).
- **SC-005 사용성 관찰.** PD-14가 정하는 관찰 일정에서 기록한다. 2판은 '준비 중'·'이전 판'·레벨·배지를 뜻대로 읽는지 확인 질문 둘을 더한다. 구현 완료와 구분해 보고한다(constitution "완료의 정의").
- **화려함 상한(design-notes §2).** 화면 검토로 본다. 자동 검사가 없다.
- **002·005·007·009·010·011 화면의 도움말 자리.** 각 spec이 정한 뒤 그쪽 검증에서 확인한다([term-help-ui](contracts/term-help-ui.md) §6).
