# Phase 0 Research: 시장 흐름 개요

**Spec**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Date**: 2026-09-16

2026-09-16 clarify로 확정된 FR-004·FR-008·FR-011·FR-016·SC-007을 전제로 남은 설계 미결을 정리한다.
008 PD-11(등록표 실제 값)과 010 PD-08(모델 v1)은 이 문서에서 정하지 않는다.

## 현재 코드 상태 조사

plan을 쓰기 전에 실제 코드를 확인했다. 아래 세 가지가 설계를 바꿨다.

1. **시장 흐름 메뉴는 이미 화면을 갖고 있고, 그 화면은 spec을 따르지 않는다.**
   이 화면은 spec 작업을 시작하기 전에 만든 것이라 spec과 어긋나 있는 것이 정상이다. 회귀가 아니라
   교체 대상이다. 아래는 무엇을 걷어내야 하는지 알기 위한 목록이다.
   `frontend/src/components/landing/LandingHeader.tsx:13`과 `AppHeader.tsx:28`이 '시장 흐름'을 `/home`으로
   보내고, `frontend/src/pages/HomePage.tsx`가 `frontend/src/data/marketMock.ts`의 목업으로 화면을 그린다.
   - `MarketRegimeHero`는 `regime.headline`으로 "지금은 조심하되, 완전히 나쁜 시장은 아닙니다."를 띄우고
     경기·물가·시장 위험을 등급으로 보인다. 경제 전체를 하나의 좋고 나쁜 판정으로 요약하는 표시다.
     **FR-003·SC-002와 정면으로 충돌하고 D08·원칙 II를 어긴다.**
   - `StrategyRecommendationSection`은 "이 시장에 맞는 전략"·"추천 퀀트 전략"·"적합도"를 보인다.
     **원칙 III(진단이지 추천이 아니다)를 어기고 009 범위 밖이다.**
   - `SimilarMarketPanel`은 목업 유사 구간을 보인다. 010이 정할 검색 결과를 목업으로 선점한 상태다.
   - 결론: 009는 새 화면을 더하는 일이 아니라 **이 화면을 spec에 맞는 화면으로 교체하는 일**이다.

2. **008은 다른 팀원이 병렬로 진행 중이며 아직 코드에 반영되지 않았다.**
   `specs/008-macro-indicator-registry/`에 plan·tasks가 없고 `backend/src/main/java/com/ssafy/thorp/`에
   거시지표 도메인도 없다. 009가 표시할 17개 지표·분야·기준월을 읽을 저장소가 **지금은** 없다는 뜻이며,
   나중에 합쳐진다. 009는 그 시점에 맞춰 멈추지 않고, 합쳐질 때 갈아 끼울 경계를 만들어 둔다.

3. **기존 `market` 도메인은 009가 쓸 자료가 아니다.** `MarketController`는 `/markets/{slug}`로 KOSPI·
   KOSDAQ·USD_KRW 등 11개 지표의 최신값을 개별 반환한다(docs/specs/market-api.md). 이는 001이 확보한
   시장 자료이고, 009의 7개 분야 17개 지표(008 FR-001)와 집합이 다르다. FR-017의 국내 시장 참고 정보
   (KOSPI)만 이 API를 쓴다.

## 결정

### R1. 서술 대상 지표를 고르는 규칙 (FR-004)

- **Decision**: 분야 안에서 아래 순서로 가른다. 단위가 다른 지표의 변화 폭을 직접 비교하지 않는다.
  1. **방향 지속 길이**: 최근 3개월 경로에서 같은 방향으로 이어진 개월 수. `t-2→t-1`과 `t-1→t`의
     부호가 같으면 2, 하나만 움직였으면 1, 방향이 꺾였거나 보합이면 0.
  2. **같은 단위끼리의 변화 폭**: 1이 동률이면, 등록표의 단위가 같은 지표끼리만 `|t - t-2|`를 비교한다.
     단위가 다르면 이 단계로 가르지 않는다.
  3. **등록표의 분야 내 고정 순서**: 그래도 남으면 008 FR-001 표의 지표 나열 순서로 가른다.
  - 최대 2개까지 고르고, 1단계 값이 0인 지표만 남으면 "최근 3개월 동안 뚜렷한 방향 변화가 없었습니다"
    형태의 문장을 쓴다. 지어내지 않는다(FR-004, 원칙 VI).
- **Rationale**: 표준화 점수·거리는 FR-007과 SC-003이 막는다. 008 FR-014는 공통 척도 산출용 과거 구간을
  제공하되 **척도 계산 자체는 010이 정한다**고 못 박았으므로, 009가 MAD·IQR 같은 척도를 먼저 정하면
  010 PD-08을 앞당겨 결정하는 것이 된다. 방향 지속 길이는 값의 부호만 쓰므로 척도가 필요 없고 단위에
  영향받지 않는다. 기획서가 제시한 예시 문장 "취업자 수 증가율이 **3개월 연속** 낮아졌습니다"가 이미
  지속 길이를 앞세운 형태라는 점도 근거다.
- **Alternatives considered**:
  - *분야 안에서 변화 폭 절댓값을 그대로 비교*: 대외거래(수출 증가율 %, 무역수지 억달러)나 금융·주택
    (국고채 %, 환율 원, 주택가격 %)처럼 한 분야 안에 단위가 섞여 있어 비교가 성립하지 않는다.
  - *지표별 과거 분포로 표준화한 뒤 비교*: FR-007·SC-003 위반은 아니지만(내부 계산이므로) 010 PD-08의
    척도 선택을 009가 먼저 고정하게 된다. 010이 다른 척도를 고르면 두 화면의 설명이 어긋난다.
  - *분야마다 대표 지표 하나를 고정*: clarify에서 버린 선택지(B)다. 실제로 움직인 지표를 놓친다.
- **후속**: 1단계가 clarify 답의 "변화가 가장 큰"을 **방향이 가장 오래 이어진**으로 읽은 것이다. 팀이
  변화 폭을 앞세우길 원하면 010 PD-08 확정 뒤 clarify를 다시 열어야 한다. 이 해석은 spec을 고치지 않고
  plan의 결정으로만 둔다.

### R2. 008이 병렬로 진행되는 동안 009를 진행하는 방식

- **Decision**: 009는 지표 저장소를 만들지 않는다. `MacroIndicatorSnapshotPort`(009 소유 인터페이스)를
  두고, 008이 저장소를 만들 때까지는 **버전이 붙은 예시 자료 fixture**를 읽는 어댑터를 쓴다. 예시 자료로
  동작하는 분야는 응답과 화면에 예시임을 표시한다.
- **Rationale**: 008 FR-022가 "인증키 발급 전이거나 자료를 이용할 수 없으면 명시된 예시 자료로 개발하고
  예시 자료임을 화면에 표시한다"를 이미 허용한다. 009 FR-014와 Edge Case도 예시 자료 상태를 요구한다.
  012가 PD-15 회신을 기다리는 동안 fixture와 `PREPARING` 상태로 구현을 끝낸 것과 같은 방식이다
  (012 plan "PD-15 회신은 공개 게이트이지 구현 차단 조건이 아니다").
- **Alternatives considered**:
  - *008 완료를 기다렸다가 009를 시작*: 008은 다른 팀원이 병렬로 진행 중이라 완료 시점이 009의 일정과
    맞지 않을 수 있다. 포트를 두면 두 작업이 서로를 기다리지 않는다.
  - *009가 지표 수집·저장을 겸함*: 008 FR-002~FR-014와 정면으로 겹치고, 등록표 버전·자료 버전 소유권이
    두 spec으로 쪼개진다.
- **교체 비용**: 008이 실제 저장소를 만들면 어댑터 구현체 하나만 바뀐다. 포트 시그니처와 읽기 모델,
  화면은 그대로 둔다.
- **합류 위험 — 이 결정에서 가장 주의할 점**: 포트의 조회 넷은 008 spec의 FR-013·FR-014·FR-002·FR-011을
  읽고 009가 **혼자 정한 모양**이다. 008을 맡은 사람이 다른 모양으로 만들면 두 작업이 만나는 날
  어댑터 교체가 아니라 포트 재설계가 된다. 포트 시그니처를 확정하기 전에 008 담당자와 맞춰야 하고,
  특히 아래 셋을 확인해야 한다.
  1. 분야별 T_g와 지표별 최신 확보월을 **009가 계산하지 않고 받는다**는 전제(008 FR-013)가 유지되는지
  2. 임의 기준월 t에 대한 3개월 경로 조회(008 FR-014)가 009가 부르는 단위로 제공되는지
  3. 수집 실패·예시 자료 여부를 **지표 단위로** 구분해 주는지. 원천 단위로만 주면 009가 분야 상태를
     판정할 수 없다(R6)

### R3. 백엔드 배치

- **Decision**: `backend/src/main/java/com/ssafy/thorp/marketflow/`에 새 bounded context를 만들고 외부 경로
  `/api/market-flow`(Spring 매핑 `/market-flow`)로 읽기 전용 API를 연다. 기존 `market` 도메인은 건드리지
  않고, FR-017의 참고 정보는 화면이 기존 `/api/markets/kospi`를 그대로 호출한다.
- **Rationale**: 012가 `news`를 별도 context로 두고 `/market-news`를 연 선례와 같다. `market` 도메인은
  001의 시장 자료 조회를 소유하고 있어 7개 분야 읽기 모델을 넣으면 두 spec의 책임이 섞인다. backend
  CLAUDE.md의 도메인별 4계층(presentation/application/domain/infrastructure)을 그대로 따른다.
- **Alternatives considered**:
  - *`market` 도메인 확장*: 001과 009의 변경이 같은 패키지에서 충돌하고 롤백 경계가 겹친다.
  - *Worker에 배치*: 읽기 조회이고 DB 접근이 필요하다. 루트 CLAUDE.md의 Worker 역할(백테스트 계산)과 다르다.

### R4. 화면 경로와 기존 `/home` 처리

- **Decision**: 시장 흐름은 `/market-flow` 라우트로 새로 만들고, `/home`은 `/market-flow`로 영구
  리다이렉트한다. 메뉴 링크(`LandingHeader`·`AppHeader`)를 `/market-flow`로 바꾼다.
  `MarketRegimeHero`·`StrategyRecommendationSection`·`SimilarMarketPanel`과 `marketMock`의 해당 항목은
  시장 흐름 화면에서 제거한다.
- **Rationale**: FR-003·SC-002가 "경제 전체를 하나의 점수·등급으로 요약한 요소가 0개"를 요구하므로
  `MarketRegimeHero`를 남긴 채로는 SC-002를 통과할 수 없다. 경로를 분리하면 교체 범위가 파일 단위로
  드러나고, 리다이렉트로 기존 링크(`MyRecordsEntryPage.tsx:29` 등)가 깨지지 않는다.
- **주의**: `HomePage`가 쓰는 `MacroIndicatorGrid`·`MarketSnapshot`·`MarketDataStatus`는 001 시장 자료를
  보이는 컴포넌트다. 시장 흐름에서는 FR-017의 참고 정보 영역으로만 남기고 분야 요약과 섞지 않는다.
  삭제 대상과 존치 대상을 tasks에서 파일 단위로 명시한다.

### R5. 섹터 선택의 세션 유지 (FR-016)

- **Decision**: 선택 섹터를 `sessionStorage`에 키 하나로 저장한다. 읽기·쓰기는 `try/catch`로 감싸고
  실패하면 화면 안 상태로만 동작한다. 계정·서버에 저장하지 않는다.
- **Rationale**: FR-016이 "새로고침·다른 메뉴 왕복에 남고 탭을 닫으면 풀린다"와 "로그인을 요구하지
  않는다"를 함께 요구한다. `sessionStorage`의 수명이 정확히 그 범위다. `frontend/src/auth/returnTarget.ts`가
  이미 같은 방식을 쓰고 있어 패턴이 저장소에 있다. 002 Edge Case가 저장소를 쓸 수 없는 환경에서 화면을
  막지 말라고 정해둔 것도 그대로 따른다.
- **Alternatives considered**: `localStorage`(탭을 닫아도 남아 FR-016 위반), URL 쿼리(공유 링크가 남의
  섹터 선택을 강제), 서버 세션(로그인 의존이 생겨 D02 위반).

### R6. 응답 상태 모델 (FR-011, FR-014, SC-005)

- **Decision**: 분야마다 `READY` / `EXAMPLE` / `EMPTY` / `COLLECTION_FAILED` 넷 중 하나를 준다. 전부
  HTTP 200이다. `STALE`이나 `DELAYED` 같은 지연 판정 상태는 **두지 않는다**.
- **Rationale**: 2026-09-16 clarify가 지연 판정을 폐기했다. 대신 모든 지표 항목이 `referenceMonth`(대상월)와
  분야가 `lastUpdatedAt`(마지막 갱신 시각)을 항상 실어 사용자가 직접 판단한다(FR-011). 외부 자료 상태가
  화면 장애로 번지지 않게 하는 건 012가 쓴 방식과 같다.
- **주의**: 012는 `STALE`을 쓴다. 뉴스는 30분 단위로 바뀌고 거시지표는 월 단위로 바뀌므로 같은 기준을
  쓰지 않는다. 두 API의 상태 집합이 다른 이유를 contracts에 적어 둔다.

### R7. SC-007(2초) 달성 방법

- **Decision**: 분야 요약은 요청 시점에 계산하지 않고, 등록표 버전·자료 버전이 바뀔 때 만들어 둔 읽기
  모델(`market_flow_field_summary`)에서 읽는다. 화면은 분야 요약을 먼저 그리고, 뉴스 묶음(012)과 국내
  시장 참고 정보(001)는 각자 늦게 채운다.
- **Rationale**: SC-007이 "2초 이내에 7개 분야 요약"만 요구하고 뉴스·참고 정보는 늦어도 된다고 명시한다
  (FR-017). 거시지표는 월 단위로 갱신되므로 요청마다 다시 계산할 이유가 없다. 원칙 IX에 따라 목표는
  측정으로 확인하고, 측정 전에 캐시 계층을 더 두지 않는다.
- **측정 방법**: Testcontainers PostgreSQL 16에 17개 지표 × 120개월 fixture를 넣고 30회 warm-up 후 100회
  측정한 분야 요약 조회 p95를 남긴다. 화면 쪽 2초는 quickstart의 수동 확인 절차로 검증한다.

### R8. 변화 요약 문장 만들기 (FR-004)

- **Decision**: 등록된 문장 틀에 값을 끼워 넣는 결정론적 formatter로만 만든다. 틀은 방향(상승/하락/보합)
  × 지속 길이(연속/이번 달) 조합으로 고정하고, 지표 이름·값·단위·기간만 채운다. 규칙 묶음에
  `market-flow-narrative-v1` 버전을 붙여 저장한다. 자유 생성 문장과 LLM 호출은 쓰지 않는다.
- **Rationale**: spec Assumptions가 "자유 생성 문장은 쓰지 않는다"를 이미 정했고, 원칙 VI가 확인할 수 없는
  내용을 만들지 못하게 한다. 버전을 붙이는 것은 원칙 VIII(재현할 수 있게 기록한다)과 008 FR-003의
  화면 분류 버전 분리 규칙에 맞춘다.
- **금지 어휘 검사**: formatter 출력에 판정·전망·투자 시사점 어휘가 섞이지 않는지 단위 테스트로 막는다.
  SC-002가 "0건"을 요구하므로 검사 자체를 코드로 둔다.
