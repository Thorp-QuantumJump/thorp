## 범위 요약

전략 진단의 두 번째 단계다. 사용자는 다섯 전략 카드에서 하나를 고르고 기본 설정으로 바로 분석하거나, 그 전략에 해당하는 상세 설정만 허용 범위 안에서 조정한다. 분석 기간·금액·비용은 '기간·금액·조건'에서 확인한다. 화면의 행동 버튼은 '분석하기'와 '설정 조합 자동 비교' 두 개다. 파라미터의 후보 값·범위·기본값은 실행 전에 등록표로 관리한다. (§4.2.2)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 전략 카드를 고르고 기본 설정으로 분석한다 (Priority: P1)

[전략을 검증하려는 개인]은 복잡한 설정을 읽지 않고 첫 분석을 시작하기 위하여 쉬운 이름과 한 줄 설명만 있는 전략 카드에서 하나를 고르고 '기본 설정 사용'으로 바로 '분석하기'를 누를 수 있다. (§4.2.2, D04)

**Why this priority**: 기획서가 첫 화면 단순함을 가장 중요한 설계 원칙으로 못 박았다(§2). 설명 없이 첫 분석을 마치는지가 사용성 확인의 첫 질문이다(§7.2).

**Independent Test**: 섹터·비중이 정해진 상태에서 전략 카드 하나를 선택하고 상세 설정을 열지 않은 채 '분석하기'가 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 섹터·비중을 정한 상태에서, **When** 전략 선택 화면이 열리면, **Then** 다섯 전략 카드가 쉬운 이름과 한 줄 설명만으로 보이고 세부 설정은 보이지 않는다.
2. **Given** 카드 하나를 선택하면, **Then** 기본 화면에는 선택한 전략과 '기본 설정 사용' 표시, 분석 기간·금액·비용 적용 여부 한 줄, '분석하기'와 '설정 조합 자동 비교' 두 버튼만 보인다.
3. **Given** '기본 설정 사용'으로 표시된 상태에서, **When** '분석하기'를 누르면, **Then** 등록된 기본값으로 분석 요청이 만들어지고 사용자는 다른 값을 입력하지 않는다.
4. **Given** 선택 섹터의 자료가 어느 전략의 워밍업을 채우고도 평가할 구간이 남으면, **Then** 그 전략 카드에 한 문장 안내가 붙고 선택은 막지 않되 분석 기간이 그만큼 줄어든다는 사실을 알린다.
5. **Given** 선택 섹터의 자료가 어느 전략의 워밍업조차 채우지 못하면, **Then** 그 전략 카드를 고를 수 없는 상태로 두고 왜 분석할 수 없는지 한 문장으로 보인다.

### User Story 2 - 상세 설정을 허용 범위 안에서 조정한다 (Priority: P2)

[전략을 검증하려는 개인]은 관측 기간이나 비중 상한 같은 조건의 영향을 보기 위하여 선택한 전략에 해당하는 상세 설정만 열어 의미와 허용 범위를 확인하며 값을 바꾸고, 필요하면 기본값으로 되돌릴 수 있다. (§4.2.2, §6.4.2, D04)

**Why this priority**: 사용자의 질문(§3.1)은 관측 기간·선정 기준·리밸런싱 주기·비중 제한에 따라 답이 달라진다. 기본 설정 다음으로 필요한 자유도다.

**Independent Test**: '변동성에 따라 나누기'를 선택해 상세 설정을 열고 목록형 항목인 변동성 관측 기간과 리밸런싱 주기에 등록된 후보만 보이는지 확인한 뒤, 입력형 항목인 비중 상한을 허용 범위 안 값과 밖 값으로 바꿔 동작을 확인하고 기본값 복원을 누른다.

**Acceptance Scenarios**:

1. **Given** 전략을 선택한 상태에서, **When** '상세 설정'을 열면, **Then** 그 전략에 해당하는 항목만 열리고 각 항목의 의미·허용 범위·기본값 복원이 보인다.
2. **Given** 상세 설정에서, **When** 허용 범위 안의 값을 입력하면, **Then** 값이 반영되고 기본값이 편의용 출발점이며 최적값이 아니라는 표시가 유지된다.
3. **Given** 상세 설정의 입력형 항목에서, **When** 허용 범위 밖의 값을 입력하면, **Then** 허용 범위를 안내하고 값을 저장하지 않으며 몰래 잘라 넣지 않는다.
4. **Given** 상세 설정의 목록형 항목에서, **Then** 등록된 후보만 보이고 등록되지 않은 값을 고를 방법이 없다.
5. **Given** 값을 바꾼 상태에서, **When** '기본값 복원'을 누르면, **Then** 그 항목이 등록된 기본값으로 돌아간다.
6. **Given** '흐름을 따라 배분하기'에서 선정 수를 선택 섹터 수보다 크게 두면, **Then** 실행 전에 유효하지 않은 조합임을 안내한다.

### User Story 3 - 기간·금액·조건을 확인하고 바꾼다 (Priority: P2)

[전략을 검증하려는 개인]은 비교 조건을 이해하고 필요할 때 바꾸기 위하여 '기간·금액·조건'에서 자동 제시된 분석 기간과 시작 금액을 허용 범위 안에서 변경하고, 004가 등록한 비용 가정은 수치·버전·임시 여부를 읽기 전용으로 확인한다. (§4.2.2, §6.4.1, D10)

**Why this priority**: 분석 기간·비교 대상·비용 적용 여부는 요약 한 줄에 항상 보여야 한다(§4.1). 조건을 모르면 결과를 오해한다.

**Independent Test**: 상장일이 다른 섹터를 섞어 선택한 뒤 자동 제시된 분석 기간이 공통 평가 가능 범위와 같은지, 시작 금액을 허용 범위 안에서 바꿀 수 있는지, 비용 가정이 읽기 전용으로만 보이고 이 화면에서 고칠 수단이 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 섹터와 전략을 정한 상태에서, **When** '기간·금액·조건'을 열면, **Then** 비교 후보가 공통으로 평가 가능한 범위에서 자동 제시된 분석 기간과 시작 금액이 보이고, 비용 가정(수수료·세금 등)은 004가 등록한 수치·버전·임시 여부가 읽기 전용으로 보인다.
2. **Given** 후보 중 긴 관측 기간 때문에 공통 평가 구간이 줄어들면, **When** 분석을 시작하려 하면, **Then** 실행 전에 줄어든 구간과 원인을 알린다.
3. **Given** '기간·금액·조건'에서, **When** 분석 기간을 공통 평가 가능 범위 안에서 바꾸면, **Then** 반영되고 범위 밖 기간은 선택할 수 없다.
4. **Given** 어느 화면에서도, **Then** 수수료·세금·평가 기간을 수익이 높아지는 방향으로 자동 최적화하는 선택지는 없다.
5. **Given** '기간·금액·조건'에서, **When** 최소 평가 기간을 완화·기본·엄격 중 다른 값으로 바꾸면, **Then** 그 값과 워밍업을 함께 반영해 카드의 선택 가능 여부와 실행 전 안내가 다시 판정된다(FR-011a).

### User Story 4 - 설정 조합 자동 비교로 넘어간다 (Priority: P3)

[전략을 검증하려는 개인]은 설정을 하나씩 바꾸는 대신 여러 조합을 한 번에 비교하기 위하여 전략 선택 화면에서 '설정 조합 자동 비교'를 선택해 자동 탐색 확인 화면으로 넘어갈 수 있다. (§4.2.2, D04)

**Why this priority**: 진입점만 이 spec의 범위다. 자동 탐색 자체는 [007](../007-auto-parameter-search/spec.md)이 정한다.

**Independent Test**: 전략 하나를 선택한 뒤 '설정 조합 자동 비교'를 눌러 그 전략과 섹터 후보 집합이 유지된 채 007의 실행 전 확인 화면이 열리는지, 다른 전략이 함께 넘어가지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 전략 하나와 섹터 후보 집합을 정한 상태에서, **When** '설정 조합 자동 비교'를 선택하면, **Then** 그 전략 하나와 섹터 후보 집합이 고정된 채 자동 탐색의 실행 전 확인 화면이 열린다.
2. **Given** 자동 비교 진입 시, **Then** 사용자는 후보 숫자를 직접 입력하지 않으며 상세 변경은 선택 사항으로만 보인다.

---

### Edge Cases

- 선택 섹터가 두 개일 때 '흐름을 따라 배분하기'의 선정 수 후보는 두 개 이하로만 보인다. 그보다 큰 등록값은 유효성 제약으로 걸러진다.
- 공통 비중 상한에 섹터 수를 곱한 값이 투자 비중에 못 미치는 조합(예: 섹터 3개, 상한 30%)은 실행 전에 안내하고 분석을 시작하지 않는다.
- 리밸런싱 주기에 등록되지 않은 값(예: 임의 일수)은 입력할 수 없다. 달력 기준과 거래일 수 기준을 한 설정에 섞어 넣을 수 없으며 둘 중 하나를 고른다.
- 상세 설정에서 값을 바꿨다가 '기본값 복원'으로 모든 항목을 되돌리면 표시가 '설정을 바꿈'에서 '기본 설정'으로 돌아온다.
- 상세 설정을 바꿨다가 다른 전략 카드로 옮기면, 이전 전략의 변경값은 그 전략으로 돌아왔을 때 유지되며 다른 전략에 적용되지 않는다. 이 유지는 탭이 열려 있는 동안 계속되므로 화면을 새로 고친 뒤에도 같게 동작한다.
- 파라미터 등록표 버전이 바뀌어 저장된 설정값이 허용 범위 밖이 되면, 내 기록에서 '설정 바꿔 비교'로 열 때 그 사실을 알리고 기본값 복원을 제안한다.
- 공통 평가 가능 범위가 어느 전략에 필요한 워밍업조차 채우지 못하면 그 전략 카드를 고를 수 없게 막고 이유를 한 문장으로 표시한다. 워밍업은 채우되 남는 평가 구간이 짧아지기만 하면 막지 않고 줄어든 기간을 알린다. 기본 설정으로는 분석할 수 있던 전략이라도 상세 설정에서 관측 기간을 늘려 워밍업이 길어지면 그 자리에서 다시 판정해 알린다.
- 섹터·비중 단계로 돌아가 비중을 고치고 다시 오면 '내가 정한 비중' 전략의 목표 비중도 바뀐 값으로 보인다. 003에 남아 있던 다른 설정값은 그대로 유지된다.
- 역변동성·섹터 모멘텀에서 모든 섹터가 상한에 닿아 더 나눠 줄 곳이 없으면 남은 몫을 투자하지 않은 상태로 두고, 그 사실을 결과와 함께 알린다. 최소분산은 상한이 계산의 제약이라 이 상황이 생기지 않는다.
- 시작 금액에 등록된 최소보다 작거나 최대보다 큰 값을 넣으면 허용 범위를 안내하고 저장하지 않는다.
- 파라미터 등록표 조회가 실패하거나 아직 끝나지 않았으면 전략 카드는 선택할 수 없는 상태로 보이며, 실패 상황에서는 다시 시도할 방법을 함께 보인다.
- 002에서 선택한 정보가 없거나 손상됐거나 선택 섹터가 두 개 미만이면 003은 기본값을 만들지 않고 이전 단계를 다시 완료하도록 안내한다.
- 입력형 값이 비었거나 숫자가 아니거나 등록한 간격에 맞지 않으면 상태에 반영하지 않는다. 최솟값·최댓값과 정확히 같은 값은 허용하고, 숫자 정밀도는 등록표의 `step`을 소수 문자열로 판정해 부동소수점 반올림으로 다른 결과를 만들지 않는다.
- 등록표 버전이나 섹터 수가 바뀌면 탭에 남은 전략별 값을 새 등록표·규칙으로 다시 판정한다. 유효한 값은 유지하고, 유효하지 않으면 자동으로 고치지 않고 이유와 기본값 복원 선택을 보인다.
- 주 분석은 `FULL_PERIOD` 시나리오로 고정하므로 목표 변동성 값을 화면 상태에 만들거나 보관하지 않는다. `TARGET_RISK`를 여는 별도 시나리오 화면이 값 생성·보관·제거 규칙을 소유한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 선택한 섹터 후보 집합에 대해 아래 다섯 전략을 카드로 제공한다. 기능 완료 시점의 등록표에는 다섯 전략이 모두 활성이어야 하며, 후속 버전이 전략을 비활성화하면 해당 카드는 보이지 않는다. 카드에는 화면 이름과 한 줄 설명만 두고, 다섯 방식이 퀀트 알고리즘 전체이거나 우열 순위라는 문구·배지를 두지 않는다. (§4.2.2, D04)

  | 화면 이름 | 전략 | 한 줄 설명 |
  |---|---|---|
  | 내가 정한 비중 | 고정 목표 비중 | 지정한 비중으로 주기적으로 맞춘다. |
  | 똑같이 나누기 | 동일 비중 | 선택 섹터에 같은 목표 비중을 둔다. |
  | 변동성에 따라 나누기 | 역변동성 | 최근 변동성이 낮은 섹터에 더 큰 비중을 둔다. |
  | 흐름을 따라 배분하기 | 섹터 모멘텀 | 과거 성과의 방향 또는 상대 강도를 규칙으로 삼아 섹터를 선택·배분한다. |
  | 전체 변동성을 줄이도록 배분하기 | 최소분산 | 섹터들이 함께 움직이는 정도를 반영해 추정 포트폴리오 분산이 작아지는 비중을 계산한다. |

- **FR-002**: 기본 화면에는 선택 전략과 '기본 설정 사용' 표시, 분석 시작·종료일·비교 대상 섹터 수·시작 금액·적용할 비용 조건의 버전과 임시 여부를 한 줄로 보인다. 시작 금액은 분석 요청에 실리는 값과 같은 값을 보여, 사용자가 보지 못한 금액으로 분석이 접수되지 않게 한다. '분석하기'와 '설정 조합 자동 비교' 두 버튼은 같은 크기로 나란히 두고, 그 밖의 행동은 이 화면에 두지 않는다. constitution 원칙 II의 예외 조항(3.4.0, [S15P21E205-253](https://ssafy.atlassian.net/browse/S15P21E205-253) 2026-09-15 승인)이 이 구성을 허용한다. '기본 설정 사용'은 사용자가 켜고 끄는 항목이 아니라 지금 설정이 등록표의 기본값 그대로인지를 알리는 표시다. 값을 하나라도 바꾸면 '설정을 바꿈'으로 바뀌고, 바꾼 값을 모두 기본값으로 되돌리면 다시 '기본 설정'으로 돌아온다. (§4.1, §4.2.2)
- **FR-003**: '상세 설정'은 선택한 전략에 해당하는 항목만 열고, 각 항목의 의미·허용 범위·기본값 복원을 제공한다. '고정 목표 비중'의 목표 비중은 [002](../002-sector-weight-selection/spec.md)에서 확정한 섹터별 비중을 그대로 보여 주기만 하며 이 화면에서 고칠 수 없고, 고치려면 섹터·비중 단계로 돌아가야 한다는 안내를 함께 둔다. 전략별 항목은 다음과 같다. (§4.2.2)

  | 전략 | 상세 설정 항목 |
  |---|---|
  | 고정 목표 비중 | 목표 비중(읽기 전용)·리밸런싱 주기·비중 상한 |
  | 동일 비중 | 리밸런싱 주기 |
  | 역변동성 | 변동성 관측 기간·리밸런싱 주기·비중 상한 |
  | 섹터 모멘텀 | 관측 기간·최근 구간 제외 기간·선정 방식(선정 수·임계값·상위 비율·전부 편입 중 하나)·배분 방식·비중 상한·리밸런싱 주기 |
  | 최소분산 | 공분산 관측 기간·추정 방법(현재는 표본공분산 하나)·비중 상한·리밸런싱 주기 |

  섹터 모멘텀의 선정 방식은 사용자가 네 가지 중 하나를 고른다. (PD-02, 2026-09-15 확정)

  | 선정 방식 | 뜻 | 사용자가 넣는 값 |
  |---|---|---|
  | 선정 수 | 점수 순으로 상위 N개만 편입 | 개수(예: 3) |
  | 임계값 | 점수가 기준을 넘는 섹터만 편입 | 수익률 기준(%) |
  | 상위 비율 | 후보 섹터 중 상위 몇 %만 편입 | 비율(%) |
  | 전부 편입 | 아무도 빼지 않고 순위대로 비중만 차등 | 없음 |

  선택한 방식에 해당하는 값 하나만 상세 설정에 열리고, 나머지 세 방식의 값은 보이지도 저장되지도 않는다. 어떤 값을 계산에 어떻게 쓰는지(모멘텀 점수 산식 자체)는 [004](../004-backtest-execution/spec.md) PD-03이 정한다 — 003은 사용자가 고른 편입 조건을 그대로 전달할 뿐 점수를 계산하지 않는다.

- **FR-004**: 기본값과 초깃값은 편의용 출발점으로 표기하고 최적값이나 투자 권고로 표기하지 않는다. (§4.2.2, 원칙 III)
- **FR-005**: 전략별로 의미가 있는 설정만 허용하고, 후보 값·범위·간격·유효성 제약·기본값을 실행 전에 파라미터 등록표로 등록한다. 등록표는 전략 카드의 이름·설명·순서·활성 여부, 축 도움말, 목표 비중 출처, 상한 처리 안내까지 소유하는 서버의 단일 원본이며 버전으로 관리한다. 화면은 조회한 현재 버전만으로 카드와 입력 항목을 구성하고, 전략 이름이나 축별 안내를 화면 코드에 따로 적어 두지 않는다. 값 자체는 PD-02(2026-09-15 확정, [data-model](data-model.md) §4)다. (§6.4.2)
- **FR-006**: 설정 항목은 등록표가 정한 방식에 따라 후보 목록에서 고르거나(목록형) 값을 직접 입력한다(입력형). 목록형 항목에는 등록된 후보만 보이므로 등록되지 않은 값을 고를 경로가 없다. 입력형 항목에서 허용 범위 밖이거나 등록된 간격에 맞지 않는 값을 입력하면 허용 범위를 안내하고 저장하지 않으며 몰래 잘라 넣지 않는다. 화면의 안내는 사용자를 돕기 위한 것이고, 분석 요청을 받는 서버는 화면 경유 여부와 무관하게 실행 직전에 등록표로 같은 검증을 다시 수행해 위반한 요청을 거절한다. 기존 요청 호환을 위해 검증을 우회하는 과도기 경로는 이 요구사항을 충족한 것으로 보지 않는다. (원칙 VI)
- **FR-007**: 공통 출발 설정은 월말 리밸런싱과 역변동성 63거래일 관측이다. 이 값은 출발안이며 승인된 후보 범위 안에서 변경·탐색할 수 있다. 리밸런싱 주기의 후보 값은 달력 기준(월말·분기말 등)과 거래일 수 기준(21거래일·63거래일 등)을 함께 담으며, 사용자는 두 방식 가운데 하나를 골라 그 후보 값 중에서 고른다. 003은 사용자가 고른 주기를 분석 요청에 담아 넘기기만 하고, 그 주기에 언제 판단하고 언제 체결하는지는 [004](../004-backtest-execution/spec.md) FR-011이 정한다(월말 정보 확인 후 다음 거래일 체결). (§4.2.2, §6.4.2)
- **FR-008**: 비중 상한은 선택한 모든 섹터에 똑같이 걸리는 값 하나이며 섹터마다 다른 상한을 두지 않는다. 유효성 제약(모멘텀 선정 수가 가용 섹터 수를 넘는 경우, 상한에 섹터 수를 곱한 값이 투자 비중에 못 미쳐 비중을 채울 수 없는 조합 등)을 위반하는 설정은 실행 전에 안내하고 분석을 시작하지 않는다. (§6.4.2, §6.4.3)
- **FR-009**: 분석 기간은 비교 후보가 공통으로 평가 가능한 범위([001](../001-etf-market-data/spec.md)의 산출값)에서 자동 제시한다. 단일 전략 분석의 비교 후보는 선택한 섹터들이고, 여러 전략을 같은 조건으로 비교할 때는 해당 전략과 섹터 조합 모두가 공통으로 평가되는 범위를 쓴다. 사용자는 그 범위 안에서만 기간을 바꿀 수 있다. (§4.2.2, §6.4.1)
- **FR-010**: '기간·금액·조건'에서 분석 기간과 시작 금액은 변경하고, 비용 가정은 004가 등록한 현재 버전의 수치·버전·임시 여부를 **읽기 전용**으로 확인한다. 사용자가 이 화면에서 수수료·세금 수치를 임의로 바꾸지 않으며, 비용 상승은 004의 별도 시나리오가 소유한다. 시작 금액의 최소·최대·간격·기본값은 등록표가 담고 다른 설정 항목과 같은 방식으로 검증하며, 100만 원~10억 원, 100만 원 간격, 기본 1,000만 원이다(PD-02, 2026-09-15 확정). 004의 PD-18(확정)이 목표 변동성(기본 연 10%, 5~20%, 1% 간격)을 003 등록표 항목으로 지정했으므로 등록표에 자리를 두되, 주 분석(`FULL_PERIOD`)에는 보이지 않는다. PD-07 확정 전에는 004가 명시한 임시 비용 프로필을 그대로 표시하고 확정값처럼 보이지 않게 한다. 수수료·세금·평가 기간을 수익을 높이는 방향으로 자동 최적화하는 선택지는 제공하지 않는다. (§4.2.2, §6.4.3, 원칙 IV)
- **FR-011**: 후보 중 긴 관측 기간 때문에 공통 평가 구간이 줄면 실행 전에 줄어든 구간과 원인을 알린다. 필요한 워밍업 기간은 등록표가 담은 전략별 산출 규칙에 현재 설정값을 넣어 계산하며, 설정값을 바꿀 때마다 다시 계산해 판정한다. 카드 목록에서는 각 전략의 기본 설정을 기준으로 판정한다. 공통 평가 가능 범위가 필요한 워밍업을 채우고도 FR-011a가 정한 최소 평가 기간만큼 남으면 그 전략을 고를 수 있고, 줄어든 기간을 카드와 실행 전 안내에 알린다. 워밍업조차 채우지 못하거나 남는 기간이 최소 평가 기간에 못 미치면 그 전략 카드를 고를 수 없는 상태로 두고 분석할 수 없는 이유를 한 문장으로 표시한다. (§6.4.1, 원칙 IV)
- **FR-011a**: '기간·금액·조건'에서 최소 평가 기간을 사용자가 고른다 — 완화(제한 없음)·기본(1년)·엄격(3년) 세 후보 중 하나이며 등록표 항목이다(analysisConditions.minEvaluationYears). 팀이 값 하나로 고정하지 않는 이유는, 짧은 평가 구간에서 나온 수익률이 통계적으로 무의미한데도 화면이 이를 막지 않으면 오해를 부르지만, 신생 섹터를 다루고 싶은 사용자에게는 그 판단을 맡기는 편이 낫기 때문이다. 기본값은 1년(리밸런싱이 월말이면 최소 12회 판단)이다. 이 값은 워밍업과 별개로 적용되며, FR-011의 "평가할 구간이 남으면"의 기준이 된다. (§6.4.1, 원칙 IV, PD-02 2026-09-15 확정)
- **FR-012**: 자동 배분 전략(역변동성·섹터 모멘텀·최소분산)을 선택하면 출력 비중이 선택한 규칙의 계산 결과이며 사용자 입력 비중과 구분된다는 설명을 보인다. (§4.2.1, D13)
- **FR-013**: '설정 조합 자동 비교'를 '분석하기'와 같은 크기의 행동 버튼으로 제공한다. 진입 시 사용자가 방금 고른 전략 하나와 섹터 후보 집합을 고정해 [007](../007-auto-parameter-search/spec.md)의 실행 전 확인 화면으로 넘기며, 003은 여러 전략을 한 번에 넘기지 않는다. 전략 선택 없이 자동 비교로 들어갈 수는 없다. (§4.2.2)
- **FR-014**: 선택 전략·설정값·분석 기간·금액·비용 가정·파라미터 등록표 버전은 분석 요청에 담겨 [004](../004-backtest-execution/spec.md)로 전달되고 [006 내 기록](../006-my-records/spec.md)에 보존된다. 여러 전략을 같은 조건으로 비교하는 요청(005 '다른 조건으로 비교', 006 '설정 바꿔 비교')은 비교 후보 전략 중 가장 긴 관측 기간을 공통 워밍업(`warmupTradingDays`)으로 함께 넘겨 모든 실행의 평가 시작일이 같게 한다(004 R-15). 사용자에게 버전이나 실험 식별자 입력을 요구하지 않는다. (§5, D14)
- **FR-015**: 계산식·자료 공급원·거리 함수·실험 식별자·서버 설정을 요구하거나 보이지 않는다. 내부 계산 항목이 많아도 화면에 동시에 나열하지 않는다. (§4.1)
- **FR-016**: 진단 화면의 용어 도움말은 [013 배우기](../013-learning-pages/spec.md) FR-008~FR-010의 단일 원본을 재사용하고 해당 주제 글 연결을 제공한다. 대응하는 설명이 없으면 즉석 문장을 만들지 않고 '설명 준비 중'으로 표시한다. 도움말을 열거나 배우기로 이동해도 탭 수명의 설정 상태는 유지한다. (§4.5)
- **FR-017**: 선택한 전략과 상세 설정값, 분석 조건은 브라우저 탭이 열려 있는 동안 유지한다. 화면을 새로 고치거나 섹터 선택 단계로 돌아갔다가 다시 와도 값이 남아 있고, 탭을 닫으면 사라져 다음 방문에는 등록표의 기본값에서 다시 시작한다. 로그인하지 않은 사용자에게도 같게 적용한다. 등록표 버전이나 섹터 수가 바뀌면 보관값을 새 범위·규칙으로 다시 검증해 유효한 값만 유지하고, 유효하지 않은 값은 자동 보정하지 않고 이유와 기본값 복원 선택을 보인다. (§4.2.2)
- **FR-018**: 파라미터 등록표를 받아오지 못하면 전략 카드를 선택할 수 없는 상태로 두고, 설정을 불러오지 못했다는 안내와 다시 시도할 방법을 보인다. 이 상태에서는 '분석하기'와 '설정 조합 자동 비교' 어느 쪽도 누를 수 없으며, 화면이 임시 값이나 예비 등록표로 대신 동작하지 않는다. (§4.2.2, 원칙 IV)
- **FR-019**: 역변동성과 섹터 모멘텀은 비중을 먼저 계산한 뒤 상한에 맞추므로 상한에 걸려 잘리는 몫이 생긴다. 잘린 몫은 아직 상한에 여유가 있는 섹터에 그 섹터들의 비중 비율대로 다시 나누고, 더 나눠 줄 섹터가 없을 때만 투자하지 않은 상태로 둔다. 상세 설정에서 상한을 정할 때 이 처리 방식을 한 문장으로 알린다. 최소분산은 상한을 계산의 제약으로 넣어 풀기 때문에(004 FR-025) 잘리는 몫이 생기지 않으며 이 설명을 보이지 않는다. **재배분 계산 자체는 [004](../004-backtest-execution/spec.md)가 수행해야 하나 004에 아직 그 규칙이 없다**(004 FR-020이 '처리 규칙을 적용한다'고만 두고 004 자신의 결정 항목으로 미확정 남겼다 — 003의 PD-02와는 다른 항목이다). 004가 규칙을 등록하기 전까지 003은 상한 값 전달까지만 맡는다. (§6.4.2, 원칙 IV)

### Key Entities *(include if feature involves data)*

- **전략 카드**: 화면 이름·전략 종류·한 줄 설명·선택 가능 여부와 안내 문장이다. 등록표가 활성으로 표시한 전략만 카드로 보인다.
- **파라미터 등록표(버전)**: 전략별 설정 항목마다 의미·후보 값 또는 범위·간격·기본값·유효성 제약을 가진다. 항목마다 목록형인지 입력형인지도 함께 담으며, 전략 설정뿐 아니라 시작 금액과 목표 변동성의 최소·최대·간격·기본값도 여기에 둔다. 비중 상한은 섹터별 목록이 아니라 값 하나로 담고, 리밸런싱 주기 후보는 달력 기준과 거래일 수 기준을 구분해 담는다. 여기에 더해 전략별로 필요한 워밍업 기간을 설정값에서 산출하는 규칙과 활성 여부도 함께 가진다. 서버가 보관하며 버전 식별자를 가지고, 화면은 조회 기능으로 현재 버전을 받아 온다.
- **전략 설정값**: 사용자가 확정한 전략 종류와 항목별 값, 기본값 사용 여부, 등록표 버전이다. 섹터별 목표 비중은 여기에 따로 두지 않고 [002](../002-sector-weight-selection/spec.md)가 확정한 값을 참조한다. 분석 요청으로 전달되기 전까지는 브라우저 탭 수명 동안만 보관한다.
- **분석 조건**: 분석 기간(자동 제시값과 사용자 변경값)·시작 금액·비용 가정(읽기 전용 버전과 임시 여부)·시나리오(연속 운용 기본)다. '목표 위험 맞춤' 시나리오를 고르면 목표 변동성이 더해진다(004 PD-18).
- **분석 요청**: 섹터·비중([002](../002-sector-weight-selection/spec.md)) + 전략 설정값 + 분석 조건 + 참조 버전(대응표·등록표·자료)이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 전략 카드 선택 한 번과 '분석하기' 한 번, 두 번의 행동으로 분석 요청을 시작할 수 있다. 상세 설정을 열지 않아도 요청이 접수된다. 분석 실행과 결과 표시는 [004](../004-backtest-execution/spec.md)와 [005](../005-result-comparison/spec.md)의 완료 기준을 따른다.
- **SC-002**: 빈 값·비숫자·최솟값 미만·최댓값 초과·간격 불일치를 포함한 허용 범위 밖 입력이 화면 상태·`sessionStorage`·분석 요청에 저장된 사례가 자동 경계값 테스트에서 0건이다.
- **SC-003**: 화면 입력과 화면을 거치지 않은 직접 API 요청 모두에서, 유효성 제약을 위반하는 설정으로 분석 요청이 접수된 사례가 자동 테스트에서 0건이다. 등록표 버전이 없는 호환 요청을 우회시키는 과도기 경로는 이 기준을 충족하지 않는다.
- **SC-004**: 기본값 또는 사용자 변경값으로 계산한 공통 평가 시작일이 워밍업 없이 계산한 시작일보다 늦은 모든 요청을 분모로 삼는다. 이 요청의 100%에서 선택 카드와 '분석하기' 직전 두 곳 모두에 줄어든 기간과 원인이 표시된다.
- **SC-005**: 기본 화면에 동시에 보이는 입력 항목은 전략 선택 하나다. '기본 설정 사용'은 입력이 아니라 상태 표시이며, 그 외 항목은 요청해야 열린다.
- **SC-006**: 002 SC-004와 같은 사용성 관찰 회차의 전략을 검증하려는 개인 6~8명을 대상으로, 진행자의 화면 설명 없이 전략 카드 하나를 고르고 분석 요청을 접수하는지 기록한다. 같은 단계에서 두 명 이상이 다음 행동을 찾지 못해 진행자 설명을 요청하면 '막힘'으로 기록하고, 화면을 수정한 뒤 같은 시나리오를 다시 관찰해 두 명 미만일 때 종료한다. (§7.2)
- **SC-007**: 전략과 상세 설정을 정한 뒤 화면을 새로 고치면 값이 그대로 남아 있고, 탭을 닫았다가 다시 열면 기본값 상태로 시작한다.
- **SC-008**: 파라미터 등록표를 받지 못한 상태에서 분석이 시작된 사례가 0건이다.

### Non-Functional Requirements

- **NFR-001**: 전략 카드, 상세 설정, 재시도, 행동 버튼은 키보드로 접근·조작할 수 있고 선택·펼침·비활성 상태를 스크린리더에 전달한다. 재시도 후 성공하면 초점을 새 카드 영역으로 이동하고, 실패하면 오류 안내를 읽은 뒤 재시도 버튼으로 돌아올 수 있게 한다.
- **NFR-002**: 선택 불가, 등록표·버전 조회 실패, 임시값, 유효성 위반은 색상만으로 구분하지 않고 문구와 의미 있는 상태를 함께 제공한다.
- **NFR-003**: 등록표는 공개 조회 정보이며 섹터·전략·설정값에 개인식별정보를 담지 않는다. 설정값은 계정이나 서버에 별도 저장하지 않고 현재 탭의 `sessionStorage`에만 두며 탭을 닫을 때 삭제된다.

## Assumptions

- 다섯 전략의 계산 규칙(모멘텀 유형, 최소분산 추정 방법 등)과 상한에 걸린 몫을 다시 나누는 계산은 [004](../004-backtest-execution/spec.md)가 수행한다. 이 spec은 그 규칙에 딸린 설정 항목과 허용 범위를 사용자에게 보이는 방식만 정한다.
- 파라미터 등록표의 제품 후보값·범위·간격·기본값은 PD-02(2026-09-15 확정, [data-model](data-model.md) §4·§7)를 그대로 쓴다. 007에 이미 있던 임시 값은 이번 확정과 같은 수치라 출처·버전 표시를 유지한 채 이관한다. 최소분산의 `estimationMethod`는 004 PD-04 확정 전까지 후보 하나(표본공분산)로 시작하며 값을 지어내지 않는다.
- 관측 기간은 거래일 단위이며 목록형 항목이라 등록된 후보 값 중에서 고른다. 리밸런싱 주기도 목록형이며 달력 기준과 거래일 수 기준을 모두 후보로 두므로 주기 값에는 어느 방식인지가 함께 담긴다. 비중 상한과 시작 금액은 입력형이다.
- 비용 가정은 004의 등록표가 소유한다. PD-07 확정 전에는 004가 명시한 `PROVISIONAL-DEMO-1`을 읽기 전용으로 보이고 임시값임을 알린다. 현재 버전을 조회할 수 없으면 값을 지어내지 않고 분석을 막으며 이유를 알린다.
