## 범위 요약

전략 진단의 두 번째 단계다. 사용자는 다섯 전략 카드에서 하나를 고르고 기본 설정으로 바로 분석하거나, 그 전략에 해당하는 상세 설정만 허용 범위 안에서 조정한다. 분석 기간·금액·비용은 '기간·금액·조건'에서 확인한다. 화면의 행동 버튼은 '분석하기' 하나다. 파라미터의 후보 값·범위·기본값은 실행 전에 등록표로 관리한다. (§4.2.2)

## Clarifications

### Session 2026-09-15

- Q: 전략별 후보 값과 허용 범위를 담은 파라미터 등록표는 어디에서 관리되고 화면에 어떻게 전달되나요? → A: 서버가 등록표를 보관하고 조회 API로 전달하며, 실행 시점에 서버가 다시 검증한다.
- Q: 사용자가 고른 전략과 바꾼 상세 설정값은 화면을 새로 고치거나 이전 단계로 돌아갔다 와도 유지되어야 하나요? → A: 브라우저 탭이 열려 있는 동안만 유지하고 탭을 닫으면 사라진다.
- Q: 서버에서 파라미터 등록표를 받아오지 못하면 전략 선택 화면은 어떻게 동작해야 하나요? → A: 전략 카드를 선택할 수 없는 상태로 두고 불러오지 못했다는 안내와 다시 시도할 방법을 보이며 '분석하기'를 막는다.
- Q: 전략 카드에 '이 전략은 분석할 수 없다'고 표시할 때 기준이 되는 최소 워밍업 기간은 어떻게 정해지나요? → A: 등록표가 전략별 워밍업 산출 규칙을 담고, 현재 설정값으로 계산해 설정이 바뀔 때마다 다시 판정한다. 카드 목록은 기본 설정 기준으로 판정한다.
- Q: '설정 조합 자동 비교'로 넘어갈 때 자동 탐색의 대상은 지금 고른 전략 하나인가요, 아니면 다섯 전략 전체인가요? → A: 지금 고른 전략 하나를 고정해 넘기고, 그 전략의 설정 조합만 탐색 대상으로 삼는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 전략 카드를 고르고 기본 설정으로 분석한다 (Priority: P1)

[전략을 검증하려는 개인]은 복잡한 설정을 읽지 않고 첫 분석을 시작하기 위하여 쉬운 이름과 한 줄 설명만 있는 전략 카드에서 하나를 고르고 '기본 설정 사용'으로 바로 '분석하기'를 누를 수 있다. (§4.2.2, D04)

**Why this priority**: 기획서가 첫 화면 단순함을 가장 중요한 설계 원칙으로 못 박았다(§2). 설명 없이 첫 분석을 마치는지가 사용성 확인의 첫 질문이다(§7.2).

**Independent Test**: 섹터·비중이 정해진 상태에서 전략 카드 하나를 선택하고 상세 설정을 열지 않은 채 '분석하기'가 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 섹터·비중을 정한 상태에서, **When** 전략 선택 화면이 열리면, **Then** 다섯 전략 카드가 쉬운 이름과 한 줄 설명만으로 보이고 세부 설정은 보이지 않는다.
2. **Given** 카드 하나를 선택하면, **Then** 기본 화면에는 선택한 전략과 '기본 설정 사용' 확인, 분석 기간·금액·비용 적용 여부 한 줄, '분석하기' 버튼만 보인다.
3. **Given** '기본 설정 사용' 상태에서, **When** '분석하기'를 누르면, **Then** 등록된 기본값으로 분석 요청이 만들어지고 사용자는 다른 값을 입력하지 않는다.
4. **Given** 선택 섹터의 자료가 어느 전략의 워밍업에 부족하면, **Then** 그 전략 카드에 한 문장 안내가 붙고 선택은 막지 않되 분석 기간이 그만큼 줄어든다는 사실을 알린다.

---

### User Story 2 - 상세 설정을 허용 범위 안에서 조정한다 (Priority: P2)

[전략을 검증하려는 개인]은 관측 기간이나 비중 상한 같은 조건의 영향을 보기 위하여 선택한 전략에 해당하는 상세 설정만 열어 의미와 허용 범위를 확인하며 값을 바꾸고, 필요하면 기본값으로 되돌릴 수 있다. (§4.2.2, §6.4.2, D04)

**Why this priority**: 사용자의 질문(§3.1)은 관측 기간·선정 기준·리밸런싱 주기·비중 제한에 따라 답이 달라진다. 기본 설정 다음으로 필요한 자유도다.

**Independent Test**: '변동성에 따라 나누기'를 선택해 상세 설정을 열고 변동성 관측 기간을 허용 범위 안 값과 밖 값으로 바꿔 동작을 확인한 뒤 기본값 복원을 누른다.

**Acceptance Scenarios**:

1. **Given** 전략을 선택한 상태에서, **When** '상세 설정'을 열면, **Then** 그 전략에 해당하는 항목만 열리고 각 항목의 의미·허용 범위·기본값 복원이 보인다.
2. **Given** 상세 설정에서, **When** 허용 범위 안의 값을 입력하면, **Then** 값이 반영되고 기본값이 편의용 출발점이며 최적값이 아니라는 표시가 유지된다.
3. **Given** 상세 설정에서, **When** 허용 범위 밖의 값을 입력하면, **Then** 허용 범위를 안내하고 값을 저장하지 않으며 몰래 잘라 넣지 않는다.
4. **Given** 값을 바꾼 상태에서, **When** '기본값 복원'을 누르면, **Then** 그 항목이 등록된 기본값으로 돌아간다.
5. **Given** '흐름을 따라 배분하기'에서 선정 수를 선택 섹터 수보다 크게 두면, **Then** 실행 전에 유효하지 않은 조합임을 안내한다.

### User Story 3 - 기간·금액·조건을 확인하고 바꾼다 (Priority: P2)

[전략을 검증하려는 개인]은 비교 조건을 이해하고 필요할 때 바꾸기 위하여 '기간·금액·조건'에서 자동 제시된 분석 기간·시작 금액·비용 가정을 확인하고 허용 범위 안에서 변경할 수 있다. (§4.2.2, §6.4.1, D10)

**Why this priority**: 분석 기간·비교 대상·비용 적용 여부는 요약 한 줄에 항상 보여야 한다(§4.1). 조건을 모르면 결과를 오해한다.

**Independent Test**: 상장일이 다른 섹터를 섞어 선택한 뒤 자동 제시된 분석 기간이 공통 평가 가능 범위와 같은지, 시작 금액과 비용 가정을 바꿀 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 섹터와 전략을 정한 상태에서, **When** '기간·금액·조건'을 열면, **Then** 비교 후보가 공통으로 평가 가능한 범위에서 자동 제시된 분석 기간, 시작 금액, 비용 가정(수수료·세금 등)이 보인다.
2. **Given** 후보 중 긴 관측 기간 때문에 공통 평가 구간이 줄어들면, **When** 분석을 시작하려 하면, **Then** 실행 전에 줄어든 구간과 원인을 알린다.
3. **Given** '기간·금액·조건'에서, **When** 분석 기간을 공통 평가 가능 범위 안에서 바꾸면, **Then** 반영되고 범위 밖 기간은 선택할 수 없다.
4. **Given** 어느 화면에서도, **Then** 수수료·세금·평가 기간을 수익이 높아지는 방향으로 자동 최적화하는 선택지는 없다.

---

### User Story 4 - 설정 조합 자동 비교로 넘어간다 (Priority: P3)

[전략을 검증하려는 개인]은 설정을 하나씩 바꾸는 대신 여러 조합을 한 번에 비교하기 위하여 전략 선택 화면에서 '설정 조합 자동 비교'를 선택해 자동 탐색 확인 화면으로 넘어갈 수 있다. (§4.2.2, D04)

**Why this priority**: 진입점만 이 spec의 범위다. 자동 탐색 자체는 [007](../007-auto-parameter-search/spec.md)이 정한다.

**Independent Test**: 전략 하나를 선택한 뒤 '설정 조합 자동 비교'를 눌러 그 전략과 섹터 후보 집합이 유지된 채 007의 실행 전 확인 화면이 열리는지, 다른 전략이 함께 넘어가지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 전략 하나와 섹터 후보 집합을 정한 상태에서, **When** '설정 조합 자동 비교'를 선택하면, **Then** 그 전략 하나와 섹터 후보 집합이 고정된 채 자동 탐색의 실행 전 확인 화면이 열린다.
2. **Given** 자동 비교 진입 시, **Then** 사용자는 후보 숫자를 직접 입력하지 않으며 상세 변경은 선택 사항으로만 보인다.

---

### Edge Cases

- 선택 섹터가 두 개일 때 '흐름을 따라 배분하기'의 선정 수 후보는 두 개 이하로만 보인다. 그보다 큰 등록값은 유효성 제약으로 걸러진다.
- 비중 상한들의 합계로 투자 비중을 채울 수 없는 조합(예: 섹터 3개, 상한 각 30%)은 실행 전에 안내하고 분석을 시작하지 않는다.
- 리밸런싱 주기에 등록되지 않은 값(예: 임의 일수)은 입력할 수 없다.
- 상세 설정을 바꿨다가 다른 전략 카드로 옮기면, 이전 전략의 변경값은 그 전략으로 돌아왔을 때 유지되며 다른 전략에 적용되지 않는다. 이 유지는 탭이 열려 있는 동안 계속되므로 화면을 새로 고친 뒤에도 같게 동작한다.
- 파라미터 등록표 버전이 바뀌어 저장된 설정값이 허용 범위 밖이 되면, 내 기록에서 '설정 바꿔 비교'로 열 때 그 사실을 알리고 기본값 복원을 제안한다.
- 공통 평가 가능 범위가 어느 전략에 필요한 워밍업보다 짧으면 그 전략은 분석할 수 없다는 한 문장을 카드에 표시한다. 기본 설정으로는 분석할 수 있던 전략이라도 상세 설정에서 관측 기간을 늘려 워밍업이 길어지면 그 자리에서 다시 판정해 알린다.
- 파라미터 등록표 조회가 실패하거나 아직 끝나지 않았으면 전략 카드는 선택할 수 없는 상태로 보이며, 실패 상황에서는 다시 시도할 방법을 함께 보인다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 선택한 섹터 후보 집합에 대해 아래 다섯 전략을 카드로 제공한다. 카드에는 화면 이름과 한 줄 설명만 둔다. 이 목록이 퀀트 알고리즘 전체를 뜻하지 않는다는 점을 화면에서 암시하지 않는다(단순히 다섯 방식을 보인다). (§4.2.2, D04)

  | 화면 이름 | 전략 | 한 줄 설명 |
  |---|---|---|
  | 내가 정한 비중 | 고정 목표 비중 | 지정한 비중으로 주기적으로 맞춘다. |
  | 똑같이 나누기 | 동일 비중 | 선택 섹터에 같은 목표 비중을 둔다. |
  | 변동성에 따라 나누기 | 역변동성 | 최근 변동성이 낮은 섹터에 더 큰 비중을 둔다. |
  | 흐름을 따라 배분하기 | 섹터 모멘텀 | 과거 성과의 방향 또는 상대 강도를 규칙으로 삼아 섹터를 선택·배분한다. |
  | 전체 변동성을 줄이도록 배분하기 | 최소분산 | 섹터들이 함께 움직이는 정도를 반영해 추정 포트폴리오 분산이 작아지는 비중을 계산한다. |

- **FR-002**: 기본 화면에는 선택 전략과 '기본 설정 사용' 확인, 분석 기간·비교 대상·비용 적용 여부 한 줄, '분석하기' 버튼만 보인다. 화면의 행동 버튼은 '분석하기' 하나다. (§4.1, §4.2.2)
- **FR-003**: '상세 설정'은 선택한 전략에 해당하는 항목만 열고, 각 항목의 의미·허용 범위·기본값 복원을 제공한다. 전략별 항목은 다음과 같다. (§4.2.2)

  | 전략 | 상세 설정 항목 |
  |---|---|
  | 고정 목표 비중 | 목표 비중·리밸런싱 주기·비중 상한 |
  | 동일 비중 | 리밸런싱 주기·투자 가능 섹터와 제약 |
  | 역변동성 | 변동성 관측 기간·리밸런싱 주기·비중 상한 |
  | 섹터 모멘텀 | 관측 기간·최근 구간 제외 여부·선정 수 또는 임계값·배분 방식·리밸런싱 주기 |
  | 최소분산 | 공분산 관측 기간·추정 방법·비중 상한·리밸런싱 주기 |

- **FR-004**: 기본값과 초깃값은 편의용 출발점으로 표기하고 최적값이나 투자 권고로 표기하지 않는다. (§4.2.2, 원칙 III)
- **FR-005**: 전략별로 의미가 있는 설정만 허용하고, 후보 값·범위·간격·유효성 제약·기본값을 실행 전에 파라미터 등록표로 등록한다. 등록표는 서버가 보관하는 진실의 원본이며 버전으로 관리한다. 화면은 조회 기능으로 현재 버전의 등록표를 받아 입력 항목과 허용 범위를 구성하고, 등록표 내용을 화면 쪽에 따로 적어 두지 않는다. 값 자체는 결정 항목 PD-02다. (§6.4.2)
- **FR-006**: 등록되지 않은 값은 입력·실행할 수 없다. 허용 범위 밖 값을 입력하면 허용 범위를 안내하고 저장하지 않으며 몰래 잘라 넣지 않는다. 화면의 안내는 사용자를 돕기 위한 것이고, 분석 요청을 받는 서버가 실행 직전에 등록표로 같은 검증을 다시 수행해 위반한 요청을 거절한다. (원칙 VI)
- **FR-007**: 공통 출발 설정은 월말 리밸런싱과 역변동성 63거래일 관측이다. 이 값은 출발안이며 승인된 후보 범위 안에서 변경·탐색할 수 있다. (§4.2.2, §6.4.2)
- **FR-008**: 유효성 제약(모멘텀 선정 수가 가용 섹터 수를 넘는 경우, 비중 상한들의 합계로 투자 비중을 채울 수 없는 조합 등)을 위반하는 설정은 실행 전에 안내하고 분석을 시작하지 않는다. (§6.4.2, §6.4.3)
- **FR-009**: 분석 기간은 비교 후보가 공통으로 평가 가능한 범위([001](../001-etf-market-data/spec.md)의 산출값)에서 자동 제시한다. 사용자는 그 범위 안에서만 기간을 바꿀 수 있다. (§4.2.2, §6.4.1)
- **FR-010**: '기간·금액·조건'에서 분석 기간·시작 금액·비용 가정을 확인·변경한다. 비용 가정의 기본 수치는 결정 항목 PD-07이다. 수수료·세금·평가 기간은 수익을 높이는 방향으로 자동 최적화하는 변수가 아니며 그런 선택지를 제공하지 않는다. (§4.2.2, §6.4.3, 원칙 IV)
- **FR-011**: 후보 중 긴 관측 기간 때문에 공통 평가 구간이 줄면 실행 전에 줄어든 구간과 원인을 알린다. 필요한 워밍업 기간은 등록표가 담은 전략별 산출 규칙에 현재 설정값을 넣어 계산하며, 설정값을 바꿀 때마다 다시 계산해 판정한다. 카드 목록에서는 각 전략의 기본 설정을 기준으로 판정한다. 필요한 워밍업보다 공통 평가 가능 범위가 짧으면 그 전략 카드에 분석할 수 없다는 한 문장을 표시한다. (§6.4.1, 원칙 IV)
- **FR-012**: 자동 배분 전략(역변동성·섹터 모멘텀·최소분산)을 선택하면 출력 비중이 선택한 규칙의 계산 결과이며 사용자 입력 비중과 구분된다는 설명을 보인다. (§4.2.1, D13)
- **FR-013**: '설정 조합 자동 비교' 진입점을 제공한다. 진입 시 사용자가 방금 고른 전략 하나와 섹터 후보 집합을 고정해 [007](../007-auto-parameter-search/spec.md)의 실행 전 확인 화면으로 넘기며, 003은 여러 전략을 한 번에 넘기지 않는다. 전략 선택 없이 자동 비교로 들어갈 수는 없다. (§4.2.2)
- **FR-014**: 선택 전략·설정값·분석 기간·금액·비용 가정·파라미터 등록표 버전은 분석 요청에 담겨 [004](../004-backtest-execution/spec.md)로 전달되고 [006 내 기록](../006-my-records/spec.md)에 보존된다. 여러 전략을 같은 조건으로 비교하는 요청(005 '다른 조건으로 비교', 006 '설정 바꿔 비교')은 비교 후보 전략 중 가장 긴 관측 기간을 공통 워밍업(`warmupTradingDays`)으로 함께 넘겨 모든 실행의 평가 시작일이 같게 한다(004 R-15). 사용자에게 버전이나 실험 식별자 입력을 요구하지 않는다. (§5, D14)
- **FR-015**: 계산식·자료 공급원·거리 함수·실험 식별자·서버 설정을 요구하거나 보이지 않는다. 내부 계산 항목이 많아도 화면에 동시에 나열하지 않는다. (§4.1)
- **FR-016**: 진단 화면의 용어 도움말은 [013 배우기](../013-learning-pages/spec.md)와 같은 설명을 재사용한다. (§4.5)
- **FR-017**: 선택한 전략과 상세 설정값, 분석 조건은 브라우저 탭이 열려 있는 동안 유지한다. 화면을 새로 고치거나 섹터 선택 단계로 돌아갔다가 다시 와도 값이 남아 있고, 탭을 닫으면 사라져 다음 방문에는 등록표의 기본값에서 다시 시작한다. 로그인하지 않은 사용자에게도 같게 적용한다. (§4.2.2)
- **FR-018**: 파라미터 등록표를 받아오지 못하면 전략 카드를 선택할 수 없는 상태로 두고, 설정을 불러오지 못했다는 안내와 다시 시도할 방법을 보인다. 이 상태에서는 '분석하기'를 누를 수 없으며, 화면이 임시 값이나 예비 등록표로 대신 동작하지 않는다. (§4.2.2, 원칙 IV)

### Key Entities *(include if feature involves data)*

- **전략 카드**: 화면 이름·전략 종류·한 줄 설명·선택 가능 여부와 안내 문장이다. 등록표가 활성으로 표시한 전략만 카드로 보인다.
- **파라미터 등록표(버전)**: 전략별 설정 항목마다 의미·후보 값 또는 범위·간격·기본값·유효성 제약을 가지고, 전략별로 필요한 워밍업 기간을 설정값에서 산출하는 규칙과 활성 여부도 함께 가진다. 서버가 보관하며 버전 식별자를 가지고, 화면은 조회 기능으로 현재 버전을 받아 온다.
- **전략 설정값**: 사용자가 확정한 전략 종류와 항목별 값, 기본값 사용 여부, 등록표 버전이다. 분석 요청으로 전달되기 전까지는 브라우저 탭 수명 동안만 보관한다.
- **분석 조건**: 분석 기간(자동 제시값과 사용자 변경값)·시작 금액·비용 가정·시나리오(연속 운용 기본)다.
- **분석 요청**: 섹터·비중([002](../002-sector-weight-selection/spec.md)) + 전략 설정값 + 분석 조건 + 참조 버전(대응표·등록표·자료)이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 전략 카드 선택 한 번과 '분석하기' 한 번, 두 번의 행동으로 분석을 시작할 수 있다. 상세 설정을 열지 않아도 분석이 완료된다.
- **SC-002**: 허용 범위 밖 값이 저장된 사례가 0건이다.
- **SC-003**: 유효성 제약을 위반하는 설정으로 분석이 시작된 사례가 0건이다.
- **SC-004**: 공통 평가 구간이 줄어드는 모든 분석 요청에서 실행 전 알림이 표시된다(100%).
- **SC-005**: 기본 화면에 동시에 보이는 입력 항목은 전략 선택과 '기본 설정 사용' 두 가지다. 그 외 항목은 요청해야 열린다.
- **SC-007**: 전략과 상세 설정을 정한 뒤 화면을 새로 고치면 값이 그대로 남아 있고, 탭을 닫았다가 다시 열면 기본값 상태로 시작한다.
- **SC-008**: 파라미터 등록표를 받지 못한 상태에서 분석이 시작된 사례가 0건이다.
- **SC-006**: 사용성 관찰에서 참여자가 설명 없이 다섯 전략 중 하나를 골라 첫 분석을 마치는지 기록하고, 두 명 이상이 막힌 단계는 화면을 수정한다. (§7.2)

## Assumptions

- 다섯 전략의 계산 규칙(모멘텀 유형, 최소분산 추정 방법 등)은 [004](../004-backtest-execution/spec.md)가 정한다. 이 spec은 그 규칙에 딸린 설정 항목과 허용 범위를 사용자에게 보이는 방식만 정한다.
- 파라미터 등록표는 팀이 PD-02를 확정한 뒤 채운다. 확정 전에는 기획서 출발안(월말 리밸런싱, 역변동성 63거래일)과 명시된 임시 후보로 개발한다.
- 리밸런싱 주기·관측 기간은 거래일 단위이며 후보 값 목록에서 고른다.
- 비용 가정 기본값은 PD-07 확정 전까지 명시된 임시값으로 표시하고 임시값임을 알린다.
