## 범위 요약

보조 메뉴 '내 기록'이다. 완료한 분석·자동 탐색 묶음·경제환경 탐색을 이름·섹터·전략·분석 기간·저장일로 찾아 재계산 없이 다시 열고, 조건을 바꿔 새 분석으로 비교하며, CSV/JSON으로 내보낸다. 모든 기록은 같은 조건을 재현할 수 있는 항목을 갖고, 설정 변경은 새 버전으로 보존하며 기존 결과를 덮어쓰지 않는다. 사용자에게 버전이나 실험 식별자 입력을 요구하지 않는다. (§5, D14)

- Q: 006 '내 기록'의 구현은 014 사용자 인증이 어디까지 완성된 뒤에 시작할 수 있나? (FR-020) → A: 014의 세션 인증·현재 사용자 확인·'내 기록' 접근 제한만 선행 조건이며 이 기능은 이미 완료됐다. 006은 그 방식을 그대로 사용하고 인증 방식을 다시 정하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 완료한 분석을 목록에서 찾아 다시 본다 (Priority: P1)

[전략을 검증하려는 개인]은 이전 분석과 같은 조건의 결과를 다시 확인하기 위하여 '내 기록'에서 완료한 분석을 이름·섹터·전략·분석 기간·저장일로 찾아 '다시 보기'로 저장된 동일 버전 결과를 재계산 없이 볼 수 있다. (§5, D14)

**Why this priority**: 기록은 결과 해석의 근거이며 재현성의 전제다(D14, 원칙 VIII). 다시 열 수 없는 결과는 비교의 기준이 될 수 없다.

**Independent Test**: 분석을 두 번 완료한 뒤 내 기록 목록에서 각각을 다시 열어 저장 당시와 같은 결과 화면이 재계산 없이 보이는지 확인한다. 자동 탐색·경제환경 기능 없이 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 완료한 분석이 두 개 이상 있을 때, **When** 내 기록을 열면, **Then** 각 항목이 이름·섹터·전략·분석 기간·저장일로 구분된 목록이 보이고 기본 동작 '다시 보기 / 설정 바꿔 비교'가 각 항목에 있다.
2. **Given** 목록에서 분석 하나를 선택하고, **When** '다시 보기'를 누르면, **Then** 저장된 동일 버전의 결과가 재계산 없이 열리고 '동일 버전 조회'임이 표시된다.
3. **Given** 다시 본 결과에서, **Then** 저장 당시 참조한 자료 버전·대응표 버전·등록표 버전·비용 조건 버전이 상세에서 확인되고, 그 뒤 자료가 갱신됐어도 결과 값은 저장 당시와 같다.
4. **Given** 어느 화면에서도, **Then** 사용자에게 버전이나 실험 식별자 입력을 요구하지 않는다.

### User Story 2 - 설정을 바꿔 새 분석으로 비교한다 (Priority: P1)

[전략을 검증하려는 개인]은 조건 변경의 영향을 비교하기 위하여 다시 본 분석에서 '설정 바꿔 비교'를 눌러 기존 조건이 채워진 설정 화면을 열고, 분석하면 새 분석으로 저장되어 기존 결과가 덮어쓰이지 않게 할 수 있다. (§5, D14, D15)

**Why this priority**: 설정 변경을 새 버전으로 보존하는 규칙은 나중의 결과에 맞춰 과거 기준을 덮어쓰지 않기 위한 장치다(원칙 VIII). 비교의 기준이 사라지면 진단이 성립하지 않는다.

**Independent Test**: 저장된 분석에서 '설정 바꿔 비교'로 리밸런싱 주기를 바꿔 분석한 뒤, 내 기록에 원본과 새 분석이 모두 남고 원본 결과가 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 다시 본 분석에서, **When** '설정 바꿔 비교'를 누르면, **Then** 기존 섹터·비중·전략·설정·분석 조건이 채워진 전략 선택 화면이 열린다.
2. **Given** 그 화면에서 설정을 바꿔, **When** '분석하기'를 누르면, **Then** 새 분석으로 저장되고 원본 분석과 그 결과는 바뀌지 않는다.
3. **Given** 새 분석이 완료되면, **Then** 내 기록에 원본과 새 분석이 별도 항목으로 보이고 두 항목을 [005](../005-result-comparison/spec.md)의 비교 대상으로 고를 수 있다.
4. **Given** 파라미터 등록표 버전이 바뀌어 저장된 설정값이 현재 허용 범위 밖이면, **When** '설정 바꿔 비교'로 열면, **Then** 그 사실을 한 문장으로 알리고 기본값 복원을 제안하며 값을 몰래 바꾸지 않는다.

### User Story 3 - 자동 탐색 묶음과 경제환경 탐색 기록을 함께 본다 (Priority: P2)

[전략을 검증하려는 개인]은 여러 종류의 분석을 한 곳에서 관리하기 위하여 자동 탐색 결과를 한 묶음으로 보고 펼쳐서 후보별 결과·선정 이유·실패 또는 제외 사유를 확인하며, 경제환경 탐색 기록도 같은 목록에서 다시 열 수 있다. (§5, D14, D26)

**Why this priority**: 자동 탐색과 경제환경 탐색은 전략 단일 분석 위에 있는 기능이다. 그 기록이 없으면 두 기능의 결과를 재현할 수 없지만, 단일 분석 기록이 먼저 있어야 한다.

**Independent Test**: 자동 탐색 한 번과 경제환경 탐색 한 번을 완료한 뒤 내 기록에서 묶음 항목을 펼쳐 후보별 상태가 보이는지, 경제환경 탐색 항목이 기준월·분야 또는 종합 모드와 함께 다시 열리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 자동 탐색이 완료됐을 때, **When** 내 기록을 보면, **Then** 탐색 묶음이 한 항목으로 보이고 펼치면 후보별 결과·선정 이유·실패 또는 제외 사유·후보 실행 상태(완료/실패/제외/취소/미실행)가 보인다.
2. **Given** 경제환경 탐색을 수행했을 때, **When** 내 기록을 보면, **Then** 선택 분야 또는 종합 모드·실제 질의 기준월·연결한 섹터·전략과 함께 항목이 보이고 다시 열면 저장된 후보 순위가 그대로 보인다.
3. **Given** 경제환경 탐색 기록에서, **Then** 전체 후보와 표시 후보·제외 이유·지표 원값과 표준화 값·분야별 거리·자료 개정 기준·모델 버전·사후 평가 구간·당시 정보 재현 여부·ETF 가용성 필터가 상세에서 확인된다.
4. **Given** 시장 흐름 진입과 전략 결과 진입으로 만든 두 경제환경 검색이 있으면, **Then** 두 기록은 별도 항목으로 보존되고 한쪽이 다른 쪽을 대체하지 않는다.

### User Story 4 - 기록을 내보낸다 (Priority: P2)

[전략을 검증하려는 개인]은 결과를 다른 도구에서 검토하기 위하여 기록 항목의 추가 메뉴에서 CSV 또는 JSON으로 내보내되, 원천 시세·기사는 자료별 이용 범위 안에서만 포함되게 할 수 있다. (§5, §6.2, D19)

**Why this priority**: 내보내기는 재현과 외부 대조를 돕는 보조 기능이다. 자료 이용 조건(원칙 X)을 지키는 범위가 먼저 정해져야 한다.

**Independent Test**: 완료한 분석 하나를 CSV와 JSON으로 내보내 설정·결과·거래 내역이 담기는지, 원천 일별 시세 원값과 기사 본문이 포함되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기록 항목에서, **When** 추가 메뉴의 내보내기를 누르면, **Then** CSV 또는 JSON 형식을 골라 받을 수 있고 파일에는 설정값·참조 버전·핵심 결과·거래 내역·예외 처리 기록이 담긴다.
2. **Given** 내보낸 파일에서, **Then** 재배포가 금지된 원천 시세의 일별 원값과 기사 본문은 포함되지 않고, 포함되지 않은 항목과 그 이유가 파일 안에 표시된다.
3. **Given** 자동 탐색 묶음을 내보내면, **Then** 탐색 공간·후보별 결과·상태·제외 사유·선정 규칙이 함께 담긴다.

### User Story 5 - 기록을 정리한다 (Priority: P3)

[전략을 검증하려는 개인]은 목록을 관리하기 위하여 기록 항목의 이름을 바꾸거나 삭제하고, 삭제된 항목이 내 기록의 어느 자리에도 다시 나타나지 않게 할 수 있다. (§5, D14)

**Why this priority**: 보관 기간·삭제·연결 해제 정책은 결정 항목(PD-13)이다. 정책 확정 전에도 이름 변경과 사용자 삭제는 제공하되, 무기한 보관을 전제하지 않는다.

**Independent Test**: 기록 항목의 이름을 바꾸고 다른 항목을 삭제한 뒤 내 기록 목록과 006의 선택 자리에서 삭제 항목이 보이지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기록 항목에서, **When** 이름을 바꾸면, **Then** 목록의 이름만 바뀌고 저장된 결과와 참조 버전은 변하지 않는다.
2. **Given** 기록 항목을, **When** 삭제하면, **Then** 확인 뒤 사용자의 목록에서 사라지고 그 항목은 006이 제공하는 어떤 선택 자리에도 다시 나타나지 않으며, 같은 공용 계산 결과를 가리키는 다른 사용자의 항목은 그대로 다시 열린다.
3. **Given** 삭제된 분석을 참조하던 다른 기록(예: 그 분석의 결과에서 진입한 경제환경 탐색 기록)이 있으면, **Then** 그 기록은 유지되고 참조가 삭제됐다는 표시가 붙는다.

### Edge Cases

- 저장 뒤 자료 버전이 갱신됐어도 '다시 보기'는 저장 당시 버전의 결과를 보인다. 최신 자료로 다시 계산하려면 '설정 바꿔 비교'로 새 분석을 만든다.
- 대표 ETF 대응표 버전이 바뀌어 저장한 섹터가 현재 목록에서 사라졌으면, 다시 열 때 그 사실을 알린다. '설정 바꿔 비교'에서는 대체 섹터를 고르게 하되 자동으로 바꾸지 않는다. 섹터는 남았지만 대표 ETF가 다른 종목으로 교체됐으면 다시 열 때 그 사실도 같은 방식으로 알린다. 대응 내용이 같고 버전 번호만 올랐으면 알리지 않는다. 섹터 이름·표시 순서만 바뀐 경우는 대응 내용 변경으로 보지 않는다.
- 파라미터 등록표 버전이 바뀌어 저장된 설정값이 허용 범위 밖이면 기본값 복원을 제안한다. 값을 몰래 잘라 넣지 않는다.
- 실패·취소된 분석은 상태와 이유가 붙은 항목으로 남는다. 목록의 기본 보기는 완료 항목이며 실패·취소 항목은 필터로 본다.
- 식별되지 않은 사용자는 진단을 수행할 수 있지만 내 기록에 저장되지 않는다. 저장이 필요할 때 식별을 안내하고, 진단 중인 입력은 유지한다.
- 자동 탐색 묶음이 부분 완료 상태로 끝났으면 묶음 항목에 부분 완료임과 완료 범위가 표시된다.
- 내보내기 대상에 이용 범위가 다른 자료가 섞여 있으면 허용된 부분만 담고 제외 항목을 파일 안에 명시한다.
- 같은 조건으로 두 번 분석하면 두 번째는 동일 버전 조회로 처리되어 새 기록을 만들지 않는다. 별도 이름의 사본은 이번 범위에서 만들지 않는다. 저장 구조는 사본을 막지 않게 열어 둔다.
- 탐색 묶음 저장 상한(설정값, 초기 임시값 20개)에 도달하면 새 탐색을 시작하기 전에 현재 개수와 상한을 알리고, 사용자가 지우기 전에는 새 묶음을 저장하지 않는다. 기존 항목을 몰래 삭제하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

#### 목록과 기본 동작 (§4.1, §5)

- **FR-001**: 내 기록은 보조 메뉴로 제공하고, 완료한 분석·자동 탐색 묶음·경제환경 탐색을 이름·섹터·전략·분석 기간·저장일로 구분해 목록으로 보인다. (§5) 기록이 하나도 없으면 빈 목록과 진단 시작 연결을 보인다.
- **FR-002**: 각 항목의 주 동작은 '다시 보기'이고 '설정 바꿔 비교'는 보조 동작으로 같은 줄에 둔다. 같은 크기의 버튼 둘로 두지 않는다(원칙 II). 상세 설정·거래 내역·내보내기·이름 변경·삭제는 추가 메뉴에서 접근한다. (§5)
- **FR-003**: 항목 이름은 저장 시 섹터·전략·저장일로 자동 부여하고 사용자가 바꿀 수 있다. 사용자에게 이름 입력을 요구하지 않는다.
- **FR-004**: 목록은 저장일 기준 최신순이 기본이며 섹터·전략·분석 기간·종류(단일 분석/탐색 묶음/경제환경 탐색)·상태(완료/진행 중/실패/취소/부분 완료)로 걸러 볼 수 있다. 기본 보기는 완료 항목이다. 경제환경 탐색 항목의 상태는 [010](../010-economic-regime-search/spec.md)이 정한 값(계산 불가·근접만·문턱 적용)을 그대로 보이고 완료/실패로 바꿔 부르지 않는다. 목록에는 수익률·하락 폭·비용을 표시하지 않고 정렬 기준에도 넣지 않는다. 그 값은 다시 보기에서 본다(원칙 III).
- **FR-005**: 사용자에게 버전이나 실험 식별자 입력을 요구하지 않는다. 버전은 시스템이 부여하고 상세에서만 보인다. (§5, D14)

#### 다시 보기와 설정 바꿔 비교 (§5, §6.5, D14, D15)

- **FR-006**: '다시 보기'는 저장된 동일 버전의 결과를 재계산 없이 [005](../005-result-comparison/spec.md) 화면으로 열고 '동일 버전 조회'임을 표시한다. 저장 뒤 자료가 갱신됐어도 결과 값은 저장 당시와 같다.
- **FR-007**: '설정 바꿔 비교'는 기존 섹터·비중·전략·설정·분석 조건이 채워진 [003](../003-strategy-settings/spec.md) 화면을 연다. 저장 당시 대응표 버전이 현재와 다르면 섹터·비중은 채우지 않고 전략·설정·분석 조건만 채운 뒤 섹터를 다시 고르게 안내한다 — 다른 대응표에서 만든 선택을 지금 버전으로 옮기지 않는다([005](../005-result-comparison/spec.md) '다른 조건으로 비교'와 같은 동작, 원칙 VIII). 분석하면 새 분석(새 버전)으로 저장하고 기존 결과를 덮어쓰지 않는다. 나중의 결과에 맞춰 과거 기준을 덮어쓰지 않는다. (§5, D14, D15)
- **FR-007a**: 저장 결과의 파라미터 등록표 버전(`registryVersion`)과 실제 적용한 공통 워밍업(`warmupTradingDays`)·평가 기간은 당시 조건으로 보존한다. '설정 바꿔 비교'로 만든 새 분석은 003의 현재 등록표로 설정을 재검증하고 새 설정에 필요한 워밍업을 다시 산정한다. 기존 결과와 비교할 때는 003 FR-014·005 FR-004~FR-005에 따라 긴 쪽의 공통 워밍업을 사용한다. 평가 기간이 달라지면 공통 구간과 재실행할 대상을 알리고 사용자 확인 뒤 새 실행을 요청하며, 원본 결과를 덮어쓰지 않는다.
- **FR-008**: 저장된 조건이 현재 대응표·등록표 버전과 맞지 않으면(섹터 삭제, 허용 범위 밖 값) 열 때 한 문장으로 알리고 기본값 복원이나 대체 선택을 제안한다. 값을 자동으로 바꾸지 않는다. (원칙 VI) 대응표 버전만 올라가고 저장된 섹터의 대응 내용이 그대로면 '다시 보기'에서 알리지 않고 상세의 참조 버전 표시로만 보인다. 저장된 섹터의 대응 내용이 실제로 달라졌으면(대표 ETF 교체·섹터 삭제) 다시 보기에서 한 문장으로 알린다. 버전이 오를 때마다 알리면 결과가 바뀌지 않았는데도 경고가 늘어 원칙 II와 충돌한다. (UI-01, 2026-09-18 결정. 소유 표시는 [001](../001-etf-market-data/spec.md) FR-003이며 [002](../002-sector-weight-selection/spec.md)·[005](../005-result-comparison/spec.md)가 이 결정을 따른다)
- **FR-009**: 같은 조건(동일 버전)으로 다시 분석하면 [004](../004-backtest-execution/spec.md)의 동일 결과 재사용 규칙에 따라 새 기록을 만들지 않고 기존 항목으로 연결한다.

#### 저장 항목 (§5, D14, D26)

- **FR-010**: 완료한 분석마다 전략·파라미터 범위·선정 기준·시드·평가 분할·섹터/ETF 대응·당시 대상·데이터 마감/버전·비용·엔진·검색 설정·사례 선정·원본 식별자를 저장한다. 검색 설정·사례 선정을 뺀 항목은 [004](../004-backtest-execution/spec.md) FR-028이 남긴 것을 그대로 보존한다. 검색 설정·사례 선정은 [010](../010-economic-regime-search/spec.md)이 스냅샷에 남긴 것을 가리킨다. (§5, D14)
- **FR-011**: 자동 탐색은 한 묶음으로 저장하고 펼치면 후보별 결과·선정 이유·실패 또는 제외 사유·후보 실행 상태(완료/실패/제외/취소/미실행)·탐색 공간·미실행 후보 수·정렬 및 선정 규칙을 보인다. 유효하지 않아 계산하지 않은 후보도 제외 사유를 남긴다. (§5)
- **FR-012**: 경제환경 탐색 기록에는 선택 분야 또는 종합 모드, 실제 질의 기준월(T_g/T_all 또는 지정월), 전체 후보와 표시 후보, 제외 이유, 지표 원값과 표준화 값, 분야별 거리, 자료 개정 기준, 모델 버전, 연결한 섹터·ETF·전략·사후 평가 구간, 당시 정보 재현 여부, ETF 가용성 필터를 저장한다. 시장 흐름 진입과 전략 결과 진입의 순위·필터·연결 결과는 별도 항목으로 보존한다. (§5, D14, D26) 연결한 섹터·ETF·전략·사후 평가 구간·ETF 가용성 필터는 [011](../011-regime-strategy-link/spec.md)이 만드는 값이며 011 구현 전에는 비어 있다. 비어 있음을 표시하고 기본값이나 추정값으로 채우지 않는다(원칙 VI).
- **FR-013**: 전략 파라미터·경제환경 검색 설정·평가 시나리오는 별도 축으로 기록한다. (§6.4.3)
- **FR-014**: 실패·취소·부분 완료 항목은 상태와 이유를 함께 저장하고 낮은 수익과 구분해 표시한다. (§6.4.3, §7.1)

#### 내보내기와 이용 조건 (§5, §6.2, D19, 원칙 X)

- **FR-015**: CSV/JSON 내보내기를 제공한다. 파일에는 설정값·참조 버전·핵심 결과·시계열·거래 내역·예외 처리 기록·(탐색 묶음이면) 후보별 결과와 상태·(경제환경 탐색이면) FR-012 항목이 담긴다. (§5) 내보내기는 완료·부분 완료·실패·취소 항목에 제공한다. 실패·취소 항목은 설정값·참조 버전·사유만 담는다. 진행 중 항목은 내보낼 수 없다.
- **FR-016**: 원천 시세·기사의 내보내기는 자료별 이용 범위 안에서만 제공한다. 재배포가 금지된 원천의 일별 시세 원값과 기사 본문은 포함하지 않고, 제외한 항목과 이유를 파일 안에 표시한다. (§6.2, §6.3, 원칙 X)

#### 정리·보관·개인정보 (§5, D14)

- **FR-017**: 사용자는 항목 이름을 바꾸고 항목을 삭제할 수 있다. 삭제는 확인 뒤 수행한다. **삭제 단위는 개인 기록 항목(소유·이름·목록 노출·경제환경 연결 대상으로서의 지위)이며 그가 가리키는 공용 계산 결과(결과·거래 내역·참조 버전)는 삭제하지 않는다.** FR-009의 동일 결과 재사용 구조라 같은 결과를 다른 사용자의 항목이나 다른 기록이 함께 가리킬 수 있어, 한 사용자의 삭제가 다른 사용자의 재현을 깨뜨리지 않게 하기 위함이다. 삭제된 항목은 그 사용자의 내 기록 목록과 006이 제공하는 모든 선택 자리에서 제외되며 다시 복구할 수 없다. [005](../005-result-comparison/spec.md)의 비교 대상 선택은 저장된 기록이 아니라 전략·버전 등록표에서 고르므로 006 삭제와 무관하고, [011](../011-regime-strategy-link/spec.md)의 연결 대상은 011 기록을 기준으로 한다 — 두 spec이 내 기록을 선택 목록으로 쓰게 되면 삭제 표시를 따라야 하며 006은 그 사실을 전달한다. 삭제된 항목을 참조하던 기록은 유지하되 참조 삭제 표시를 붙이고, 그 표시는 공용 결과가 아니라 개인 항목이 없어졌다는 뜻이다.
- **FR-018**: 보관 기간·연결 해제·탐색 묶음 저장 상한은 결정 항목 PD-13이며 무기한 보관을 전제하지 않는다. 확정 전에는 사용자 삭제만 제공하고 시간 기반 자동 삭제(저장일·마지막 열람일 기준 만료, 삭제 여유 기간, 삭제 예고 표시)를 만들지 않는다. 나중에 보관 기간을 도입할 수 있도록 항목마다 생성 시각과 마지막 열람 시각을 저장한다. 상한은 탐색 묶음에만 둔다 — 단일 분석·경제환경 항목에는 개수 상한이 없다. 상한에 도달하면 새 저장 전에 알리고 기존 항목을 몰래 삭제하지 않는다. 이 알림은 실행 자원 한도([004](../004-backtest-execution/spec.md) PD-06)와 다른 사유로 구분해 전달한다. (§5, D14) 탐색 묶음 상한은 값과 분리해 장치를 먼저 만든다: 사용자당 묶음 개수 상한은 설정 가능한 값이고 초기 임시값은 20개이며, 이 spec은 확정값을 고정하지 않는다(004 PD-06의 한도 장치 방식과 같다). 공용 계산 결과 자체의 보관·만료는 이 spec이 아니라 004와 [005](../005-result-comparison/spec.md) PD-23이 소유한다.
- **FR-019**: 시도·실패·최종 평가 열람 등 감사 정보는 내부에서 관리하고 사용자 화면에 나열하지 않는다. 개인 식별정보는 계산 기록과 분리해 보관한다. (§5)
- **FR-020**: 내 기록 저장·재조회는 식별된 사용자 단위로 동작한다. 식별되지 않은 사용자도 진단·시장 흐름·배우기는 이용할 수 있고, 저장이 필요할 때만 식별을 안내한다. **인증·인가 방식은 [014](../014-user-auth/spec.md)가 소유하며 006은 다시 정하지 않는다.** 006의 선행 조건은 014의 세션 인증과 현재 사용자 확인([014](../014-user-auth/spec.md) FR-008), 그리고 비로그인 사용자의 '내 기록' 접근 제한과 로그인 후 원래 위치 복귀([014](../014-user-auth/spec.md) FR-011·FR-012)뿐이며 2026-09-18 현재 이 기능은 구현·계약 검증이 끝났다. 006은 요청자의 사용자 식별을 그 세션 인증에서 받아 쓰고 임시 식별 수단을 따로 만들지 않는다. 다른 사용자의 기록은 없는 것으로 응답하며 존재 여부를 알리지 않는다. 이름 변경·삭제 중 로그인이 만료되면 014 FR-012의 규칙(보호 정보 숨김·재로그인 안내·원래 위치 복귀)을 따른다.
- **FR-021**: 목록·추가 메뉴·삭제 확인·내보내기 선택은 키보드만으로 조작할 수 있고, 이름 변경·삭제·내보내기의 처리 중·성공·실패는 상태 알림 영역으로 전달한다([014](../014-user-auth/spec.md) FR-016과 같은 수준).

### Key Entities *(include if feature involves data)*

- **내 기록 항목**: 종류(단일 분석/탐색 묶음/경제환경 탐색), 이름, 섹터, 전략, 분석 기간, 저장일, 상태, 소유 사용자, 참조 대상(결과·묶음·검색)의 식별자다. 설정 변경은 새 항목(새 버전)이다. 개인 항목은 공용 계산 결과를 가리키는 소유 기록이다. 항목을 삭제하면 소유 기록만 사라지고 공용 결과는 남는다(FR-017).
- **재현 기록**: FR-010의 항목 묶음이다. 결과와 함께 보존되고 버전을 가진다.
- **경제환경 탐색 기록**: FR-012의 항목 묶음이다. 검색 경로(시장 흐름/전략 결과)별로 별도 항목이다.
- **내보내기 파일**: 형식(CSV/JSON), 포함 항목, 제외 항목과 이유, 생성 시각이다.
- **사용자**: 내 기록의 소유자다. 식별정보는 계산 기록과 분리해 보관한다.
- **감사 기록**: 시도·실패·열람 이력이며 내부 전용이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 완료한 분석·탐색 묶음·경제환경 탐색의 100%가 FR-010~FR-012의 기록 항목을 갖고 내 기록에서 동일 버전으로 다시 열린다.
- **SC-002**: '다시 보기'로 연 결과 값이 저장 당시 결과와 다른 사례가 0건이다. 저장 뒤 자료 갱신이 있어도 같다.
- **SC-003**: '설정 바꿔 비교'로 만든 새 분석이 원본 결과를 바꾼 사례가 0건이다.
- **SC-004**: 사용자가 버전·실험 식별자·항목 이름을 직접 입력해야 하는 화면이 0개다.
- **SC-005**: 내보낸 파일에 재배포 금지 원천의 일별 시세 원값이나 기사 본문이 포함된 사례가 0건이다.
- **SC-006**: 사용성 관찰(전략을 검증하려는 개인 6~8명)에서 참여자가 설명 없이 이전 분석을 다시 열고 조건을 바꿔 비교하는지 기록하고, 두 명 이상이 같은 단계에서 막히면 목록·동작 이름을 수정한다. (§7.2, D20)
- **SC-007**: 한 사용자가 기록 항목을 삭제한 뒤 같은 공용 계산 결과를 가리키던 다른 항목이 열리지 않게 된 사례가 0건이다. (FR-017)

## Assumptions

- 내 기록은 식별된 사용자 단위로 동작하고, 진단·시장 흐름·배우기는 식별 없이 이용할 수 있다. 인증·인가 방식은 [014](../014-user-auth/spec.md)가 확정한 세션 인증을 그대로 쓰며 006의 plan에서 다시 정하지 않는다(`specs/README.md` 공통 가정).
- 항목 이름은 섹터·전략·저장일로 자동 생성한다. 기획서는 이름을 목록 구분 항목으로만 언급하므로 입력을 요구하지 않는 쪽으로 해석했다.
- 실패·취소 항목도 보존한다. 기획서 §5가 시도·실패 감사 정보를 내부 관리 대상으로 두고 있어, 사용자 목록에는 기본 숨김·필터 표시로 해석했다.
- 같은 항목에 대한 동시 편집(두 탭에서 이름 변경·삭제) 충돌은 다루지 않는다. 마지막 요청이 이긴다.
- 보관 기간·삭제 정책(PD-13) 확정 전에는 사용자 삭제만 제공하고 자동 삭제는 하지 않는다(2026-09-18 명료화). 생성·마지막 열람 시각 저장은 FR-018에 있다.
- 내보내기 파일의 열 구성과 인코딩은 plan에서 정한다.
- 한국어 웹 화면이며 데스크톱 브라우저를 우선한다.
