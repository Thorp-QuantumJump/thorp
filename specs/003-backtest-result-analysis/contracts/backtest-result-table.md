# `backtest_result` 저장 계약 (Worker → PostgreSQL ← Backend)

**Date**: 2026-09-03 | **Data model**: [../data-model.md](../data-model.md) | **지표 계산 규약 v1.0**: [../research.md §2](../research.md)

백엔드는 이 테이블을 **읽기만** 한다(dev 시더 예외). Worker가 백테스트를 마치면 `backtest_job.status`를 `COMPLETED`로 바꾸고
이 테이블에 **Job당 정확히 한 행**을 INSERT한다. 두 쓰기는 한 트랜잭션으로 묶는 것을 권장한다(둘 중 하나만 반영되면
`GET /backtests/{id}/timeseries`가 409를 계속 돌려준다).

## 컬럼

| 컬럼 | 타입 | NULL | 의미 / 규약 |
|---|---|---|---|
| `id` | `BIGINT` GENERATED BY DEFAULT AS IDENTITY, PK | X | Worker는 지정하지 않는다 |
| `backtest_job_id` | `BIGINT`, UNIQUE | X | `backtest_job.id`. FK 제약은 Flyway 도입 시 추가 예정이므로 Worker가 존재하는 id만 써야 한다 |
| `initial_equity` | `BIGINT` | X | 시작 자산(KRW 정수) = `backtest_job.initial_cash`. **`equity_curve[0].equity`와 같아야 한다** |
| `final_equity` | `BIGINT` | X | 종료 시점 총 자산(KRW 정수). **`equity_curve[last].equity`와 같아야 한다** |
| `total_return` | `DOUBLE PRECISION` | O | `final_equity / initial_equity - 1` |
| `cagr` | `DOUBLE PRECISION` | O | `(final/initial)^(365/달력경과일) - 1` |
| `max_drawdown` | `DOUBLE PRECISION` | O | `min(drawdown)`. 0 또는 음수 |
| `volatility` | `DOUBLE PRECISION` | O | 일별수익률 표본표준편차(ddof=1) × √252. 관측치 2개 미만이면 NULL |
| `sharpe_ratio` | `DOUBLE PRECISION` | O | `(mean(daily) × 252 − 0.0) / volatility`. volatility NULL 또는 0이면 NULL |
| `trade_count` | `INTEGER` | X | 청산 거래 수. 0 허용 |
| `win_rate` | `DOUBLE PRECISION` | O | `0 ~ 1`. `trade_count = 0`이면 NULL |
| `profit_factor` | `DOUBLE PRECISION` | O | `>= 0`. 거래 0건·손실 거래 없음·이익 거래 없음이면 NULL |
| `metric_definition_version` | `VARCHAR(20)` | X | 현재 `'1.0'` |
| `equity_curve` | `JSONB` | X | 아래 형식의 JSON 배열. 기간 내 **모든 거래일**, 날짜 오름차순 |
| `created_at` | `TIMESTAMP` | X | 저장 시각(Worker가 `now()` 기록) |
| `updated_at` | `TIMESTAMP` | X | 저장 시각(Worker가 `now()` 기록) |

**NULL 규칙**: 계산 불가는 반드시 `NULL`. `0`·`NaN`·`Infinity`를 넣지 않는다(FR-011). `DOUBLE PRECISION`에 `NaN`/`Infinity`는
PostgreSQL이 받아들이지만 백엔드 도메인 검증에서 거부되거나 JSON 응답이 깨지므로 금지한다.

## `equity_curve` 원소 형식

```json
[
  { "date": "2019-01-02", "equity": 10000000, "cumulativeReturn": 0.0, "drawdown": 0.0 },
  { "date": "2019-01-03", "equity": 10120000, "cumulativeReturn": 0.012, "drawdown": 0.0 },
  { "date": "2019-01-04", "equity": 10050000, "cumulativeReturn": 0.005, "drawdown": -0.0069 }
]
```

| 키 | 타입 | 규약 |
|---|---|---|
| `date` | string `YYYY-MM-DD` | 거래일. strictly ascending, 중복 없음 |
| `equity` | integer | 종가 기준 총 자산(KRW). `>= 0` |
| `cumulativeReturn` | number | `equity / equity[0] - 1` |
| `drawdown` | number | `equity / max(equity[0..t]) - 1`. 0 또는 음수 |

키 이름은 camelCase 그대로 써야 한다(백엔드가 이 키로 역직렬화한다). 추가 키가 있으면 역직렬화 실패 가능성이 있으므로 넣지 않는다.

## Worker INSERT 예시 (psycopg / SQLAlchemy 등)

```sql
BEGIN;
UPDATE backtest_job SET status = 'COMPLETED', updated_at = now() WHERE id = :job_id;
INSERT INTO backtest_result (
  backtest_job_id, initial_equity, final_equity, total_return, cagr, max_drawdown, volatility,
  sharpe_ratio, trade_count, win_rate, profit_factor, metric_definition_version, equity_curve,
  created_at, updated_at
) VALUES (
  :job_id, :initial_equity, :final_equity, :total_return, :cagr, :max_drawdown, :volatility,
  :sharpe_ratio, :trade_count, :win_rate, :profit_factor, '1.0', :equity_curve_json::jsonb,
  now(), now()
);
COMMIT;
```

## Worker `models.py` 동기화 (후속 티켓)

현재 `worker/src/worker/models.py`의 `BacktestResult(job_id, total_return, mdd, sharpe, trade_count)`를 위 컬럼 집합으로 확장하고,
`BacktestJob`에 `initial_cash: int = Field(alias="initialCash", default=10_000_000)`을 추가한다. 이 브랜치에서는 수정하지 않는다.

## 백엔드 검증(참고)

백엔드는 행을 읽을 때 도메인 불변식을 검증한다. 위반 시 조회가 500으로 실패하므로 Worker는 다음을 보장해야 한다.

- `equity_curve`가 비어 있지 않고 날짜 오름차순
- `equity_curve[0].equity == initial_equity`, `equity_curve[last].equity == final_equity`
- `max_drawdown <= 0`, `0 <= win_rate <= 1`, `profit_factor >= 0`, `trade_count >= 0`, `metric_definition_version` 비어 있지 않음
