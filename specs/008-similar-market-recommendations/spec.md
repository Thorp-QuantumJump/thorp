# Feature Specification: 유사 시장 기반 전략 후보 제시

**Feature Branch**: `008-similar-market-recommendations`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "F8. 유사 시장 기반 전략 추천 — Thorp에서 유사한 과거 시장의 실제 백테스트 결과를 이용해 사용자가 살펴볼 전략 후보를 제시한다. 사용자는 현재 또는 선택한 시장 상황을 기준으로 후보와 근거가 된 유사 시장·성과를 확인하고, 성과와 위험 특성을 비교하며, 사용 데이터와 검증 기준을 추적할 수 있어야 한다. 미래 데이터로 과거 추천을 만들거나 미래 수익을 보장한다고 표현할 수 없고, 추천 과정은 추천에 쓰지 않은 미래 구간에서 별도로 검증 가능해야 한다. 실제 투자 자문, 자동 주문, 유사 시장 탐색 알고리즘, 구체적인 추천 모델 및 포트폴리오 자동 구성은 제외한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 실제 근거가 있는 전략 후보 생성 (Priority: P1)

현재 또는 특정 과거 시장 상황에서 어떤 전략부터 검토할지 모르는 사용자가 완료된 유사 시장 검색(F7)을
선택한다. 사용자는 추천 기준 시점, 근거로 사용할 유사 구간, 평가할 전략 후보 집합과 적용될 추천 정의를
확인한다. 시스템은 선택된 모든 유사 구간에서 같은 조건으로 성공 완료된 실제 백테스트가 있는 후보만을
평가하고, 사용자가 지정한 최대 개수까지 검토 후보를 제시한다.

**Why this priority**: 유사 시장과 실제 전략 성과가 연결되지 않으면 추천의 핵심 근거가 사라진다. 후보를
만들기 전에 비교 조건과 증거의 완전성을 확인해야 결과가 공정하고 추적 가능하다.

**Independent Test**: 유사 구간 3개와 전략 후보 5개를 준비하되 일부 후보의 결과를 누락하거나 조건을
다르게 만든다. 추천을 생성했을 때 모든 구간에서 비교 가능한 완료 결과가 있는 후보만 평가되고, 제외된
후보와 이유, 추천 기준 시점과 적용 정의가 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 접근 가능한 완료 유사 시장 검색, **When** 사용자가 추천 준비 화면을 열면, **Then** 기준 시장
   상황, 정보 기준 시점, 유사 구간과 유사성 근거, 사용할 전략 후보 집합이 표시된다.
2. **Given** 각 유사 구간에 동일 조건으로 완료된 전략별 백테스트 결과, **When** 사용자가 추천 생성을
   확인하면, **Then** 실제 결과가 있는 후보만 평가되고 추천 식별자와 검토 후보 목록이 제공된다.
3. **Given** 어느 유사 구간에서 결과가 없거나 실패했거나 비교 조건이 다른 후보, **When** 추천 근거를
   준비하면, **Then** 해당 후보는 평가에서 제외되고 누락 구간 또는 불일치 조건이 구체적으로 표시된다.
4. **Given** 비교 가능한 후보가 둘 미만인 상태, **When** 사용자가 추천을 생성하려 하면, **Then** 후보
   비교에 필요한 근거가 부족하다는 안내와 함께 추천 결과가 생성되지 않는다.
5. **Given** 적용될 추천 정의, **When** 사용자가 설명을 열면, **Then** 유사 구간 반영 방식, 성과·위험
   지표, 후보별 값을 종합하는 규칙, 순위와 동률·계산 불가 처리, 최대 제시 수 및 정의 버전을 확인할 수 있다.

### User Story 2 - 후보 성과·위험과 추천 근거 비교 (Priority: P2)

사용자는 제시된 전략 후보를 나란히 놓고 유사 구간별 실제 백테스트 성과, 구간 전체를 요약한 평가 값,
수익과 위험 특성을 비교한다. 각 후보가 앞선 이유와 불리했던 구간도 함께 확인하고, 원본 유사 시장 검색과
백테스트 결과로 이동해 세부 근거를 검증한다.

**Why this priority**: 초보 사용자가 후보 이름이나 단일 점수만 보고 선택하지 않게 하려면 성과와 위험의
상충 관계, 유사 구간별 편차와 원본 결과를 한 화면에서 이해할 수 있어야 한다.

**Independent Test**: 수익률은 높지만 낙폭이 큰 후보, 안정적이지만 수익률이 낮은 후보, 구간별 편차가 큰
후보가 포함된 결과를 열어 F3 원본 지표와 값이 일치하는지, 각 후보의 유리·불리한 근거와 위험 특성이
동시에 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 검토 후보가 둘 이상인 추천 결과, **When** 사용자가 후보 비교를 열면, **Then** 각 후보의 전략
   버전·파라미터, 유사 구간별 F3 공통 지표, 종합 평가 값과 순위가 같은 정의·단위로 나란히 표시된다.
2. **Given** 후보 하나, **When** 추천 이유를 펼치면, **Then** 어떤 유사 구간과 성과·위험 지표가 후보
   순위에 얼마나 기여했는지와 가장 불리했던 근거를 확인할 수 있다.
3. **Given** 수익 지표는 우수하지만 위험 지표는 불리한 후보, **When** 사용자가 비교하면, **Then** 두
   특성이 모두 표시되고 높은 수익만으로 안전하거나 적합하다고 표현되지 않는다.
4. **Given** 같은 평가 기준 값을 가진 후보들, **When** 사용자가 순위를 확인하면, **Then** 해당 후보들은
   같은 순위로 표시되고 임의의 우열이 부여되지 않는다.
5. **Given** 후보의 구간별 지표나 유사성 근거, **When** 사용자가 원본을 확인하면, **Then** 출처 F7 검색과
   F1·F3 백테스트 실행·결과를 식별해 같은 값을 대조할 수 있다.

### User Story 3 - 추천 시점·데이터와 한계 추적 (Priority: P3)

사용자는 추천이 어느 시점에 어떤 정보만을 사용해 만들어졌는지 확인한다. 과거 시점의 추천은 그 시점까지
이용 가능했던 유사 시장, 백테스트 입력 데이터 및 추천 기준만 사용하며 이후 시장 성과는 섞이지 않는다.
추천 기록은 입력과 결과가 고정되어 반복 조회해도 같고, 결과는 투자 자문이나 미래 수익 보장이 아닌
추가 검토가 필요한 전략 후보로 설명된다.

**Why this priority**: 사후 정보를 사용한 추천은 실제 당시 가능한 판단을 재현하지 못한다. 시점 일관성과
불변 기록, 명확한 한계 고지가 있어야 추천의 설명과 검증을 신뢰할 수 있다.

**Independent Test**: 과거 기준 시점 뒤에 발표·수정된 데이터와 성과를 준비한 뒤 과거 시점 추천을
생성한다. 이후 정보가 입력·순위·근거에 포함되지 않는지, 같은 버전과 기준으로 반복 생성했을 때 결과가
같은지, 보장·투자 지시 문구가 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 과거 시점을 기준으로 한 추천, **When** 추천 근거를 확인하면, **Then** 근거 유사 구간은 모두
   추천 기준 시점 전에 끝나고 각 입력은 그 시점까지 이용 가능했던 데이터 기준을 가진다.
2. **Given** 추천 기준 시점 뒤에 공개되거나 수정된 데이터와 시장 성과, **When** 과거 추천을 생성하면,
   **Then** 이후 정보는 후보 선정, 점수, 순위 또는 설명에 사용되지 않는다.
3. **Given** 동일한 기준 시장, 유사 검색, 후보 집합, 백테스트 결과, 데이터·지표·추천 정의 버전, **When**
   추천을 다시 생성하면, **Then** 후보 목록, 평가 값, 근거와 순위가 동일하다.
4. **Given** 추천 결과, **When** 사용자가 안내를 읽으면, **Then** 결과가 제한된 과거 유사 사례에서 검토할
   후보임과 미래 수익을 예측·보장하지 않고 실제 투자 자문이 아님이 표시된다.
5. **Given** 추천 정의나 원천 데이터가 개정된 뒤, **When** 사용자가 기존 추천을 다시 열면, **Then** 기존
   입력·결과는 바뀌지 않고 당시 사용 버전과 새 버전을 구분할 수 있다.

### User Story 4 - 미사용 미래 구간에서 추천 과정 검증 (Priority: P4)

사용자는 추천 결과가 만들어질 때 전혀 사용하지 않은 이후 구간을 검증 구간으로 예약한다. 추천 후보,
전체 평가 대상, 검증 기간, 비교 기준과 평가 방법은 구간 결과를 보기 전에 고정된다. 검증 구간이 완결된
뒤 원래 후보를 변경 없이 같은 조건으로 평가하고, 추천 후보가 당시 전체 평가 대상 및 사전 정의된 기준과
비교해 어떤 성과를 보였는지 확인한다. 같은 추천 정의의 여러 기록을 모아 추천 과정의 반복 성능도 확인할
수 있다.

**Why this priority**: 설명이 그럴듯해도 추천 과정이 실제로 유용한 후보를 앞세우는지는 추천에 쓰지 않은
데이터에서 별도로 확인해야 한다. 사전 고정된 검증 계획은 결과를 본 뒤 기준을 바꾸는 일을 막는다.

**Independent Test**: 추천 생성 시 미래 검증 구간, 전체 후보 집합, 추천 상위 후보, 검증 지표와 비교
기준을 고정한다. 기간이 끝나기 전에는 성과가 표시되지 않고, 완결 후 원래 구성 그대로 평가되며, 추천
후보와 전체 후보·기준의 차이가 사전 정의대로 계산되고 원본 추천은 변하지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 추천 결과를 생성하는 사용자, **When** 미래 검증 계획을 확인하면, **Then** 추천 기준 시점보다
   뒤의 검증 구간, 동결된 전체 후보와 추천 후보, 공통 조건, 평가 지표, 비교 기준 및 평가 규칙이 결과를
   보기 전에 저장된다.
2. **Given** 검증 구간 데이터가 아직 완결되지 않은 상태, **When** 사용자가 검증 결과를 확인하면, **Then**
   평가 가능 예정일과 대기 상태만 표시되고 부분 성과나 중간 판정은 제공되지 않는다.
3. **Given** 검증 구간이 완결된 상태, **When** 추천 검증을 수행하면, **Then** 원래 전체 후보를 전략 버전·
   파라미터와 공통 조건 변경 없이 같은 미래 구간에서 평가하고 추천 후보와 전체 후보·사전 기준의 성과
   차이를 제공한다.
4. **Given** 완료된 검증, **When** 사용자가 원본 추천을 열면, **Then** 검증 결과는 원래 후보 목록, 점수,
   순위와 근거를 변경하지 않고 별도 검증 결과로 표시된다.
5. **Given** 같은 추천 정의 버전으로 생성되고 독립 검증이 완료된 기록이 여러 개, **When** 사용자가 과정
   성능을 확인하면, **Then** 포함 기록 수, 기준 시점·검증 구간과 사전 정의된 집계 지표별 결과를 확인할 수 있다.

---

### Edge Cases

- 완료되지 않았거나 요청자가 조회할 수 없는 F7 검색은 추천 근거로 사용할 수 없다.
- 과거 기준 시점 이후에 끝난 유사 구간이나 그 시점 뒤에 이용 가능해진 데이터·추천 기준이 포함되면 과거
  추천을 생성하지 않고 위반된 근거를 표시한다.
- 유사 구간이 하나뿐이면 추천은 생성할 수 있으나 근거가 단일 사례에 한정됨을 눈에 띄게 표시한다. 유사
  구간이 하나도 없으면 추천을 생성하지 않는다.
- 후보는 선택한 모든 유사 구간에서 성공 완료된 실제 백테스트를 가져야 한다. 하나라도 누락·실패하거나
  공통 조건·지표 정의가 다르면 해당 후보를 제외하고 이유를 표시한다.
- 제외 후 비교 가능한 후보가 한 개뿐이거나 없으면 순위와 추천 후보를 만들지 않고 근거 부족을 안내한다.
- 여러 유사 구간이 크게 겹치면 동일 시장 사례가 반복 반영될 수 있으므로, 추천 정의가 중첩 처리 규칙을
  명시하고 결과에 실제 반영 비중과 중첩 정보를 표시한다.
- 필수 평가 지표가 어느 구간에서 계산 불가인 후보는 추천 순위에서 제외한다. 순위에 필요하지 않은 지표는
  계산 불가와 이유를 표시하고 나머지 비교를 제공한다.
- 모든 평가 기준 값이 같은 후보는 같은 순위로 표시한다. 제시 개수의 경계에서 동률이면 동률 후보를 모두
  표시하고 요청한 최대 개수를 넘은 이유를 알린다.
- 전략이나 지표·추천 정의가 개정되어도 기존 추천은 원래 버전을 유지한다. 원래 버전과 데이터 기준을 더
  이상 재현할 수 없으면 새 추천을 만들지 않고 이유를 표시한다.
- 추천 검증 구간이 아직 끝나지 않았거나 필수 데이터가 일부만 존재하면 부분 결과를 제공하지 않는다.
- 검증 계획을 정한 뒤 후보, 기간, 평가 지표 또는 비교 기준을 바꾸려면 새 검증 계획을 만들며 기존 계획과
  추천 기록은 변경하지 않는다.
- 검증 구간 결과를 본 뒤 같은 추천 정의를 조정하면 조정된 정의는 새 버전이 되고, 이미 본 구간은 새 버전의
  독립 검증 구간으로 재사용할 수 없다.
- 검증 중 일부 후보 백테스트가 실패하면 성공 후보만으로 추천 과정이 우수하다고 판정하지 않고 검증을
  불완전으로 표시하며 실패 후보와 이유를 제공한다.
- 같은 추천을 반복 조회하거나 같은 생성 요청이 재전달되어도 중복 추천·근거·검증 계획을 만들지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 추천은 요청자가 조회할 수 있는 완료된 유사 시장 검색(F7)을 출처로 해야 하며, 기준 시장
  상황과 추천 정보 기준 시점을 그대로 가져와야 한다.
- **FR-002**: 추천 근거에 사용하는 유사 시장 구간은 출처 F7 검색의 결과여야 하고 추천 기준 시점 전에
  끝나야 한다. 사용자는 사용할 구간과 각 구간의 유사성 점수·근거·중첩 정보를 확인할 수 있어야 한다.
- **FR-003**: 추천의 평가 대상 단위는 전략 이름만이 아니라 전략 버전과 그 평가에 사용된 전체 파라미터
  값의 조합이어야 한다. 같은 전략의 다른 버전이나 파라미터 조합은 서로 다른 후보로 구분해야 한다.
- **FR-004**: 각 평가 대상 후보는 선택된 모든 유사 구간에서 성공 완료된 실제 백테스트 실행(F1)과 결과
  분석(F3)을 가져야 한다. 추정값이나 백테스트가 없는 성과를 실제 결과처럼 사용해서는 안 된다.
- **FR-005**: 동일 유사 구간의 후보 백테스트는 대상 종목, 초기 자산, 기간 외 공통 조건, 시장 데이터 기준
  및 지표 정의 버전이 같아야 한다. 서로 다른 기준의 결과를 같은 추천 순위에 섞어서는 안 된다.
- **FR-006**: 필수 결과가 누락·실패했거나 FR-005의 비교 조건을 충족하지 않는 후보는 평가에서 제외하고,
  후보별 누락 구간 또는 불일치 항목을 사용자에게 제공해야 한다. 비교 가능한 후보가 둘 미만이면 추천을
  생성해서는 안 된다.
- **FR-007**: 모든 추천은 버전이 있는 추천 정의를 사용해야 한다. 정의에는 유사 구간의 선택·중첩·반영
  방식, 사용하는 F3 성과·위험 지표, 지표의 중요도와 후보별 값을 종합하는 규칙, 필수 지표의 계산 불가
  처리, 순위·동률 처리, 최대 제시 수 및 후보 제외 규칙이 포함되어야 한다.
- **FR-008**: 추천 정의와 결과는 사용자가 이해할 수 있는 용어로 열람 가능해야 하며, 구체적인 추천 모델이나
  구현 기술을 공개하지 않더라도 동일 입력에서 후보별 점수와 순위가 나온 이유를 검증할 수 있어야 한다.
- **FR-009**: 추천 생성 전 시스템은 기준 시장 상황, 정보 기준 시점, 출처 F7 검색과 선택 유사 구간,
  전체 평가 대상과 제외 후보, 공통 백테스트 조건, 데이터·지표·추천 정의 버전 및 최대 제시 수를 사용자에게
  보여주고 확인을 받아야 한다.
- **FR-010**: 과거 시점 추천의 유사 시장, 백테스트 시장 데이터, 지표 정의 및 추천 기준을 정하거나 보정하는
  데 사용된 모든 정보는 추천 기준 시점까지 이용 가능했던 것이어야 한다. 이후 시장 움직임, 수정 데이터,
  사건 결과 또는 검증 구간 성과가 후보 선정·점수·순위·설명에 사용되어서는 안 된다.
- **FR-011**: 추천에 사용된 각 유사성 근거, 백테스트 결과 및 추천 기준 정보는 이용 가능 시점과 데이터
  기준을 확인할 수 있어야 한다. 당시 기준을 확인할 수 없는 자료는 과거 추천에 사용할 수 없다.
- **FR-012**: 시스템은 추천 정의에 따라 비교 가능한 전체 후보의 평가 값을 계산하고 순위를 제공하며,
  사용자가 지정한 최대 제시 수까지 상위 후보를 “검토 후보”로 표시해야 한다.
- **FR-013**: 모든 평가 기준 값이 같은 후보에는 같은 순위를 부여해야 한다. 제시 경계의 동률 후보는 모두
  표시하고 최대 제시 수를 넘은 이유를 제공해야 한다.
- **FR-014**: 각 검토 후보는 전략 버전과 전체 파라미터 값, 순위와 평가 값, 유사 구간별 F3 공통 지표,
  구간 전체의 성과·위험 요약 및 구간별 편차를 제공해야 한다.
- **FR-015**: 각 후보의 추천 설명은 순위에 가장 크게 기여한 유사 구간과 성과·위험 지표뿐 아니라 가장
  불리했던 구간·지표와 추천 정의가 다루지 않은 한계를 함께 제공해야 한다.
- **FR-016**: 후보별 유사 구간 지표는 원본 F3 결과와 같은 정의·단위·값이어야 하고, 종합 평가 값은
  공개된 추천 정의의 구간 반영 방식과 지표 종합 규칙에 따라 재계산 가능해야 한다.
- **FR-017**: 결과에는 출처 F7 검색, 각 유사 구간과 유사성 정의 버전, 후보별 F1 실행과 F3 결과, 공통
  조건, 시장 데이터 기준, 지표 정의 버전, 추천 정의 버전 및 추천 정보 기준 시점이 함께 제공되어야 한다.
- **FR-018**: 완료된 추천은 고유 식별자를 가져야 하며 입력, 전체 평가 후보와 제외 사유, 검토 후보 목록,
  평가 값, 순위와 설명을 보존해야 한다. 완료된 기록을 반복 조회해도 값이 달라져서는 안 되며, 같은 추천
  생성 요청의 재전달·재시도는 중복 추천이나 중복 근거를 만들지 않아야 한다.
- **FR-019**: 동일한 기준 시장, 출처 유사 검색, 유사 구간, 전체 후보와 원본 백테스트 결과, 데이터·지표·
  추천 정의 버전 및 입력 옵션으로 추천을 다시 생성하면 후보 목록, 평가 값, 근거와 순위가 동일해야 한다.
- **FR-020**: 데이터, 원본 결과 또는 추천 정의가 개정된 뒤 새 추천을 만들면 새 버전을 명시해야 하며,
  기존 추천의 입력·결과·근거를 소급 변경해서는 안 된다.
- **FR-021**: 추천 결과에는 후보가 제한된 과거 유사 구간과 평가 기준에서 추가 검토할 대상일 뿐 미래
  수익이나 현재 시장 적합성을 예측·보장하지 않고 실제 투자 자문이 아니라는 고지를 항상 표시해야 한다.
- **FR-022**: 시스템은 추천 결과로 자동 주문을 실행하거나 포트폴리오를 자동 구성해서는 안 된다.
- **FR-023**: 추천을 생성할 때 시스템은 추천에 사용하지 않을 검증 구간, 동결된 전체 평가 후보와 검토
  후보, 공통 조건, 평가 지표, 비교 기준, 결과 집계 규칙을 포함한 미래 검증 계획을 결과와 별도로 저장할
  수 있어야 한다.
- **FR-024**: 검증 구간은 추천 정보 기준 시점보다 뒤에 있고 추천에 사용된 어떤 구간과도 겹치지 않아야
  한다. 해당 구간의 시장 데이터와 성과는 원래 추천의 후보 선정, 점수, 순위 또는 설명에 사용되어서는 안 된다.
- **FR-025**: 미래 검증 계획은 검증 구간의 결과를 보기 전에 확정되어야 하며, 확정 후 후보, 전략 버전,
  파라미터, 기간, 공통 조건, 평가 지표, 비교 기준과 집계 규칙을 변경할 수 없어야 한다. 변경하려면 새
  계획을 만들고 기존 계획은 보존해야 한다.
- **FR-026**: 검증 구간의 필수 데이터가 완결되기 전에는 미래 검증 결과나 부분 성과를 제공해서는 안 되며,
  검증 가능 예정일과 대기 상태를 표시해야 한다.
- **FR-027**: 검증 구간이 완결되면 동결된 전체 후보를 전략 버전·파라미터와 공통 조건 변경 없이 같은
  구간에서 백테스트해야 한다. 실행과 결과는 F1·F3을 따르며 모든 후보가 성공 완료되어야 추천 과정의
  검증 결과를 완료로 표시할 수 있다.
- **FR-028**: 추천 과정 검증은 원래 검토 후보의 검증 구간 성과를 동결된 전체 평가 후보와 사전 정의된
  비교 기준에 따라 비교해야 한다. 적용 지표, 후보별 결과, 추천 후보와 전체 후보·비교 기준의 차이,
  계산 불가 및 실패 상태를 제공해야 한다.
- **FR-029**: 미래 검증은 별도 식별자로 추적할 수 있어야 하며 최소한 데이터 대기, 실행 대기, 실행 중,
  완료, 불완전, 실패 상태를 구분해야 한다. 모든 후보 평가가 성공해야 완료가 되고, 일부 후보 평가가
  종결 실패하면 불완전과 이유를 표시해야 한다. 검증 자체가 더 진행될 수 없으면 실패와 이유를 표시해야
  한다. 상태 집합과 전이는 관련 파트가 공유하는 계약으로 관리하고, 같은 검증 실행 요청이나 작업의
  재전달·재시도는 중복 백테스트·결과·상태 변경을 만들지 않아야 한다. 검증 결과는 원래 추천의 후보 목록,
  평가 값, 순위와 설명을 변경해서는 안 된다.
- **FR-030**: 같은 추천 정의 버전의 독립 검증 완료 기록을 집계할 때 시스템은 포함·제외 기록 수와 이유,
  각 추천·검증 구간, 정의 버전 및 사전 정의된 과정 성능 지표별 값을 제공해야 한다. 검증 결과를 본 뒤
  정의가 바뀐 기록을 같은 버전 집계에 섞어서는 안 된다.
- **FR-031**: 추천 검증 결과를 본 뒤 추천 정의를 변경하면 새 버전으로 관리해야 하며, 이미 확인한 검증
  구간은 새 버전의 독립 검증 근거로 사용해서는 안 된다.
- **FR-032**: 추천 기록과 미래 검증 계획·결과는 추천을 요청한 사용자만 조회할 수 있어야 한다.
- **FR-033**: 이 기능은 유사 시장 결과와 실제 전략 성과를 결합한 검토 후보, 설명, 비교 및 독립 검증
  근거를 제공한다. 실제 투자 자문, 자동 주문, 유사 시장 탐색 알고리즘, 구체적인 추천 모델, 파라미터
  자동 생성, 포트폴리오 자동 구성과 분산 처리 기술 선택은 포함하지 않는다.

### Key Entities *(include if feature involves data)*

- **추천 기준 상황(Recommendation Context)**: F7 기준 시장 상황에서 이어진 추천의 기준. 현재 또는 과거
  시장 구간, 추천 정보 기준 시점, 출처 검색과 선택 유사 구간을 가진다.
- **전략 평가 후보(Strategy Evaluation Candidate)**: 비교 대상인 전략 버전과 전체 파라미터 값의 조합.
  선택된 각 유사 구간의 실제 백테스트 실행·결과와 포함 또는 제외 상태를 가진다.
- **추천 정의(Recommendation Definition)**: 후보를 평가하고 검토 후보를 정하는 버전된 계약. 유사 구간
  선택·중첩·반영 규칙, 성과·위험 지표와 중요도, 종합 규칙, 계산 불가·제외·순위·동률 규칙 및 제시 수를
  가진다.
- **후보 추천 근거(Candidate Recommendation Evidence)**: 특정 후보의 평가를 설명하는 자료. 유사 구간별
  F7 근거와 F1·F3 결과, 점수 기여, 유리·불리한 성과·위험 요인, 데이터 이용 가능 시점과 한계를 가진다.
- **전략 검토 후보(Strategy Review Candidate)**: 추천 정의에 따라 상위에 표시된 평가 후보. 순위, 종합
  평가 값, 구간별 성과, 위험 특성과 추천 설명을 가지며 투자 지시가 아니다.
- **전략 후보 추천(Strategy Candidate Recommendation)**: 완료된 추천 전체를 식별하는 불변 기록. 추천
  기준 상황, 전체 후보·제외 사유, 공통 조건과 버전, 검토 후보, 순위 및 설명을 가진다.
- **추천 미래 검증 계획(Recommendation Forward-Validation Plan)**: 추천에 사용하지 않은 이후 구간에서
  추천 과정을 평가하기 위해 결과 확인 전에 동결한 계획. 전체 후보·검토 후보, 구간, 조건, 지표, 비교
  기준과 집계 규칙을 가진다.
- **추천 과정 검증 결과(Recommendation Process Validation Result)**: 완결된 미래 구간에서 동결 후보를
  평가한 별도 기록. 후보별 F1·F3 결과, 추천 후보와 전체 후보·비교 기준의 차이, 상태와 실패 이유를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 제시된 전략 검토 후보의 100%가 선택된 모든 유사 구간에서 성공 완료된 실제 백테스트 결과를
  가지며, 누락·실패·비교 불가능 결과를 근거로 제시된 후보가 0건이다.
- **SC-002**: 과거 시점 추천에서 추천 기준 시점 뒤에 이용 가능해진 데이터, 사건 결과 또는 시장 성과가
  후보 선정·점수·순위·설명에 사용된 사례가 0건이다.
- **SC-003**: 추천 후보의 유사 구간별 지표와 원본 F3 결과가 불일치하거나, 종합 평가 값이 공개된 추천
  정의로 재계산되지 않는 사례가 0건이다.
- **SC-004**: 추천 결과의 100%에서 사용자는 기준 상황, 출처 F7 검색과 유사 구간, 후보별 백테스트,
  공통 조건, 데이터·지표·추천 정의 버전 및 정보 기준 시점을 추적할 수 있다.
- **SC-005**: 동일한 원본과 입력 버전으로 추천을 반복 생성하거나 완료 기록을 반복 조회했을 때 후보,
  평가 값, 근거 또는 순위가 달라지는 사례가 0건이다.
- **SC-006**: 유사 구간 5개와 비교 가능한 전략 후보 20개의 완료 결과를 사용하는 추천 생성 요청의 95%는
  사용자가 확인한 뒤 5초 이내에 검토 후보 목록과 제외 후보 사유를 제공한다.
- **SC-007**: 추천 결과에서 미래 수익 보장, 실제 투자 지시, 자동 주문 또는 자동 포트폴리오로 오해될 수
  있는 표현이나 행동이 노출된 사례가 0건이다.
- **SC-008**: 사용성 검증에서 대상 사용자의 80% 이상이 상위 후보 둘의 추천 근거가 된 유사 구간과 수익·
  위험 차이를 각각 설명하고 원본 결과를 5분 이내에 찾아 확인할 수 있다.
- **SC-009**: 미래 검증 결과의 100%에서 검증 계획이 해당 구간 결과 확인 전에 고정되었고, 원래 전체
  후보·검토 후보·조건·평가 기준이 변경 없이 적용되었음을 확인할 수 있다.
- **SC-010**: 미래 검증 결과가 원래 추천 후보, 평가 값, 순위 또는 설명을 변경한 사례가 0건이며, 완료된
  모든 검증에서 추천 후보와 전체 후보·사전 비교 기준의 성과 차이를 확인할 수 있다.

## Assumptions

- 대상 사용자는 인증된 Thorp 사용자다. 추천 및 검증 기록의 보존 기간은 연결된 F1·F7 기록보다
  짧지 않으며, 접근 권한은 요청자에게 한정한다.
- 이 기능에서 “추천”은 사용자가 추가 분석을 시작할 검토 후보를 좁혀 주는 뜻이다. 개인의 재무 상황,
  투자 목적이나 위험 감수 성향을 고려한 투자 자문 또는 적합성 판단이 아니다.
- 기준 시장 상황과 유사 구간은 F7이 결정하며, 이 기능은 유사성 점수나 구간을 다시 계산하지 않는다.
- 초기 범위의 전략 평가 근거는 F4 전략 비교 또는 동일 조건의 개별 F1 실행에서 나온 F3 결과다. F5의
  파라미터 후보를 사용할 수 있지만 이 기능이 새 전략·파라미터 조합을 생성하지는 않는다.
- 후보 비교에는 선택한 모든 유사 구간에서 동일한 전략 버전·파라미터 조합을 사용한다. 한 구간에서만
  파라미터가 다른 결과는 같은 후보의 근거로 합치지 않는다.
- 유사 구간이 하나인 추천은 허용하지만 단일 사례 근거임을 강조한다. 평가 후보는 비교 가능한 둘 이상이어야
  하며, 제시할 후보 수의 기본값은 3개이고 사용자는 지원 한도 안에서 바꿀 수 있다.
- 추천 정의는 하나 이상 제공될 수 있다. 구체적인 모델이나 알고리즘은 계획 단계에서 결정하지만, 입력
  범위, 구간·지표 반영 규칙, 제외 규칙과 결과 설명은 동일 입력의 재현과 사용자 검증이 가능해야 한다.
- 과거 시점 추천을 재구성할 때 추천 기준을 정하거나 보정하는 데 사용한 데이터의 이용 가능 시점도 기준
  시점 이전이어야 한다. 이를 입증할 수 없으면 독립적인 과거 추천으로 표시하지 않는다.
- 미래 검증은 추천 생성 시 함께 만들거나 나중에 만들 수 있지만, 검증 구간의 결과를 보기 전에 계획이
  동결된 경우만 독립 검증으로 인정한다. 이미 결과를 본 구간을 사용한 평가는 참고용 사후 분석으로만
  구분하며 추천 과정의 독립 검증 집계에 포함하지 않는다.
- 미래 검증의 평가 대상은 검토 후보뿐 아니라 원래 전체 평가 후보다. 그래야 추천 과정이 다른 후보보다
  유용한 후보를 앞세웠는지 같은 조건에서 비교할 수 있다.
- 추천 검증을 위한 백테스트 실행·추적과 성과지표는 F1·F3을 재사용한다. 실행을 분배하는 방식이나 처리
  기술은 이 명세에서 정하지 않는다.
- 후보를 사용자가 직접 골라 새 백테스트 조건으로 넘기는 기능은 기존 F2·F4 흐름을 사용한다. 추천만으로
  백테스트, 자동 주문 또는 포트폴리오 구성이 시작되지 않는다.

## Constitution Alignment

- **원칙 I·II (독립 실행과 추적성)**: 추천 생성은 완료된 결과를 사용한다. 미래 검증에서 필요한 백테스트는
  FR-027에 따라 F1의 독립 실행·상태·결과 추적을 따르며 추천 요청 과정에서 직접 계산하지 않는다.
- **원칙 III (실측 후 기술 도입)**: FR-008·FR-033은 특정 추천 모델과 분산 처리 기술을 요구하지 않는다.
  계획 단계에서 후보 20개·유사 구간 5개의 응답 목표와 미래 검증 부하를 측정해 필요한 구조를 결정한다.
- **원칙 IV (파트 경계 계약)**: F7 검색, F1·F3 결과, 추천 정의·근거와 미래 검증 계획·결과는 생산·소비
  파트가 공유하는 계약이다. 구체적 필드와 전달 형식은 계획 단계에서 문서화하고 호환성을 함께 관리한다.
- **원칙 V (결과 신뢰성)**: FR-004~FR-005와 FR-016이 실제 결과와 공통 기준의 비교 가능성을,
  FR-010~FR-011이 미래 정보 유입 금지를, FR-018~FR-020이 불변성과 재현성을, FR-023~FR-031이 추천에
  사용하지 않은 구간에서의 독립 검증을 요구한다.
- 원칙에서 벗어나는 요구사항은 없다.
