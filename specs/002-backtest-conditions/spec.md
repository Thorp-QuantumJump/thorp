# Feature Specification: 백테스트 조건 설정

**Feature Branch**: `002-backtest-conditions`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "F2. 백테스트 조건 설정 — Quantum Jump에서 사용자가 백테스트에 사용할 조건을 설정하는 기능을 정의한다. 동일한 전략이라도 적용할 시장, 기간, 자산 및 전략 파라미터에 따라 결과가 달라진다. 사용자가 자신이 검증하려는 조건을 명확하게 지정하고, 유효하지 않은 조건으로 잘못된 백테스트를 수행하지 않도록 해야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 전략 선택과 전략별 입력 조건 확인 (Priority: P1)

전략과 조건을 직접 설정해 과거 성과를 검증하려는 사용자가 백테스트에 사용할 전략을 하나
선택한다. 전략을 선택하면 그 전략이 요구하는 파라미터와 입력 조건(각 파라미터의 이름, 의미, 허용
범위, 필수 여부)이 명확하게 제시되어, 사용자는 무엇을 입력해야 하는지 추측하지 않는다.

**Why this priority**: 전략마다 사용할 수 있는 파라미터가 다르므로, 전략을 먼저 확정하지 않으면
나머지 조건을 정의할 수 없다. 전략별 입력 조건이 명확하다는 것이 이 기능의 핵심 정책이다.

**Independent Test**: 제공되는 전략 목록에서 전략을 하나 선택하고, 그 전략에 정의된 파라미터 목록과
각 파라미터의 허용 범위·필수 여부가 제시되는지 확인한다. 다른 전략을 선택하면 그 전략에 맞는
목록으로 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용 가능한 전략 목록, **When** 사용자가 전략을 선택하면, **Then** 그 전략이 허용하는
   파라미터 목록과 각 파라미터의 이름·의미·허용 범위·필수 여부가 제시된다.
2. **Given** 파라미터 구성이 다른 두 전략, **When** 사용자가 선택 전략을 바꾸면, **Then** 제시되는
   파라미터 목록이 새 전략의 정의로 바뀌고 이전 전략에만 있던 파라미터는 조건에서 제외된다.
3. **Given** 사용 가능하지 않은(제공 목록에 없는) 전략, **When** 사용자가 그 전략으로 조건을
   구성하려 하면, **Then** 지원하지 않는 전략임이 안내되고 조건이 유효하지 않은 것으로 판정된다.

---

### User Story 2 - 대상·기간·초기 자산 설정 (Priority: P2)

사용자는 선택한 전략을 적용할 백테스트 대상 자산(종목)을 하나 이상 선택하고, 기간(시작일, 종료일)과
초기 자산을 설정한다. 대상은 지원하는 시장에 실제로 존재하는 종목이어야 하고, 기간은 과거 데이터가
존재하는 범위 안에서만 설정할 수 있으며, 미래 데이터를 참조하게 되는 조건은 허용되지 않는다.

**Why this priority**: 전략 다음으로 결과를 결정하는 핵심 조건이며, 미래 데이터 참조 금지라는
헌장 원칙(V)이 사용자 입력 단계에서 처음 적용되는 지점이다.

**Independent Test**: 존재하는 종목과 존재하지 않는 종목, 유효한 기간과 무효한 기간(종료일이 시작일보다
앞서는 경우, 종료일이 데이터가 존재하는 마지막 일자 이후인 경우)을 각각 입력하여 유효한 조합만
통과하고 나머지는 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 선택된 전략, **When** 사용자가 지원 시장에 존재하는 종목을 하나 이상 선택하고 데이터가
   존재하는 범위 안의 시작일·종료일과 양의 초기 자산을 설정하면, **Then** 대상·기간·초기 자산이
   조건에 반영된다.
5. **Given** 존재하지 않는 종목이나 지원하지 않는 시장의 종목이 포함된 대상, **When** 사용자가 조건을
   확정하려 하면, **Then** 어떤 종목이 문제인지 특정하여 거부된다.
6. **Given** 같은 종목이 중복 선택된 대상, **When** 사용자가 조건을 확정하려 하면, **Then** 중복임을
   특정하여 거부된다.
2. **Given** 시작일보다 앞선 종료일, **When** 사용자가 조건을 확정하려 하면, **Then** 기간이 모순됨을
   이유로 거부된다.
3. **Given** 데이터가 존재하는 마지막 일자 이후의 종료일(오늘 이후 포함), **When** 사용자가 조건을
   확정하려 하면, **Then** 미래 데이터 참조 또는 데이터 없음을 이유로 거부된다.
4. **Given** 0 이하의 초기 자산, **When** 사용자가 조건을 확정하려 하면, **Then** 지원하지 않는 값을
   이유로 거부된다.

### User Story 3 - 전략 파라미터 설정 (Priority: P3)

사용자는 선택한 전략이 정의한 파라미터에 값을 입력한다. 각 값은 그 파라미터의 허용 범위 안에 있어야
하며, 필수 파라미터는 비워 둘 수 없다. 전략이 정의하지 않은 파라미터는 조건에 포함될 수 없다.

**Why this priority**: 전략과 대상·기간이 확정된 뒤에 의미가 있으며, 파라미터의 허용 범위는 전략
정의에서 파생되므로 US1에 의존한다.

**Independent Test**: 허용 범위 안의 값, 범위 밖의 값, 필수 파라미터 누락, 정의되지 않은 파라미터
추가를 각각 시도하여 첫 번째만 통과하고 나머지는 항목별 사유와 함께 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 전략의 파라미터 정의, **When** 사용자가 모든 필수 파라미터에 허용 범위 안의 값을
   입력하면, **Then** 파라미터 값이 조건에 반영된다.
2. **Given** 허용 범위 밖의 파라미터 값, **When** 사용자가 조건을 확정하려 하면, **Then** 어떤
   파라미터가 어떤 범위를 벗어났는지 특정하여 거부된다.
3. **Given** 필수 파라미터가 비어 있는 조건, **When** 사용자가 조건을 확정하려 하면, **Then** 누락된
   파라미터를 특정하여 거부된다.
4. **Given** 전략이 정의하지 않은 파라미터가 포함된 조건, **When** 사용자가 조건을 확정하려 하면,
   **Then** 지원하지 않는 파라미터임을 특정하여 거부된다.

---

### User Story 4 - 실행 전 조건 유효성 확인 (Priority: P4)

사용자는 조건을 모두 입력한 뒤 실행을 요청하기 전에 조건 전체가 유효한지 확인받는다. 유효하지
않으면 어떤 항목이 어떤 이유로 유효하지 않은지 한 번에 알 수 있고, 유효하면 그 조건이 재현 가능한
단위로 식별된다는 것을 확인할 수 있다.

**Why this priority**: 잘못된 조건으로 백테스트가 실행되는 것을 막는 최종 관문이며, 조건 간 상호
검증(전략의 요구 이력 대비 기간 길이 등)은 개별 항목이 모두 채워진 뒤에만 가능하다.

**Independent Test**: 여러 항목이 동시에 무효한 조건을 검증하여 모든 위반이 항목별 사유와 함께 한
번에 보고되는지 확인한다. 유효한 조건을 두 번 동일하게 입력하여 같은 조건으로 식별되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 모든 항목이 유효한 조건, **When** 사용자가 유효성 확인을 요청하면, **Then** 조건이
   유효함과 그 조건의 식별 정보가 제시된다.
2. **Given** 둘 이상의 항목이 무효한 조건, **When** 사용자가 유효성 확인을 요청하면, **Then** 모든
   위반이 항목별 사유와 함께 한 번에 보고되고 실행 요청은 허용되지 않는다.
3. **Given** 전략이 요구하는 최소 이력 기간보다 짧은 백테스트 기간, **When** 사용자가 유효성 확인을
   요청하면, **Then** 기간과 전략 파라미터가 모순됨을 이유로 거부된다.
4. **Given** 동일한 전략·대상·기간·파라미터·초기 자산으로 구성된 두 조건, **When** 각각 유효성
   확인을 요청하면, **Then** 두 조건은 같은 조건으로 식별된다.

---

### Edge Cases

- 시작일 또는 종료일이 비거래일(주말, 휴장일)인 경우: 조건 자체는 거부하지 않되, 기간 안에 거래일이
  하나도 없으면 기간이 비어 있음을 이유로 거부한다.
- 종료일이 데이터가 존재하는 마지막 일자와 같은 경우는 허용한다. 그보다 하루라도 뒤이면 거부한다.
- 전략 파라미터가 과거 이력을 요구하는 경우(예: 이동평균 기간), 시작일 이전에 그만큼의 데이터가
  존재하지 않으면 기간과 파라미터가 모순됨을 이유로 거부한다.
- 파라미터 값이 형식은 맞지만 미래 데이터 참조를 유발하는 값(예: 음수 지연, 미래 시점 참조)인
  경우 거부한다.
- 전략 정의가 갱신되어 파라미터 구성이 바뀐 뒤, 이전 정의로 작성된 조건은 새 정의로 재검증되며
  더 이상 유효하지 않으면 거부된다.
- 초기 자산이 형식상 숫자가 아니거나, 지원 범위를 벗어나는 매우 큰 값인 경우 지원하지 않는 값을
  이유로 거부한다.
- 대상이 비어 있거나(종목 0개), 존재하지 않는 종목이나 지원하지 않는 시장의 종목을 가리키는 경우
  거부한다.
- 선택한 종목이 백테스트 기간 안에 거래 데이터가 전혀 없는 경우(기간 종료 이전에 상장 폐지되었거나
  기간 시작 이후에 상장된 경우 포함)에는 기간과 대상이 모순됨을 이유로 거부한다. 기간의 일부에만
  데이터가 있는 종목의 처리는 실행 방식의 문제이므로 이 스펙에서 거부 사유로 삼지 않는다.
- 같은 종목이 대상에 두 번 이상 포함된 경우 중복을 이유로 거부한다. 종목의 나열 순서는 조건의
  동일성에 영향을 주지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 선택할 수 있는 전략의 목록을 제공해야 하며, 사용자는 그중 하나를
  백테스트 전략으로 선택할 수 있어야 한다.
- **FR-002**: 각 전략은 그 전략이 허용하는 파라미터의 정의(이름, 의미, 값의 종류, 허용 범위 또는
  선택지, 필수 여부)를 명확하게 가져야 하며, 사용자가 전략을 선택하면 이 정의가 제시되어야 한다.
- **FR-003**: 사용자는 백테스트 대상 자산(종목)을 하나 이상 선택하고, 기간(시작일·종료일)과 초기
  자산을 설정할 수 있어야 한다.
- **FR-004**: 사용자는 선택한 전략의 파라미터 정의에 따라 각 파라미터의 값을 설정할 수 있어야 한다.
- **FR-005**: 시스템은 백테스트 실행 요청 전에 조건 전체의 유효성을 확인할 수 있는 수단을 제공해야
  하며, 실행 요청 시에도 동일한 규칙으로 조건을 재검증해야 한다.
- **FR-006**: 유효하지 않은 조건은 실행 요청으로 이어질 수 없어야 한다. 검증에 통과한 조건만 실행
  요청의 입력이 될 수 있다.
- **FR-007**: 시스템은 다음 경우를 지원하지 않는 값으로 거부해야 한다: 제공 목록에 없는 전략, 비어
  있는 대상, 존재하지 않거나 지원하지 않는 시장에 속한 종목, 중복 선택된 종목, 허용 범위 밖의 파라미터
  값, 전략이 정의하지 않은 파라미터, 필수 파라미터의 누락, 0 이하이거나 형식이 맞지 않는 초기 자산.
- **FR-008**: 시스템은 다음 경우를 서로 모순되는 입력으로 거부해야 한다: 종료일이 시작일보다 앞선
  기간, 거래일이 하나도 없는 기간, 전략 파라미터가 요구하는 최소 이력보다 짧거나 시작일 이전 데이터가
  부족한 기간, 백테스트 기간 안에 거래 데이터가 전혀 없는 종목이 포함된 대상.
- **FR-009**: 시스템은 미래 데이터를 이용하게 되는 조건을 거부해야 한다. 종료일은 백테스트 데이터가
  존재하는 마지막 일자를 넘을 수 없고, 미래 시점 참조를 유발하는 파라미터 값은 허용되지 않는다.
  (헌장 원칙 V)
- **FR-010**: 검증 결과는 유효 여부와 함께, 무효인 경우 위반된 항목 각각에 대해 어떤 항목이 어떤
  이유로 거부되었는지를 사용자가 이해할 수 있게 제시해야 한다. 위반이 여럿이면 한 번에 모두 보고한다.
- **FR-011**: 검증에 통과한 조건은 전략(및 그 전략 정의의 버전), 대상, 기간, 모든 파라미터 값, 초기
  자산을 포함하는 하나의 조건 집합으로 확정되어야 한다.
- **FR-012**: 조건 집합은 동일한 조건을 동일한 것으로 식별할 수 있어야 한다. 같은 전략 버전·대상·
  기간·파라미터 값·초기 자산으로 구성된 두 조건은 같은 조건으로 판정되어야 하며, 어느 하나라도 다르면
  다른 조건으로 판정되어야 한다. (헌장 원칙 V, 재현성)
- **FR-013**: 조건 집합에 포함되는 전략 식별은 전략 로직의 특정 버전을 가리켜야 한다. 전략 정의가
  바뀌면 같은 입력값이라도 다른 조건으로 식별된다.
- **FR-014**: 백테스트 대상은 지원하는 시장에 존재하는 개별 자산(종목)의 집합이며, 종목은 하나
  이상이어야 한다. 시스템은 사용자가 선택할 수 있는 종목을 식별할 수 있어야 하고, 대상의 동일성은
  종목의 집합으로 판정하며 나열 순서는 영향을 주지 않는다.
- **FR-015**: 조건 집합의 식별은 사용자 입력값(전략 버전, 대상, 기간, 파라미터 값, 초기 자산)만으로
  한다. 사용된 시장 데이터의 기준(스냅샷 또는 버전)은 조건의 일부가 아니며, 실행 시점에 실제로
  사용된 데이터 기준은 실행 기록(F1)에 남겨 재현성 추적에 사용한다.

### Key Entities *(include if feature involves data)*

- **전략 정의(Strategy Definition)**: 사용자가 선택할 수 있는 전략 하나를 설명하는 정의. 전략 식별자와
  버전, 이름, 설명, 파라미터 정의 목록, 전략이 요구하는 최소 이력 기간을 가진다.
- **파라미터 정의(Parameter Definition)**: 전략 정의에 속하는 파라미터 하나의 명세. 이름, 의미, 값의
  종류, 허용 범위 또는 선택지, 필수 여부를 가진다.
- **대상 자산(Target Asset)**: 사용자가 선택할 수 있는 개별 종목. 종목 식별자, 이름, 소속 시장, 거래
  데이터가 존재하는 기간을 가진다. 조건 집합의 대상은 이 종목들의 집합(1개 이상, 중복 없음)이다.
- **백테스트 조건 집합(Backtest Condition Set)**: 사용자가 단일 백테스트를 위해 확정한 입력 전체.
  전략(버전 포함), 대상 자산 집합, 기간(시작일·종료일), 파라미터 값들, 초기 자산으로 구성되며, 이
  입력값만으로 동일성 판정이 가능한 식별 정보를 가진다. 사용된 데이터 기준은 포함하지 않는다. 검증에
  통과한 조건 집합만 실행 요청(F1)의 입력이 된다.
- **검증 결과(Validation Result)**: 조건 집합에 대한 검증의 산출물. 유효 여부와, 무효인 경우 위반
  항목 목록(항목, 위반 유형: 지원하지 않는 값·모순·미래 데이터 참조, 사유 설명)을 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 검증을 통과하지 않은 조건으로 백테스트 실행이 시작된 사례가 0건이다.
- **SC-002**: 종료일이 데이터 존재 마지막 일자를 넘거나 미래 시점을 참조하는 조건이 검증을 통과한
  사례가 0건이다.
- **SC-003**: 무효한 조건에 대한 검증 결과의 100%에서 사용자는 어떤 항목이 어떤 이유로 거부되었는지
  추가 문의 없이 특정할 수 있다.
- **SC-004**: 여러 항목이 동시에 무효한 조건에서, 사용자가 모든 위반을 알기까지 필요한 검증 시도 횟수는
  1회다.
- **SC-005**: 조건 유효성 확인 요청의 95%는 2초 이내에 결과를 돌려준다.
- **SC-006**: 동일한 입력으로 구성한 두 조건이 다른 조건으로 식별되거나, 다른 입력으로 구성한 두
  조건이 같은 조건으로 식별된 사례가 0건이다.
- **SC-007**: 전략을 선택한 사용자의 90% 이상이 그 전략의 파라미터 정의만 보고 추가 안내 없이 필수
  파라미터를 모두 채운다.

## Assumptions

- 이 스펙이 다루는 사용자 입력은 전략, 대상, 기간(시작일·종료일), 전략 파라미터, 초기 자산으로 한정한다.
  수수료, 슬리피지, 리밸런싱 주기, 벤치마크 등은 요청되지 않았으므로 포함하지 않으며, 필요해지면
  스펙 개정으로 추가한다.
- 초기 자산은 단일 통화의 양의 금액이다. 통화는 대상 시장의 기준 통화를 따른다.
- 기간은 일 단위(날짜)로 지정한다. 장중 시각 단위의 기간 설정은 범위 밖이다.
- 전략 정의(파라미터 목록, 허용 범위, 최소 이력 기간)는 전략을 제공하는 측이 관리하며 사용자가
  바꿀 수 없다. 이 스펙은 전략 정의가 "명확하게 존재해야 한다"는 요구만 하고 그 관리 방식은 정하지
  않는다.
- 파라미터 정의에 기본값이 포함될 수 있으나, 기본값은 입력 편의를 위한 것이며 추천 파라미터를
  의미하지 않는다. 기본값 제공 여부는 전략 정의가 정한다.
- "데이터가 존재하는 마지막 일자"는 시스템이 현재 보유한 시장 데이터를 기준으로 판정한다. 데이터의
  갱신 주기와 수집 방식은 범위 밖이다.
- 검증은 실행 요청 없이 독립적으로 요청할 수 있고, 실행 요청 시 동일 규칙으로 다시 수행된다. 두
  검증 사이에 전략 정의나 데이터 범위가 바뀌면 실행 요청 시점의 검증 결과가 우선한다.
- 검증을 통과한 조건 집합은 F1(백테스트 실행 및 결과 추적)의 실행 요청 입력이 된다. 실행 방식,
  상태·결과 조회는 F1이 다룬다.
- 같은 조건 집합으로 실행한 결과가 데이터 갱신 전후로 달라질 수 있다. 이 차이는 조건이 아니라 실행
  기록에 남는 데이터 기준으로 설명되며, F1이 "실행에 사용된 데이터 기준 기록"을 요구한다.
- 대상으로 선택할 수 있는 종목의 최대 개수는 이 스펙에서 정하지 않는다. 상한이 필요하면 지원하지
  않는 값의 한 종류로 검증 규칙에 추가한다.
- 지원하는 시장의 범위(현재 KRX)는 데이터 제공 범위가 정하며, 이 스펙은 "지원 시장에 존재하는
  종목"이라는 조건만 요구한다.
- 조건 집합의 저장 여부와 저장 구조, 조건 재사용(불러오기) 기능은 범위 밖이다.

## Constitution Alignment

- **원칙 IV (파트 경계 계약)**: 전략 정의와 조건 집합은 입력을 생산하는 쪽과 소비하는 쪽이 공유하는
  계약이 된다. 필드와 형식은 설계 단계에서 `docs/specs/`에 문서화한다.
- **원칙 V (결과 신뢰성)**: FR-009가 미래 데이터 참조 조건을 입력 단계에서 차단하고(look-ahead bias
  금지), FR-011~FR-013이 동일 조건의 식별 가능성을 요구한다(재현성). 재현에 필요한 나머지 요소인
  시장 데이터 기준은 FR-015에 따라 실행 기록(F1)이 보존한다. 비교 가능성은 결과 지표 스펙에서 다룬다.
- **원칙 I·II**: 이 스펙은 실행 방식을 다루지 않으므로 직접 관련되지 않는다. 검증은 실행 요청 전에
  완료되어야 하며, 장시간 계산을 수반하지 않는다.
- **원칙 III**: 새 인프라나 의존성을 요구하지 않는다.
- 원칙에서 벗어나는 요구사항은 없다.
