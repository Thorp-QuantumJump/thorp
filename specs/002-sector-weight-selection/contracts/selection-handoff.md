# Contract: 섹터·비중 선택 값의 보관과 인계

**근거**: [spec.md](../spec.md) FR-012·FR-013·FR-014, [plan.md](../plan.md), [research.md](../research.md) 결정 1·3·9

002가 소유하는 유일한 계약이다. 서버 API가 아니라 **화면 사이의 계약**이며, 같은 브라우저 탭 안에서 002가 만든 값을 [003](../../003-strategy-settings/spec.md)이 이어받고 [013](../../013-learning-pages/spec.md)이 002로 값을 밀어 넣는 두 방향을 정의한다.

서버 쪽 계약인 `GET /sectors`와 `GET /sectors/{code}/instrument-profile`은 [001이 소유](../../001-etf-market-data/contracts/sector-api.md)한다. 002는 그 계약을 다시 정의하지 않는다.

## 값 표현 규칙

**비중은 0.1%p 단위 정수다.** `1000`이 100%이고 `334`가 33.4%다. 이 계약을 지나는 모든 비중 값이 정수이며, 소수나 문자열로 싣지 않는다. 까닭은 [research.md](../research.md) 결정 1에 있다. 합계 판정은 `sum === 1000`이라는 정수 비교이므로, 값을 소수로 바꿔 실어 보내면 받는 쪽에서 판정이 흔들린다.

## 1. 탭 세션 보관 (002 → 002, 002 → 003)

**저장소**: `sessionStorage`
**키**: `thorp.diagnosis.sectorSelection`

```json
{
  "version": 1,
  "mapVersion": "SEM-2026-09-10-001",
  "selected": [
    { "code": "SEMICONDUCTOR", "weightTenths": 334 },
    { "code": "BATTERY", "weightTenths": 333 },
    { "code": "SHIPBUILDING", "weightTenths": 333 }
  ],
  "weightsTouched": false
}
```

| 필드 | 뜻 | 근거 |
|---|---|---|
| `version` | 이 페이로드 형식의 번호. 형식을 바꾸면 올린다 | 아래 「형식이 바뀔 때」 |
| `mapVersion` | 값을 만들 당시의 대응표 버전 | FR-003, 원칙 VIII |
| `selected` | 선택 섹터와 비중. 002의 표시 순서로 정렬되어 있다 | FR-004, FR-005 |
| `weightsTouched` | 사용자가 비중을 한 번이라도 고쳤는지 | FR-005, SC-009 |

**불변식**

1. `selected`의 `code`에 중복이 없다.
2. 모든 `weightTenths`가 `0 <= v <= 1000`인 정수다. 0은 유효한 값이다(FR-016).
3. `selected`의 합계가 1000이라는 보장은 **없다.** 합계가 맞지 않는 상태도 그대로 보관한다. 사용자가 입력을 마치지 못한 채 화면을 떠났다가 돌아오면 그 상태 그대로 보여야 하며, 저장 시점에 자동으로 맞추면 원칙 VI를 어긴다.
4. `selected`가 비어 있을 수 있다. 아무것도 고르지 않은 상태도 보관한다.

**읽는 쪽의 의무**

- 페이로드를 신뢰하지 않는다. `sessionStorage`는 사용자가 편집할 수 있다. 위 불변식을 모두 검사하고, 섹터 코드는 현재 `GET /sectors` 응답에 있는 코드만 받아들인다.
- 검사에서 빠진 항목이 있으면 조용히 버리지 않고 빠졌다는 사실을 한 문장으로 알린다(원칙 VI). 무엇을 제안할지는 [006 FR-008](../../006-my-records/spec.md)과 UI-01이 소유한다.
- 저장소 접근이 막힌 환경(프라이빗 모드 등)에서는 예외를 삼키고 메모리 상태로만 동작한다. 화면을 오류로 막지 않는다.

**003이 이어받는 방식**: 003은 같은 키를 읽는다. 002가 값을 URL이나 navigation state로 따로 실어 보내지 않는다. 새로고침으로 화면이 다시 뜨는 경우와 같은 경로를 쓰기 위해서다. 003이 필요로 하는 섹터 이름·대표 ETF 이름은 003이 `GET /sectors`로 직접 받는다. 이름을 이 페이로드에 실으면 대응표 버전이 바뀌었을 때 어느 쪽이 기준인지 흐려진다.

**형식이 바뀔 때**: `version`이 읽는 쪽이 아는 값보다 크면 그 페이로드를 쓰지 않고 빈 상태로 시작한다. 이때도 사용자에게 한 문장으로 알린다. 탭 세션 안의 값이라 오래된 형식이 남아 있을 창이 좁지만, 배포 중 열려 있던 탭에서는 생길 수 있다.

## 2. 배우기 예시 진입 (013 → 002)

**수단**: React Router의 navigation state. 013이 `/diagnosis/sectors`로 이동하면서 아래 값을 싣는다.

```json
{
  "sectorSelectionExample": {
    "source": "learning",
    "topicId": "equal-weight-basics",
    "selected": [
      { "code": "SEMICONDUCTOR", "weightTenths": 500 },
      { "code": "BATTERY", "weightTenths": 500 }
    ]
  }
}
```

| 필드 | 뜻 |
|---|---|
| `source` | 어디서 온 예시인지. 화면이 예시 표시를 붙이는 근거 |
| `topicId` | 어느 주제의 예시인지. 내용은 [013](../../013-learning-pages/spec.md)이 소유한다 |
| `selected` | 예시 섹터와 비중. 값 표현 규칙은 위와 같다 |

**002의 처리**

| 들어온 상태 | 동작 | 근거 |
|---|---|---|
| 아직 아무 섹터도 고르지 않았고 비중도 없다 | 묻지 않고 예시를 채운다 | FR-012, SC-011 |
| 이미 고른 섹터나 입력한 비중이 있다 | 덮어쓸지 먼저 묻는다. 거절하면 기존 값을 그대로 둔다 | FR-012, SC-011 |
| 예시에 현재 목록에 없는 코드가 있다 | 위 「읽는 쪽의 의무」와 같게 처리한다 | 원칙 VI |
| 예시 합계가 1000이 아니다 | 그대로 채우고 FR-007의 부족·초과 안내로 처리한다. 자동으로 맞추지 않는다 | 원칙 VI |

002는 예시를 한 번 읽고 소비한 뒤 navigation state를 `replace`로 지운다. 지우지 않으면 뒤로 가기나 새로고침 때 덮어쓰기 확인이 다시 뜬다.

**쿼리 문자열을 쓰지 않는다.** 비중이 담긴 링크는 공유되면 '추천 비중'처럼 읽힐 여지가 있고(원칙 III), 외부에서 값을 주입하는 경로가 열린다([research.md](../research.md) 결정 9).

## 3. 004 분석 요청과의 관계

FR-013은 사용자가 입력한 섹터·비중 원본이 분석 요청에 포함된다고 정한다. **그 요청을 만드는 것은 002가 아니라 [003](../../003-strategy-settings/spec.md)이다.** 003의 Key Entities가 "분석 요청 = 섹터·비중(002) + 전략 설정값 + 분석 조건 + 참조 버전"이라고 적어 두었다. 002는 위 1번 페이로드를 남기는 데까지만 책임진다. 비중을 백분율 소수로 바꿀지 정수로 보낼지는 004의 메시지 계약이 정하며, 002는 그 변환을 하지 않는다.
