# Feature Specification: 파라미터 탐색

**Feature Branch**: `005-parameter-exploration`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "F5. 파라미터 탐색 — Thorp에서 전략의 여러 파라미터 조합을 탐색하고 후보를 비교하는 기능을 정의한다. 사용자는 탐색할 전략과 파라미터 범위를 지정하고, 여러 조합의 탐색 진행·완료 여부를 확인하며, 동일 조건과 공통 평가 기준으로 결과를 비교해 우수한 후보를 확인할 수 있어야 한다. 탐색 데이터와 최종 검증 데이터를 구분하고, 결과를 미래 성과를 보장하는 최적값으로 표현하지 않는다. 구체적인 탐색 알고리즘, 병렬·분산 처리 구조, 최종 검증 실행은 범위에서 제외한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 탐색 범위와 평가 기준 설정 (Priority: P1)

전략의 파라미터 후보를 체계적으로 살펴보려는 사용자가 전략과 그 버전을 선택하고, 탐색할 파라미터별
범위와 고정할 파라미터 값을 정한다. 사용자는 모든 후보에 공통으로 적용할 대상 종목, 초기 자산,
탐색 데이터 기간을 설정하고, 탐색 결과를 판단할 주 평가 지표와 선택적인 동률 해소 지표를 정한다.
최종 검증용으로 예약할 데이터 범위는 탐색 데이터와 별도로 표시한다. 실행 전에는 확정된 후보 조합 수,
공통 조건, 데이터 역할, 평가 기준을 검토할 수 있다.

**Why this priority**: 비교할 후보와 공통 기준을 먼저 명확히 고정해야 이후 실행과 결과 순위가 같은
질문에 답한다. 탐색 데이터와 검증 데이터를 이 단계에서 분리해야 후보 선택 과정에 검증 데이터가
섞이는 일을 막을 수 있다.

**Independent Test**: 조정 가능한 파라미터가 둘 이상인 전략을 선택해 각 범위, 공통 조건, 서로 겹치지
않는 탐색·검증 데이터 범위, 주 평가 지표를 설정한다. 실행 전 요약에서 후보 수와 모든 설정이 정확히
표시되고, 범위 밖 후보나 검증 데이터가 평가 계획에 포함되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 파라미터 정의가 제공되는 전략, **When** 사용자가 하나 이상의 탐색 범위와 나머지 고정값,
   공통 조건, 탐색·검증 데이터 범위, 주 평가 지표를 유효하게 설정하면, **Then** 시스템은 실행될 유한한
   후보 조합 집합과 그 개수, 공통 조건, 데이터 역할, 평가 기준을 실행 전에 보여준다.
2. **Given** 실행 전 요약, **When** 사용자가 후보 조합을 확인하면, **Then** 모든 후보 값은 지정한 범위와
   전략의 파라미터 정의 안에 있고 중복 조합은 없으며, 후보마다 달라질 수 있는 것은 탐색 대상으로 지정한
   파라미터뿐이다.
3. **Given** 탐색 데이터와 검증 데이터가 겹치거나 시간 순서가 잘못된 설정, **When** 사용자가 탐색을
   요청하면, **Then** 어느 데이터 범위가 왜 잘못되었는지 안내되고 어떤 후보 실행도 시작되지 않는다.
4. **Given** 우수 방향이 정의되지 않은 공통 지표, **When** 사용자가 그 지표를 주 평가 기준으로 선택하려
   하면, **Then** 순위 기준으로 사용할 수 없다는 안내와 함께 선택이 거부된다.
5. **Given** 확정 후보가 한 개뿐인 설정, **When** 사용자가 탐색을 요청하면, **Then** 비교 가능한 후보가
   둘 이상이어야 한다는 안내와 함께 요청이 거부된다.

### User Story 2 - 다수 후보 실행과 진행 상황 추적 (Priority: P2)

사용자가 검토한 탐색을 시작하면 시스템은 탐색 식별자를 제공하고 각 후보 조합에 대해 백테스트를
수행한다. 사용자는 화면을 닫았다가 다시 돌아와도 전체 탐색의 상태와 계획·대기·실행·성공·실패 후보
수를 확인해 얼마나 진행되었고 언제 완료되었는지 알 수 있다.

**Why this priority**: 파라미터 탐색은 일반적으로 단일 백테스트보다 오래 걸리므로 요청과 독립적으로
진행되고 이후에도 추적 가능해야 사용자가 대량 실행을 신뢰하고 사용할 수 있다.

**Independent Test**: 후보 20개인 탐색을 시작해 식별자가 계산 완료 전에 제공되는지, 후보 상태 변화에
따라 집계 수가 맞게 갱신되는지, 연결 종료 후 같은 식별자로 다시 조회할 수 있는지, 모든 후보가 종결되면
탐색이 완료로 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 유효하고 사용자가 확인한 탐색 설정, **When** 사용자가 실행을 시작하면, **Then** 계산 완료를
   기다리지 않고 탐색 식별자가 제공되며 확정된 후보마다 하나의 백테스트 실행이 시작된다.
2. **Given** 진행 중인 탐색, **When** 사용자가 탐색 식별자로 상태를 확인하면, **Then** 전체 상태와 함께
   계획된 후보 수 및 대기·실행·성공·실패 후보 수를 확인할 수 있고 그 합계는 서로 모순되지 않는다.
3. **Given** 사용자가 탐색 시작 후 연결을 종료한 상태, **When** 나중에 같은 식별자로 다시 조회하면,
   **Then** 탐색은 중단되지 않았고 현재 진행 상태를 이어서 확인할 수 있다.
4. **Given** 탐색의 모든 후보 실행이 성공 또는 실패 상태에 도달한 상태, **When** 사용자가 진행 상황을
   확인하면, **Then** 탐색은 완료로 표시되며 성공·실패 후보 수가 함께 표시된다.
5. **Given** 같은 탐색 시작 요청이 재전달된 상황, **When** 시스템이 요청을 처리하면, **Then** 별도의
   탐색이나 중복 후보 실행을 만들지 않고 원래 탐색을 계속 추적한다.

### User Story 3 - 공통 기준으로 후보 비교 (Priority: P3)

탐색 후보가 완료되면 사용자는 성공한 각 조합의 파라미터 값과 F3의 공통 성과지표를 나란히 확인한다.
모든 결과는 같은 전략 버전, 공통 조건, 시장 데이터 기준 및 지표 정의 버전에서 나온다. 사용자는 주 평가
지표와 동률 해소 기준에 따른 순위를 보고 상위 후보들을 확인하며, 필요하면 다른 공통 지표로 정렬해
수익과 위험의 차이를 함께 살펴본다.

**Why this priority**: 실행 자체가 아니라 후보 차이를 공정하게 읽고 후속 검증 대상을 좁히는 것이 기능의
핵심 사용자 가치다.

**Independent Test**: 성공 후보와 실패 후보, 동률 후보, 계산 불가 지표가 섞인 완료 탐색을 열어 성공
후보의 값이 F3 단일 결과와 일치하고, 순위가 저장된 평가 기준대로 계산되며, 실패·계산 불가 후보가
오해를 부르지 않게 구분되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 성공한 후보가 둘 이상인 탐색, **When** 사용자가 결과를 열면, **Then** 각 후보의 전체
   파라미터 값과 F3 공통 지표가 같은 정의·단위로 나란히 표시되고 단일 결과 분석의 값과 일치한다.
2. **Given** 완료된 탐색 결과, **When** 사용자가 기본 순서를 확인하면, **Then** 후보는 실행 전에 저장된
   주 평가 지표와 동률 해소 지표 순서 및 각 지표의 우수 방향에 따라 정렬되고 적용 기준이 함께 표시된다.
3. **Given** 평가 기준 값이 모두 같은 후보들, **When** 사용자가 순위를 확인하면, **Then** 해당 후보들은
   같은 순위로 표시되고 임의의 우열이 부여되지 않는다.
4. **Given** 주 평가 지표를 계산할 수 없는 후보, **When** 사용자가 결과를 확인하면, **Then** 그 후보는
   순위 없음과 계산 불가 이유로 표시되며 숫자 대체값으로 순위에 포함되지 않는다.
5. **Given** 일부 후보 실행이 실패한 탐색, **When** 사용자가 결과를 확인하면, **Then** 성공 후보의
   비교는 제공되고 실패 후보는 순위에서 제외된 채 실패 상태와 이유가 표시된다.

### User Story 4 - 탐색 근거와 한계 확인 (Priority: P4)

사용자는 결과와 함께 실제 탐색 범위, 평가된 후보 조합, 공통 조건, 탐색에 사용된 데이터 기준, 예약된
최종 검증 데이터 범위 및 평가 기준을 다시 확인한다. 결과는 과거 탐색 데이터에서 상대적으로 우수했던
후보로 표현되며, 미래 성과를 보장하는 최적값이나 자동 추천으로 표현되지 않는다. 예약된 데이터로 실제
최종 검증을 수행하는 일은 별도 단계임을 알 수 있다.

**Why this priority**: 탐색 결과를 과최적화된 확정 답으로 오해하지 않게 하고, 재현 및 독립 검증에 필요한
근거를 남기는 신뢰 장치다.

**Independent Test**: 완료된 탐색을 열어 입력 범위와 실제 평가 조합, 데이터 역할과 기준, 지표 정의
버전이 모두 보이는지 확인한다. 결과 전체에서 “최적”, “보장”, “추천”처럼 미래 성과를 암시하는 표현이
없고 검증 데이터의 백테스트 결과가 생성되지 않았는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 완료된 탐색, **When** 사용자가 탐색 근거를 열면, **Then** 전략 버전, 원래 파라미터 범위,
   실제 평가된 전체 후보 조합, 공통 조건, 탐색 데이터 기준, 예약된 검증 데이터 범위, 평가 기준과 지표
   정의 버전을 확인할 수 있다.
2. **Given** 탐색 결과의 상위 후보, **When** 사용자가 후보 설명을 읽으면, **Then** 해당 후보는 지정된
   탐색 데이터와 평가 기준에서 상대적으로 앞선 후보로 표현되고 미래 성과를 보장하는 최적값·추천값으로
   표현되지 않는다.
3. **Given** 최종 검증용 데이터가 예약된 탐색, **When** 탐색 실행과 결과의 데이터 사용 내역을 확인하면,
   **Then** 모든 후보 평가는 탐색 데이터만 사용했고 검증 데이터는 사용되지 않았음을 확인할 수 있다.
4. **Given** 완료된 탐색, **When** 사용자가 예약된 검증 데이터의 결과를 찾으면, **Then** 이 기능에서는
   최종 검증을 실행하거나 그 성과를 제공하지 않으며 별도 검증 단계가 필요하다는 안내가 표시된다.

### Edge Cases

- 탐색 대상으로 지정한 파라미터가 없거나 범위에서 확정되는 고유 후보가 한 개뿐이면 비교가 성립하지
  않으므로 탐색을 시작하지 않는다.
- 파라미터 범위의 하한이 상한보다 크거나, 허용되지 않는 값 종류·간격·범주를 포함하거나, 파라미터 간
  제약을 어기는 후보가 생기면 어느 범위와 후보가 왜 유효하지 않은지 알리고 어떤 실행도 시작하지 않는다.
- 후보 조합 수가 시스템이 공개한 한도를 넘으면 실제 후보 실행을 만들지 않고 예상 조합 수와 지원 한도를
  안내한다. 한도의 값과 확장 방법은 계획 단계에서 부하 측정을 근거로 결정한다.
- 서로 다른 범위 정의가 같은 후보 조합을 만들면 실행 전 후보 집합에서 중복을 제거하고 실제 고유 후보
  수를 표시한다. 중복 제거 후 후보가 하나뿐이면 탐색을 시작하지 않는다.
- 탐색 데이터와 예약된 검증 데이터가 겹치거나 검증 데이터가 탐색 데이터보다 앞선 경우 입력을 거부한다.
  예약된 검증 데이터는 후보 생성, 지표 계산, 순위 결정에 사용하지 않는다.
- 탐색 시작 뒤 전략 또는 지표 정의가 개정되어도 진행 중인 탐색은 시작 시점에 고정된 전략 버전과 지표
  정의 버전을 유지한다.
- 여러 후보의 주 평가 지표 값이 같으면 저장된 동률 해소 지표를 순서대로 적용한다. 모든 기준이 같으면
  같은 순위로 표시한다.
- 거래가 없어 주 평가 지표를 계산할 수 없는 후보는 임의의 0이나 최하점으로 바꾸지 않고 순위 없음으로
  표시한다. 모든 성공 후보가 계산 불가이면 상위 후보를 표시하지 않는다.
- 일부 후보만 실패해도 성공 후보의 비교 결과는 제공한다. 모든 후보가 실패하면 비교 가능한 후보가 없음을
  명시하고 각 실패 이유를 제공한다.
- 탐색 시작 뒤 파라미터 범위, 공통 조건, 데이터 역할 또는 평가 기준을 바꾸려면 기존 기록을 수정하지
  않고 새 탐색으로 시작한다.
- 사용자가 결과를 반복 조회하거나 탐색 시작 요청이 중복 전달되어도 후보 집합, 후보별 결과, 집계 상태와
  순위가 중복되거나 달라지지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 탐색할 전략을 하나 선택할 수 있어야 하며, 탐색은 해당 전략 정의의 특정 버전을
  가리켜야 한다.
- **FR-002**: 사용자는 전략이 제공하는 파라미터 정의(F2)에 따라 하나 이상의 파라미터에 탐색 범위를,
  나머지 필수 파라미터에 고정값을 지정할 수 있어야 한다. 범위는 값 종류에 맞는 유한 후보 목록 또는
  경계와 허용 간격으로 표현할 수 있어야 한다.
- **FR-003**: 시스템은 탐색 실행 전에 범위로부터 실행 단위가 되는 유한한 후보 조합 집합을 확정해야 한다.
  모든 후보는 지정 범위와 전략의 파라미터 정의를 만족해야 하고 서로 중복되지 않아야 하며, 후보 집합을
  범위에서 선택하는 구체적인 탐색 알고리즘은 이 명세에서 규정하지 않는다.
- **FR-004**: 사용자는 모든 후보에 공통으로 적용할 대상 종목, 초기 자산 및 탐색 데이터 기간을 지정할 수
  있어야 한다. 후보별로 달라질 수 있는 것은 탐색 대상으로 지정한 파라미터 값뿐이다.
- **FR-005**: 사용자는 탐색 데이터와 별개로 최종 검증용으로 예약할 데이터 범위를 지정할 수 있어야 한다.
  두 범위는 겹치지 않아야 하고 검증 데이터는 시간상 탐색 데이터 뒤에 있어야 한다.
- **FR-006**: 시스템은 탐색 데이터만 후보의 백테스트, 지표 계산 및 순위 결정에 사용해야 하며, 예약된
  최종 검증 데이터에 대한 백테스트나 성과 평가는 이 기능에서 수행해서는 안 된다.
- **FR-007**: 사용자는 F3 공통 지표 중 우수 방향이 정의된 지표 하나를 주 평가 기준으로 선택해야 하며,
  우수 방향이 정의된 지표를 동률 해소 기준으로 우선순위와 함께 추가 선택할 수 있어야 한다.
- **FR-008**: 탐색 시작 전 시스템은 전략 버전, 파라미터 범위와 고정값, 확정 후보 수, 공통 조건, 탐색·
  검증 데이터 역할, 주 평가 지표와 동률 해소 기준을 사용자에게 보여주고 확인을 받아야 한다.
- **FR-009**: 파라미터 범위, 각 후보의 전체 조건, 데이터 범위 및 평가 기준은 F2와 각 지표 정의의 검증을
  통과해야 한다. 하나라도 유효하지 않거나 고유 후보가 둘 미만이면 탐색은 거부되고 어떤 백테스트도
  시작되지 않아야 한다.
- **FR-010**: 확정 후보 수가 시스템이 공개한 지원 한도를 넘으면 탐색은 거부되어야 하며, 사용자에게
  후보 수와 지원 한도 및 범위를 줄여야 한다는 이유가 제공되어야 한다. 최초 지원 한도는 후보 1,000개
  이상이어야 하며, 그보다 큰 한도는 부하 측정을 근거로 계획 단계에서 정한다.
- **FR-011**: 수락된 탐색은 고유 식별자를 가져야 하며, 사용자는 그 식별자로 요청 생명주기와 독립적으로
  진행 상태와 결과를 이후에도 추적할 수 있어야 한다.
- **FR-012**: 탐색 요청이 수락되면 확정된 고유 후보마다 하나의 새 백테스트 실행(F1)이 시작되어야 한다.
  같은 탐색 요청 또는 후보 작업의 재전달·재시도는 중복 탐색, 중복 실행, 중복 결과 또는 중복 상태 변경을
  만들지 않아야 한다.
- **FR-013**: 탐색 안의 모든 후보 백테스트는 같은 전략 버전, 대상 종목, 초기 자산, 탐색 기간, 시장 데이터
  기준(F1 FR-018), 공통 조건 및 지표 정의 버전을 사용해야 한다.
- **FR-014**: 시스템은 탐색 전체에 대해 최소한 실행 대기, 실행 중, 완료, 실패 상태를 구분하고, 계획된
  후보 수 및 대기·실행·성공·실패 후보 수를 제공해야 한다. 후보 상태별 수의 합은 계획된 후보 수와
  항상 같아야 한다. 모든 후보가 F1의 성공 완료 또는 실패 상태가 되면 성공 후보가 없더라도 탐색은
  완료로 표시되어야 하며, 탐색 자체가 더 진행될 수 없어 실패한 경우에는 그 이유가 제공되어야 한다.
- **FR-015**: 탐색 진행 중 클라이언트 연결이 종료되어도 실행은 계속되어야 하며, 사용자는 나중에 같은
  탐색 식별자로 최신 진행 상태와 결과를 조회할 수 있어야 한다.
- **FR-016**: 탐색 결과는 성공한 각 후보의 전체 파라미터 값과 F3 공통 지표 집합을 같은 정의·계산 기준·
  단위로 나란히 제공해야 하며, 각 값은 해당 후보의 단일 결과 분석과 일치해야 한다.
- **FR-017**: 시스템은 성공 후보를 시작 전에 저장된 주 평가 지표, 동률 해소 지표의 우선순위 및 각 지표
  정의의 우수 방향에 따라 정렬하고 순위를 제공해야 한다. 모든 적용 기준 값이 같은 후보에는 같은 순위를
  부여해야 한다.
- **FR-018**: 주 평가 지표를 계산할 수 없는 후보와 실패 후보는 순위에서 제외하되 결과 목록에서 제거하지
  않아야 한다. 계산 불가 또는 실패 상태와 이유를 명시하고, 성공한 다른 후보의 비교는 계속 제공해야 한다.
- **FR-019**: 결과에는 상위 순위 후보가 강조되어야 하지만, 이를 “최적 파라미터”, “추천 파라미터” 또는
  미래 성과를 보장하는 값으로 표현해서는 안 된다. 결과가 특정 과거 탐색 데이터와 선택한 평가 기준에
  따른 상대 비교임을 항상 함께 고지해야 한다.
- **FR-020**: 탐색 결과에는 입력한 파라미터 범위, 실제 평가된 전체 후보 조합, 공통 조건, 사용한 탐색
  데이터 기준, 예약된 검증 데이터 범위, 평가 기준, 전략 버전 및 지표 정의 버전이 함께 제공되어야 한다.
- **FR-021**: 시작된 탐색의 후보 집합, 공통 조건, 데이터 역할 및 평가 기준은 변경할 수 없어야 한다.
  사용자가 이 설정을 바꾸려면 새 탐색을 시작해야 한다.
- **FR-022**: 같은 탐색을 반복 조회할 때 후보 집합, 후보별 결과, 집계 상태 및 완료 시점의 순위는 동일해야
  한다. 후보 결과는 동일한 전략·파라미터·조건·데이터 기준에서 재현 가능해야 한다.
- **FR-023**: 탐색과 그 후보 실행의 접근 범위는 F1의 정책을 따라야 하며, 탐색을 요청한 사용자만 진행
  상태, 설정 및 결과를 조회할 수 있어야 한다.
- **FR-024**: 이 기능은 파라미터 범위 정의, 후보 조합 실행, 진행 추적, 결과 비교와 상위 후보 확인까지만
  제공한다. 구체적인 탐색 알고리즘, 실행을 병렬·분산하는 구조와 작업 주체 수, 대규모 처리 기술 선택,
  예약된 데이터에서의 최종 검증, 유사 시장 기반 탐색 및 자동 매매는 포함하지 않는다.

### Key Entities *(include if feature involves data)*

- **탐색 정의(Exploration Definition)**: 사용자가 실행 전에 확정한 탐색의 입력. 전략과 버전, 파라미터별
  범위 또는 고정값, 공통 조건, 탐색 데이터 범위, 예약된 검증 데이터 범위, 평가 기준을 가진다.
- **파라미터 범위(Parameter Range)**: 특정 전략 파라미터에 허용한 후보 영역. 파라미터 정의를 가리키며
  유한 값 목록 또는 경계와 허용 간격 및 고정 여부를 가진다.
- **후보 조합(Candidate Combination)**: 탐색에서 평가할 전략 파라미터 값의 완전한 한 세트. 탐색 정의
  하나에 속하고 동일 탐색 안에서 유일하며, 후보 백테스트 실행 하나와 대응한다.
- **데이터 역할 구분(Data Role Assignment)**: 시장 데이터 범위를 후보 평가에 쓰는 탐색 데이터와 사용하지
  않고 남겨 두는 최종 검증 데이터로 구분한 기록. 각 범위, 시간 순서, 비중첩 여부와 실제 사용 여부를
  가진다.
- **평가 기준(Evaluation Criteria)**: 후보 순위에 적용할 주 지표와 선택적인 동률 해소 지표의 순서.
  각 지표의 정의 버전과 우수 방향을 가리킨다.
- **파라미터 탐색(Parameter Exploration)**: 탐색 실행 전체를 식별하는 기록. 탐색 정의, 확정 후보 집합,
  전체 상태, 후보 상태별 집계, 생성·완료 시점과 결과 비교를 가진다.
- **후보 평가 결과(Candidate Evaluation Result)**: 후보 조합 하나와 그 백테스트 실행(F1), F3 공통 지표,
  순위 또는 순위 없음 상태 및 이유를 연결한 결과다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 완료된 탐색의 100%에서 성공 후보 전체가 같은 전략 버전, 공통 조건, 시장 데이터 기준 및
  지표 정의 버전을 사용하며, 이를 위반한 후보 비교가 0건이다.
- **SC-002**: 탐색 후보의 평가 또는 순위 결정에 예약된 최종 검증 데이터가 사용된 사례가 0건이다.
- **SC-003**: 결과의 100%에서 사용자는 원래 파라미터 범위, 실제 평가 후보, 공통 조건, 탐색·검증 데이터
  역할, 평가 기준과 정의 버전을 확인할 수 있다.
- **SC-004**: 성공 후보에 표시된 공통 지표가 해당 후보의 F3 단일 결과 분석과 불일치한 사례가 0건이다.
- **SC-005**: 같은 완료 탐색을 반복 조회했을 때 후보 집합, 후보별 결과 또는 완료 순위가 달라지는 사례가
  0건이다.
- **SC-006**: 지원 한도 안에서 후보 1,000개를 포함한 탐색 시작 요청의 95%에서 사용자는 전체 계산 시간과
  무관하게 2초 이내에 탐색 식별자와 계획 후보 수를 확인할 수 있다.
- **SC-007**: 후보 상태가 바뀐 뒤 탐색 진행 집계에 반영되기까지의 지연은 95%에서 5초 이내다.
- **SC-008**: 미래 성과 보장, 확정적 최적값 또는 자동 추천으로 오해될 수 있는 문구가 탐색 결과에 노출된
  사례가 0건이다.
- **SC-009**: 사용성 검증에서 대상 사용자의 85% 이상이 추가 도움 없이 전략, 3개 파라미터 범위, 공통
  조건, 탐색·검증 데이터 범위 및 평가 기준을 5분 이내에 설정하고 탐색 전 요약을 확인할 수 있다.
- **SC-010**: 사용성 검증에서 대상 사용자의 80% 이상이 완료 결과만 보고 상위 후보 둘의 파라미터 차이와
  수익·위험 지표 차이, 별도 최종 검증이 필요한 이유를 각각 설명할 수 있다.

## Assumptions

- 대상 사용자는 인증된 Thorp 사용자이며, 전략과 파라미터 정의, 백테스트 조건 검증은 F2를
  재사용한다. 탐색 및 후보 실행의 보존 기간과 접근 권한은 F1 정책을 따른다.
- 한 탐색은 하나의 전략 버전만 다룬다. 여러 전략을 비교하는 목적에는 F4 전략 비교를 사용한다.
- 탐색 범위에서 후보 조합을 선택하는 구체적인 방식과 후보 수를 정하는 정책은 이 명세의 범위 밖이다.
  다만 실제 실행 전 유한하고 중복 없는 후보 집합이 확정되어 사용자에게 후보 수가 공개되어야 한다.
- 후보별 백테스트에는 F2의 대상 종목, 기간, 초기 자산과 현재 지원되는 공통 조건이 동일하게 적용된다.
  수수료·세금·슬리피지 등 F2에 없는 조건은 이 기능만을 위해 새로 추가하지 않는다.
- 탐색 데이터와 최종 검증 데이터는 같은 데이터 출처 안의 서로 겹치지 않는 시간 구간으로 구분한다.
  검증 구간은 탐색 구간보다 시간상 뒤에 두며, 이 기능은 그 구간을 예약·표시할 뿐 실행하지 않는다.
- 평가 지표와 그 우수 방향, 계산 불가 규칙 및 단위는 F3의 버전된 공통 지표 정의를 그대로 사용한다.
  별도의 복합 점수나 숨겨진 가중치는 만들지 않는다.
- 상위 후보 강조는 저장된 평가 기준에 따른 상대적 순위 표시일 뿐 투자 조언이나 전략 추천이 아니다.
- 탐색이 시작되면 기존 완료 결과를 섞지 않고 후보마다 새 실행을 만든다. 향후 결과 재사용은 계산 부하와
  정확성 이득을 측정한 뒤 별도 요구사항과 계획으로 검토한다.
- 최초 지원 후보 수 한도는 대량 실행 요구를 검증할 수 있도록 최소 1,000개로 둔다. 더 큰 한도와 이를
  위한 실행 구조, 진행·결과 표시 방식은 계획 단계에서 실제 부하와 사용성 측정을 근거로 정한다.
- 사용자가 직접 실행을 취소하거나 일부 후보를 중단·재실행하는 기능, 결과 내보내기와 공유는 요청되지
  않았으므로 포함하지 않는다.

## Constitution Alignment

- **원칙 I (독립 실행 경계)**: FR-011~FR-015는 대량 후보 계산이 탐색 시작 요청과 독립적으로 진행되고
  추적되도록 요구하며, 계산을 어느 기술이나 구조로 분배할지는 정하지 않는다.
- **원칙 II (추적 가능성)**: 탐색과 후보 실행은 각각 식별 가능하고, 연결 종료 후에도 상태와 결과를
  추적할 수 있으며, 후보 상태 집계와 완료 기준을 명시한다.
- **원칙 III (실측 후 기술 도입)**: FR-010과 Assumptions는 지원 한도와 실행 구조를 부하 측정에 따라
  계획하도록 남겨 두고, Grid Search·Random Search, 작업 주체 수, Hadoop·Spark 등의 기술을 요구하지
  않는다.
- **원칙 IV (파트 경계 계약)**: 탐색 정의, 후보 조합, 데이터 역할, 평가 기준과 상태 집계는 생산·소비
  파트가 공유할 계약 대상이며, 구체적 필드와 전달 형식은 계획 단계에서 문서화한다.
- **원칙 V (결과 신뢰성)**: FR-005~FR-006이 탐색·검증 데이터 분리와 미래 데이터 사용 금지를,
  FR-012·FR-022가 멱등성과 재현성을, FR-013·FR-016~FR-020이 같은 조건과 공통 지표에 따른 비교 가능성을
  요구한다.
- 원칙에서 벗어나는 요구사항은 없다.
