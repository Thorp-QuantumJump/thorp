# Feature Specification: Out-of-Sample 검증

**Feature Branch**: `006-out-of-sample-validation`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "F6. Out-of-Sample 검증 — Thorp에서 전략 또는 파라미터 선택에 사용하지 않은 시장 데이터로 후보의 성능을 검증하는 기능을 정의한다. 과거 데이터에서 가장 좋은 전략이나 파라미터를 선택하면 해당 데이터에 과도하게 맞춰질 수 있으므로, 탐색에 사용하지 않은 별도의 구간에서 성능을 검증하여 과최적화 가능성을 확인할 수 있어야 한다. 사용자는 탐색 구간과 검증 구간을 구분하고, 탐색 구간에서 선택된 후보를 확인하고, 선택된 후보를 검증 구간에서 변경 없이 평가하고, 탐색 성능과 검증 성능의 차이를 확인해 후보의 일반화 가능성을 판단할 수 있어야 한다. 검증 구간 정보가 선택 과정에 사용되어서는 안 되고, 검증 대상은 탐색이 끝난 뒤 변경해서는 안 되며, 미래 정보가 이전 선택 과정에 유입되지 않아야 하고, 탐색 결과와 검증 결과를 명확하게 구분해 표시해야 한다. 구체적인 기간 분할 알고리즘, Walk-Forward 검증, 유사 시장 선택 알고리즘 자체의 검증, 파라미터 탐색 알고리즘, 분산 실행 방식은 범위에서 제외한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 선택 근거와 검증 대상 확정 (Priority: P1)

파라미터 탐색(F5) 또는 전략 비교(F4)를 마친 사용자가 그 결과에서 나온 후보가 탐색 구간에만 잘 맞은
것은 아닌지 확인하려 한다. 사용자는 완료된 탐색 기록을 열어 후보 선택에 실제로 사용된 탐색(In-Sample)
구간과 사용되지 않은 검증(Out-of-Sample) 구간을 확인하고, 탐색 구간의 순위와 근거를 보고 검증할 후보를
고른다. 시스템은 고른 후보의 전략 버전과 파라미터 값을 탐색 기록에서 그대로 가져와 보여주며, 사용자는
이를 편집할 수 없다. 검증을 시작하기 전에 사용자는 후보, 두 구간, 공통 조건, 평가 기준을 한 번 더 확인한다.

**Why this priority**: 어느 데이터로 후보를 골랐고 어느 데이터로 검증할지가 분리되지 않으면 검증
자체가 성립하지 않는다. 후보를 탐색 기록에서 변경 없이 가져오는 것이 "탐색이 끝난 뒤 검증 대상을
바꾸지 않는다"는 정책을 지키는 가장 확실한 방법이다.

**Independent Test**: 검증 구간이 예약된 완료 탐색(F5)을 열어 탐색 구간·검증 구간·후보 순위가 표시되고,
상위 후보를 선택했을 때 전략 버전과 모든 파라미터 값이 탐색 기록과 동일하게 채워지고 편집이 불가능한지
확인한다. 검증 구간이 탐색 구간과 겹치거나 앞서도록 지정하면 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 완료된 파라미터 탐색 또는 전략 비교 기록, **When** 사용자가 검증 준비 화면을 열면, **Then**
   후보 선택에 사용된 탐색 구간, 검증에 사용할 구간, 탐색 구간의 후보 순위와 평가 기준이 서로 구분되어
   표시된다.
2. **Given** 탐색 기록의 후보 목록, **When** 사용자가 검증할 후보 하나를 고르면, **Then** 그 후보의 전략
   버전과 전체 파라미터 값이 탐색 기록에서 그대로 채워지고, 사용자는 어떤 값도 수정할 수 없으며, 그 후보의
   탐색 구간 순위와 평가 기준 값이 함께 표시된다.
3. **Given** 검증 구간이 미리 예약된 탐색 기록(F5), **When** 사용자가 검증 구간을 확인하면, **Then** 예약된
   구간이 그대로 사용되고 사용자는 이를 변경할 수 없다.
4. **Given** 검증 구간이 예약되지 않은 탐색 기록(F4), **When** 사용자가 검증 구간을 지정하면, **Then**
   탐색 구간과 겹치지 않고 시간상 뒤에 있는 구간만 수락되고, 그렇지 않으면 어느 조건이 왜 위반되었는지
   안내되며 검증은 시작되지 않는다.
5. **Given** 아직 완료되지 않은 탐색 기록, **When** 사용자가 검증을 시작하려 하면, **Then** 탐색이 완료된
   뒤에만 검증할 수 있다는 안내와 함께 요청이 거부된다.

### User Story 2 - 검증 구간에서 변경 없이 평가 (Priority: P2)

사용자가 검증을 시작하면 시스템은 확정된 후보를 검증 구간의 시장 데이터로 새 백테스트(F1)로 평가한다.
공통 조건(대상 종목, 초기 자산 등)과 지표 정의 버전은 탐색과 같고, 달라지는 것은 데이터 구간만이다.
사용자는 검증 식별자로 진행 상태를 추적하고, 완료 뒤 검증 구간의 성과지표(F3)를 확인한다. 검증이
시작된 뒤에는 후보, 구간, 조건을 바꿀 수 없으며 바꾸려면 새 검증을 시작해야 한다.

**Why this priority**: 후보를 변경 없이 별도 데이터로 평가하는 것이 이 기능의 핵심 동작이다. 조건이
하나라도 달라지면 탐색 성능과의 차이를 구간 차이로 해석할 수 없다.

**Independent Test**: 확정된 후보로 검증을 시작해 식별자가 즉시 제공되는지, 생성된 백테스트의 전략
버전·파라미터·공통 조건·지표 정의 버전이 탐색 후보와 동일하고 기간만 검증 구간인지, 완료 뒤 결과가
F3 단일 결과 분석과 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 확인한 검증 설정, **When** 검증을 시작하면, **Then** 계산 완료를 기다리지 않고 검증
   식별자가 제공되고, 후보에 대해 검증 구간만을 기간으로 하는 새 백테스트가 시작된다.
2. **Given** 시작된 검증의 백테스트, **When** 실행 조건을 확인하면, **Then** 전략 버전, 파라미터 값, 대상
   종목, 초기 자산, 공통 조건, 지표 정의 버전이 탐색 후보와 동일하고 데이터 구간만 검증 구간이다.
3. **Given** 진행 중인 검증, **When** 사용자가 연결을 끊었다가 나중에 같은 식별자로 조회하면, **Then**
   검증은 중단되지 않았고 현재 상태 또는 완료 결과를 이어서 확인할 수 있다.
4. **Given** 시작된 검증, **When** 사용자가 후보의 파라미터나 검증 구간을 바꾸려 하면, **Then** 기존 검증은
   수정되지 않고 새 검증을 시작해야 한다는 안내가 표시된다.
5. **Given** 같은 검증 시작 요청이 재전달된 상황, **When** 시스템이 요청을 처리하면, **Then** 별도의 검증이나
   중복 백테스트를 만들지 않고 원래 검증을 계속 추적한다.

### User Story 3 - 탐색 성능과 검증 성능 비교 (Priority: P3)

검증이 완료되면 사용자는 같은 후보의 탐색 구간 성과와 검증 구간 성과를 F3 공통 지표별로 나란히 보고
차이를 확인한다. 두 결과는 어느 것이 탐색 구간이고 어느 것이 검증 구간인지 항상 구분되어 표시되며,
각 구간의 길이와 거래일 수가 함께 제공된다. 사용자는 두 구간의 자산 가치 흐름을 같은 화면에서 이어
보며 성과가 검증 구간에서 어떻게 달라졌는지 읽는다. 시스템은 합격·불합격 판정을 내리지 않고, 사용자가
차이를 바탕으로 일반화 가능성을 스스로 판단할 수 있게 근거를 제공한다.

**Why this priority**: 검증 성과 하나만으로는 과최적화를 판단할 수 없다. 탐색 성과와의 차이를 지표별로
읽을 수 있어야 사용자가 후보의 일반화 가능성을 판단할 수 있다.

**Independent Test**: 완료된 검증을 열어 지표마다 탐색 값·검증 값·차이가 한 줄에 표시되고 구간 표기가
붙어 있는지, 각 값이 해당 구간 백테스트의 F3 결과와 일치하는지, 계산 불가 지표가 구분되는지, 자동
판정 문구가 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 완료된 검증, **When** 사용자가 결과를 열면, **Then** F3 공통 지표마다 탐색 구간 값, 검증 구간
   값, 두 값의 차이가 같은 정의·단위로 나란히 표시되고 각 값에 어느 구간의 값인지 표기된다.
2. **Given** 결과의 지표 값, **When** 사용자가 각 구간 백테스트의 단일 결과 분석(F3)과 대조하면, **Then**
   두 값은 동일하다.
3. **Given** 어느 한 구간에서 계산 불가인 지표, **When** 사용자가 결과를 확인하면, **Then** 그 지표의 차이는
   숫자 대신 계산 불가와 이유로 표시되고 다른 지표의 비교는 계속 제공된다.
4. **Given** 완료된 검증, **When** 사용자가 자산 가치 흐름을 확인하면, **Then** 탐색 구간과 검증 구간의
   자산 가치 시계열이 같은 시간축 위에 이어져 표시되고 구간 경계가 명확히 구분된다.
5. **Given** 완료된 검증, **When** 사용자가 결과 전체를 읽으면, **Then** 각 구간의 길이와 거래일 수가
   표시되고, 시스템이 후보를 “검증 통과”, “일반화됨”처럼 판정하는 표현은 없다.

### User Story 4 - 검증의 독립성 확인 (Priority: P4)

사용자는 검증 결과와 함께 이 검증이 탐색과 독립적으로 수행되었음을 확인한다. 후보가 어떤 탐색 기록의
어느 순위에서 왔는지, 탐색 구간에 검증 구간 데이터가 사용되지 않았는지, 같은 탐색 기록의 다른 후보가
같은 검증 구간에서 이미 몇 번 검증되었는지를 볼 수 있다. 같은 탐색 기록에서 여러 후보를 같은 검증
구간으로 검증하면 검증 구간이 사실상 선택에 쓰이게 되므로, 시스템은 그 사실을 사용자에게 알린다.

**Why this priority**: 검증 결과의 가치는 독립성에 달려 있다. 독립성이 깨진 검증을 독립적인 것처럼
표시하면 과최적화 확인이라는 목적이 무너진다.

**Independent Test**: 완료된 검증을 열어 출처 탐색 기록, 후보의 탐색 순위, 두 구간의 비중첩·시간 순서
확인 결과가 표시되는지 확인한다. 같은 탐색 기록에서 두 번째 후보를 같은 구간으로 검증했을 때 두 검증
모두에 반복 검증 횟수와 안내가 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 완료된 검증, **When** 사용자가 검증 근거를 열면, **Then** 출처 탐색 기록, 후보의 탐색 구간 순위와
   평가 기준, 탐색 구간과 검증 구간의 범위 및 시장 데이터 기준, 두 구간이 겹치지 않고 검증 구간이 뒤에
   있음이 표시된다.
2. **Given** 같은 탐색 기록의 같은 검증 구간에서 이미 검증된 후보가 있는 상태, **When** 사용자가 다른
   후보의 검증을 시작하거나 결과를 열면, **Then** 이 검증 구간에서 같은 탐색 기록의 후보가 검증된 총 횟수와
   반복 검증이 검증의 독립성을 약화시킨다는 안내가 표시된다.
3. **Given** 완료된 검증, **When** 사용자가 검증 구간의 결과가 탐색 기록의 순위에 반영되었는지 확인하면,
   **Then** 탐색 기록의 후보 순위, 평가 기준, 결과는 검증 전과 동일하다.
4. **Given** 완료된 검증, **When** 사용자가 결과 설명을 읽으면, **Then** 결과는 특정 과거 구간에 대한
   평가임과 미래 성과를 보장하지 않음이 고지된다.

### Edge Cases

- 출처 탐색 기록이 완료되지 않았거나 성공 후보가 없으면 검증을 시작할 수 없다. 탐색 구간에서 실패한
  후보는 비교할 탐색 성과가 없으므로 검증 대상으로 선택할 수 없다. 주 평가 지표를 계산할 수 없어 순위가
  없는 성공 후보는 사용자가 명시적으로 선택하면 검증할 수 있으되, 결과에 탐색 구간에서 순위 없음이었음을
  표시한다.
- 검증 구간이 탐색 구간과 겹치거나 탐색 구간보다 앞서거나 탐색 구간 종료일 이전에 시작하면 입력을
  거부한다. 두 구간 사이에 공백이 있는 것은 허용하되 공백 길이를 표시한다.
- 검증 구간의 시장 데이터가 아직 존재하지 않거나 일부만 존재하면(예약 구간이 현재 시점보다 뒤인 경우)
  검증을 시작하지 않고 사용 가능한 데이터 범위를 안내한다. 부분 데이터로 조용히 실행하지 않는다.
- 검증 구간이 너무 짧아 어떤 지표를 계산할 수 없으면 그 지표는 F3 규칙에 따라 계산 불가로 표시하고
  나머지 비교는 제공한다. 검증 구간에서 거래가 한 건도 없어도 결과는 제공하며 거래 없음을 명시한다.
- 탐색 기록에 사용된 전략 버전이나 지표 정의 버전이 그 뒤에 개정되어도 검증은 탐색 기록에 고정된 버전을
  사용한다. 고정된 버전을 더 이상 실행할 수 없으면 검증을 시작하지 않고 그 이유를 알린다.
- 탐색 기록의 시장 데이터 기준(F1 FR-018)과 검증 구간에서 사용할 데이터 기준이 다르면 결과에 두 기준을
  각각 표시한다.
- 검증 백테스트가 실패하면 검증은 실패로 표시되고 이유가 제공되며, 탐색 구간 성과는 그대로 표시된다.
- 같은 후보에 대해 같은 검증 구간으로 검증을 다시 시작하면 별도의 검증 기록이 만들어지되, 결과는 재현
  가능성에 따라 이전 검증과 동일해야 한다. 요청의 재전달·재시도는 새 검증을 만들지 않는다.
- 같은 탐색 기록에서 여러 후보를 같은 검증 구간으로 검증하는 것을 막지는 않지만, 그 횟수를 모든 관련
  검증 결과에 표시하고 독립성 약화를 안내한다.
- 사용자가 결과를 반복 조회해도 탐색 값, 검증 값, 차이, 구간 정보는 달라지지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 검증은 완료된 탐색 기록(파라미터 탐색 F5 또는 전략 비교 F4)을 출처로 해야 한다. 탐색 기록이
  없는 임의의 전략·파라미터 조합은 이 기능으로 검증할 수 없다.
- **FR-002**: 시스템은 출처 탐색 기록에서 후보 선택에 실제로 사용된 데이터 구간을 탐색 구간으로 확정하고,
  이를 검증 구간과 구분해 사용자에게 표시해야 한다.
- **FR-003**: 출처 탐색 기록에 예약된 검증 데이터 범위(F5 FR-005)가 있으면 그 범위를 검증 구간으로 사용해야
  하며 사용자는 이를 변경할 수 없다. 예약된 범위가 없으면 사용자는 검증 구간을 지정해야 하며, 검증 구간은
  탐색 구간과 겹치지 않고 시간상 탐색 구간 뒤에 있어야 한다.
- **FR-004**: 검증 대상 후보는 출처 탐색 기록에서 탐색 구간 백테스트가 성공 완료된 후보 중 사용자가 선택한
  것이어야 한다. 시스템은 후보의 전략 버전과 전체 파라미터 값을 탐색 기록에서 그대로 가져와야 하며,
  사용자가 이를 수정하는 것을 허용해서는 안 된다.
- **FR-005**: 시스템은 검증 대상 후보와 함께 그 후보의 탐색 구간 순위, 적용된 평가 기준, 탐색 구간 성과지표를
  표시해야 한다.
- **FR-006**: 검증 시작 전 시스템은 후보(전략 버전·파라미터), 탐색 구간, 검증 구간, 공통 조건, 지표 정의
  버전을 사용자에게 보여주고 확인을 받아야 한다.
- **FR-007**: 출처 탐색 기록이 완료 상태가 아니거나, 검증 구간이 FR-003을 위반하거나, 검증 구간의 시장
  데이터가 전부 존재하지 않거나, 후보에 고정된 전략 버전 또는 지표 정의 버전을 더 이상 실행할 수 없으면
  검증은 거부되어야 하고 어떤 백테스트도 시작되지 않아야 한다. 거부 사유는 사용자에게 특정되어 제공되어야
  한다.
- **FR-008**: 수락된 검증은 고유 식별자를 가져야 하며, 사용자는 그 식별자로 요청 생명주기와 독립적으로 진행
  상태와 결과를 이후에도 추적할 수 있어야 한다.
- **FR-009**: 검증이 수락되면 후보에 대해 검증 구간만을 기간으로 하는 새 백테스트 실행(F1)이 시작되어야
  한다. 이 실행은 출처 탐색의 전략 버전, 파라미터 값, 대상 종목, 초기 자산, 공통 조건 및 지표 정의 버전을
  동일하게 사용해야 하며, 데이터 구간 외의 어떤 조건도 달라져서는 안 된다.
- **FR-010**: 검증 구간의 시장 데이터는 후보 선택, 탐색 구간 순위 결정 또는 탐색 기록의 갱신에 사용되어서는
  안 된다. 검증 결과는 출처 탐색 기록의 후보 순위, 평가 기준, 결과를 변경하지 않아야 한다.
- **FR-011**: 검증이 시작된 뒤 후보, 탐색 구간, 검증 구간, 공통 조건은 변경할 수 없어야 한다. 이를 바꾸려면
  새 검증을 시작해야 한다.
- **FR-012**: 시스템은 검증에 대해 최소한 실행 대기, 실행 중, 완료, 실패 상태를 구분해야 한다. 검증 백테스트가
  실패하면 검증은 실패로 표시되고 이유가 제공되어야 하며, 탐색 구간 성과는 계속 표시되어야 한다.
- **FR-013**: 같은 검증 시작 요청 또는 검증 작업의 재전달·재시도는 중복 검증, 중복 백테스트, 중복 결과
  또는 중복 상태 변경을 만들지 않아야 한다.
- **FR-014**: 검증 결과는 F3 공통 지표 각각에 대해 탐색 구간 값, 검증 구간 값, 두 값의 차이를 같은 정의·
  계산 기준·단위로 나란히 제공해야 한다. 각 값에는 어느 구간의 값인지 표기되어야 한다.
- **FR-015**: 결과에 표시되는 탐색 구간 값은 출처 탐색 기록의 해당 후보 결과와, 검증 구간 값은 검증
  백테스트의 단일 결과 분석(F3)과 동일해야 한다.
- **FR-016**: 어느 한 구간에서 계산 불가인 지표는 차이를 숫자로 표시하지 않고 계산 불가와 이유로 표시해야
  하며, 다른 지표의 비교는 계속 제공되어야 한다.
- **FR-017**: 검증 결과는 탐색 구간과 검증 구간의 자산 가치 시계열을 같은 시간축 위에 이어서 제공하고, 두
  구간의 경계, 각 구간의 길이와 거래일 수, 두 구간 사이의 공백 길이를 표시해야 한다.
- **FR-018**: 시스템은 후보에 대해 합격·불합격, 일반화 여부, 과최적화 여부 같은 자동 판정을 제공해서는 안
  된다. 결과는 사용자가 차이를 바탕으로 판단할 수 있는 근거로 제공되어야 한다.
- **FR-019**: 검증 결과에는 출처 탐색 기록, 후보의 탐색 구간 순위와 평가 기준, 탐색 구간과 검증 구간의 범위,
  각 구간의 시장 데이터 기준(F1 FR-018), 전략 버전, 지표 정의 버전, 두 구간의 비중첩·시간 순서 확인 결과가
  함께 제공되어야 한다.
- **FR-020**: 시스템은 같은 출처 탐색 기록의 후보가 같은 검증 구간에서 검증된 총 횟수를 기록하고, 그 횟수가
  둘 이상이면 관련된 모든 검증의 시작 전 확인 화면과 결과에 그 횟수와 반복 검증이 독립성을 약화시킨다는
  안내를 표시해야 한다.
- **FR-021**: 검증 결과에는 결과가 특정 과거 구간에 대한 평가이며 미래 성과를 보장하지 않는다는 고지가
  포함되어야 한다.
- **FR-022**: 같은 검증을 반복 조회할 때 탐색 값, 검증 값, 차이, 구간 정보는 동일해야 한다. 검증 백테스트
  결과는 동일한 전략·파라미터·조건·데이터 기준에서 재현 가능해야 한다.
- **FR-023**: 검증과 그 백테스트의 접근 범위는 F1의 정책을 따라야 하며, 출처 탐색 기록을 조회할 수 있는
  사용자만 검증을 시작하고 조회할 수 있어야 한다.
- **FR-024**: 이 기능은 탐색·검증 구간 구분, 후보 확정, 검증 구간 평가, 탐색·검증 성과 비교와 독립성 근거
  제공까지만 다룬다. 구간을 자동으로 분할하는 알고리즘, Walk-Forward 검증, 유사 시장 선택 알고리즘의
  검증, 파라미터 탐색 알고리즘, 실행을 병렬·분산하는 구조는 포함하지 않는다.

### Key Entities *(include if feature involves data)*

- **탐색 기록(Selection Record)**: 후보 선택의 출처가 되는 완료된 파라미터 탐색(F5) 또는 전략 비교(F4).
  후보 목록, 후보 선택에 사용된 데이터 구간, 평가 기준, 순위, 공통 조건, 전략 버전과 지표 정의 버전,
  예약된 검증 데이터 범위(있는 경우)를 가진다.
- **구간 구분(Sample Split)**: 하나의 검증에서 탐색(In-Sample) 구간과 검증(Out-of-Sample) 구간을 구분한
  기록. 각 구간의 범위, 각 구간의 시장 데이터 기준, 비중첩·시간 순서 확인 결과, 두 구간 사이의 공백을 가진다.
- **검증 대상 후보(Validation Candidate)**: 탐색 기록에서 변경 없이 가져온 전략 버전과 전체 파라미터 값의
  한 세트. 출처 탐색 기록과 그 안에서의 순위, 적용된 평가 기준을 가리킨다.
- **Out-of-Sample 검증(Out-of-Sample Validation)**: 검증 실행 전체를 식별하는 기록. 검증 대상 후보, 구간
  구분, 검증 백테스트 실행(F1), 상태, 생성·완료 시점, 같은 탐색 기록·검증 구간에서의 반복 검증 횟수를
  가진다.
- **성과 대비(Performance Contrast)**: 같은 후보의 탐색 구간 성과와 검증 구간 성과를 F3 공통 지표별로
  나란히 놓은 결과. 지표마다 탐색 값, 검증 값, 차이 또는 계산 불가 상태와 이유를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 검증 백테스트의 100%에서 전략 버전, 파라미터 값, 공통 조건, 지표 정의 버전이 출처 탐색 후보와
  동일하고 데이터 구간만 다르다. 이를 위반한 검증이 0건이다.
- **SC-002**: 검증 구간이 탐색 구간과 겹치거나 앞서는 상태로 시작된 검증이 0건이다.
- **SC-003**: 검증 결과가 출처 탐색 기록의 후보 순위, 평가 기준 또는 결과를 변경한 사례가 0건이다.
- **SC-004**: 결과의 100%에서 탐색 구간 값과 검증 구간 값에 구간 표기가 붙어 있고, 각 값이 해당 구간 결과
  (F5/F4 결과 및 F3 단일 결과 분석)와 불일치한 사례가 0건이다.
- **SC-005**: 같은 탐색 기록의 후보가 같은 검증 구간에서 둘 이상 검증된 경우의 100%에서 관련 검증 결과에
  반복 횟수와 독립성 안내가 표시된다.
- **SC-006**: 검증 시작 요청의 95%에서 사용자는 전체 계산 시간과 무관하게 2초 이내에 검증 식별자를 확인할
  수 있다.
- **SC-007**: 같은 완료 검증을 반복 조회했을 때 탐색 값, 검증 값, 차이 또는 구간 정보가 달라지는 사례가
  0건이다.
- **SC-008**: 합격·불합격, 일반화 여부, 과최적화 여부 등 자동 판정으로 읽힐 수 있는 문구가 검증 결과에
  노출된 사례가 0건이다.
- **SC-009**: 사용성 검증에서 대상 사용자의 85% 이상이 추가 도움 없이 완료된 탐색에서 후보를 골라 3분
  이내에 검증을 시작하고, 탐색 구간과 검증 구간을 구분해 설명할 수 있다.
- **SC-010**: 사용성 검증에서 대상 사용자의 80% 이상이 완료 결과만 보고 탐색 성과와 검증 성과의 차이가
  큰 지표 둘을 짚어내고, 그것이 과최적화 가능성과 어떻게 연결되는지 설명할 수 있다.

## Assumptions

- 대상 사용자는 인증된 Thorp 사용자이며, 검증의 접근 권한과 보존 기간은 F1 정책을 따른다.
- 검증의 출처는 완료된 파라미터 탐색(F5) 또는 전략 비교(F4)다. 두 기능은 후보 선택에 사용한 데이터 구간,
  공통 조건, 평가 기준, 전략 버전, 지표 정의 버전을 기록하고 있으며 검증은 이를 그대로 참조한다. F5가
  예약한 검증 데이터 범위는 그대로 검증 구간이 된다.
- 한 검증은 후보 하나를 다룬다. 여러 후보를 검증하려면 검증을 후보마다 시작하며, 시스템은 그 횟수를
  드러내 독립성 약화를 알린다. 어느 후보를 몇 개 검증할지 강제하지 않는다.
- 탐색 구간과 검증 구간은 같은 데이터 출처 안의 서로 겹치지 않는 시간 구간이며 검증 구간은 시간상 뒤에
  있다. 구간을 나누는 비율이나 방식, 여러 구간을 이어 검증하는 방식(Walk-Forward)은 이 명세의 범위 밖이다.
- 검증 백테스트는 검증 구간을 기간으로 하는 F1의 새 실행이며 F2의 조건 검증과 F3의 지표 정의를 그대로
  사용한다. 이 기능만을 위한 새 지표나 복합 점수는 만들지 않는다.
- 탐색 구간과 검증 구간의 길이가 다를 수 있으므로 지표 차이의 해석은 사용자에게 맡기며, 시스템은 구간
  길이와 거래일 수를 함께 제공한다. 차이의 표현 방식(절대 차, 비율 등)은 계획 단계에서 지표 단위에 맞게
  정한다.
- 후보를 검증 구간에서 평가한 뒤 그 결과를 보고 파라미터를 다시 조정하는 것은 새 탐색으로 취급되며, 그
  탐색에 검증 구간을 탐색 구간으로 포함할지는 사용자의 책임이다. 시스템은 검증 구간이 이미 검증에 사용된
  사실을 기록으로 남겨 추적할 수 있게 한다.
- 검증 취소, 결과 내보내기와 공유, 여러 검증의 일괄 비교는 요청되지 않았으므로 포함하지 않는다.

## Constitution Alignment

- **원칙 I (독립 실행 경계)**: FR-008~FR-009, FR-012는 검증 백테스트가 시작 요청과 독립적으로 실행·추적되도록
  요구하며 실행 구조나 기술은 정하지 않는다.
- **원칙 II (추적 가능성)**: 검증은 고유 식별자를 가지며 연결 종료 후에도 상태와 결과를 추적할 수 있고
  상태 집합을 명시한다.
- **원칙 III (실측 후 기술 도입)**: 새 인프라나 대규모 처리 기술을 요구하지 않으며, 검증은 기존 F1 실행을
  재사용한다.
- **원칙 IV (파트 경계 계약)**: 탐색 기록 참조, 구간 구분, 검증 대상 후보, 성과 대비는 생산·소비 파트가
  공유할 계약 대상이며 구체적 필드와 전달 형식은 계획 단계에서 문서화한다.
- **원칙 V (결과 신뢰성)**: FR-003, FR-010이 검증 구간 정보의 선택 과정 유입과 미래 데이터 참조를 금지하고,
  FR-013·FR-022가 멱등성과 재현성을, FR-009·FR-014~FR-015가 같은 조건과 공통 지표에 따른 비교 가능성을
  요구한다.
- 원칙에서 벗어나는 요구사항은 없다.
