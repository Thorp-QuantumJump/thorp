# Feature Specification: 유사 시장·사건 탐색

**Feature Branch**: `007-similar-market-search`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "F7. 유사 시장 / 사건 탐색 — Thorp에서 사용자가 관심 있는 현재 또는 과거 시장 상황과 유사한 과거 시장 구간을 탐색하는 기능을 정의한다. 사용자는 기준 시장 상황, 유사 과거 구간과 판단 근거, 각 구간의 기간과 관련 정보를 확인하고 선택한 구간을 후속 백테스트 분석 구간으로 활용할 수 있어야 한다. 유사성 판단에는 비교 시점 이후 정보를 사용할 수 없고, 같은 입력은 재현 가능해야 하며, 결과를 미래의 반복이나 전략 추천으로 표현하지 않는다. 구체적인 뉴스 임베딩·클러스터링 알고리즘, 특정 데이터 공급자, 백테스트 실행 및 분산 처리 기술은 범위에서 제외한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기준 시장 상황과 유사성 기준 확인 (Priority: P1)

현재 또는 특정 과거 상황과 비슷한 사례를 찾고 싶은 사용자가 기준 시장과 관찰 구간을 정한다. 현재
상황은 검색 시점에 이용 가능한 최신 완결 데이터까지의 구간으로, 과거 상황은 사용자가 지정한 기간이나
제공되는 사건 항목의 확정된 기간으로 선택한다. 사용자는 탐색할 과거 범위와 적용될 유사성 정의를
확인하며, 어떤 시장 특성·거시 환경·사건 맥락을 어떤 범위에서 비교하는지 검색 전에 이해할 수 있다.

**Why this priority**: 무엇을 무엇과 비교하는지, 그리고 “유사함”이 어떤 뜻인지 확정되지 않으면 검색
결과와 설명을 해석하거나 같은 조건으로 재현할 수 없다.

**Independent Test**: 현재 상황과 과거 사건을 각각 기준으로 선택해 시장 범위, 기준 시작·종료일,
정보 기준 시점, 과거 탐색 범위 및 유사성 정의의 설명이 검색 전에 표시되는지 확인한다. 미래이거나
데이터가 완결되지 않은 기준일, 기준 구간과 겹치는 탐색 범위가 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 현재 상황을 기준으로 선택한 사용자, **When** 기준 상황을 확인하면, **Then** 적용 시장,
   최신 완결 데이터 기준일, 관찰 구간과 정보 기준 시점이 명확히 표시된다.
2. **Given** 사용자가 과거 기간을 직접 지정한 경우, **When** 기준 상황을 확인하면, **Then** 정확한
   시작일·종료일, 거래일 수, 시장 범위와 당시 정보 기준 시점이 표시된다.
3. **Given** 사용자가 제공되는 과거 사건 항목을 선택한 경우, **When** 기준 상황을 확인하면, **Then**
   사건 이름만이 아니라 비교에 쓰일 정확한 기간, 시장 범위, 당시 이용 가능했던 사건 정보와 출처 기준이
   표시되고 사용자가 이를 확인한 뒤 검색할 수 있다.
4. **Given** 적용될 유사성 정의, **When** 사용자가 기준 설명을 열면, **Then** 비교 차원별 의미, 관찰 범위,
   중요도, 차원별 값을 전체 점수와 순위로 결합하는 규칙, 점수의 의미와 범위, 최소 유사 기준, 데이터
   부족 처리 방식 및 정의 버전을 확인할 수 있다.
5. **Given** 미래 시점, 완결되지 않은 데이터 또는 기준 구간과 겹치는 과거 탐색 범위, **When** 사용자가
   검색을 요청하면, **Then** 어느 조건이 왜 유효하지 않은지 안내되고 검색은 수행되지 않는다.

### User Story 2 - 유사한 과거 시장 구간과 근거 확인 (Priority: P2)

사용자가 검색을 실행하면 기준을 충족하는 과거 시장 구간을 유사한 순서로 확인한다. 각 결과에는 정확한
기간과 유사성 점수뿐 아니라 어떤 비교 차원이 얼마나 비슷했는지, 어떤 차이는 남아 있는지, 판단에 사용한
당시 관측값과 사건 정보가 함께 표시된다. 사용자는 단순한 순위가 아니라 각 결과가 선택된 이유와 한계를
읽고 관심 구간을 좁힐 수 있다.

**Why this priority**: 유사 구간을 찾고 그 근거를 이해하는 것이 이 기능의 핵심 가치다. 설명 없이 점수만
제공하면 사용자가 결과를 신뢰하거나 분석 구간으로 선택할 수 없다.

**Independent Test**: 알려진 시장 특성이 다른 여러 과거 구간을 포함한 검색을 수행해, 최소 유사 기준을
통과한 결과만 정렬되는지 확인한다. 각 결과의 차원별 근거를 원천 관측값과 대조하고, 점수와 순위를 다시
계산했을 때 저장된 결과와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 최소 유사 기준을 통과한 과거 구간이 있는 검색, **When** 사용자가 결과를 열면, **Then** 각
   구간의 시작일·종료일, 거래일 수, 시장 범위, 전체 유사성 점수와 순위가 제공된다.
2. **Given** 유사 구간 하나, **When** 사용자가 판단 근거를 펼치면, **Then** 비교 차원별 기준 상황 값,
   후보 구간 값, 유사한 정도, 전체 점수에 미친 영향과 근거 데이터의 기준 시점을 확인할 수 있다.
3. **Given** 일부 차원은 유사하지만 다른 차이는 큰 구간, **When** 결과 설명을 확인하면, **Then** 주요
   유사 요인과 주요 차이 요인이 모두 표시되고 유사한 측면만 선택적으로 강조되지 않는다.
4. **Given** 모든 비교 기준 값이 같은 두 구간, **When** 사용자가 순위를 확인하면, **Then** 두 구간은 같은
   순위로 표시되고 임의의 우열이 부여되지 않는다.
5. **Given** 최소 유사 기준을 충족하는 구간이 없는 검색, **When** 결과를 확인하면, **Then** “유사 구간
   없음”과 적용 기준 및 탐색 범위가 표시되고 가장 덜 다른 구간을 유사한 사례처럼 대신 제공하지 않는다.

### User Story 3 - 시점 일관성과 검색 재현성 확인 (Priority: P3)

사용자는 검색 결과가 어떤 데이터와 유사성 정의로 만들어졌는지 확인한다. 과거 후보 구간은 각 구간의
종료 시점까지 공개되어 이용 가능했던 정보만으로 평가되며, 이후 수정된 값이나 이후에 알려진 사건 결과는
당시 값처럼 사용되지 않는다. 검색 기록에는 입력, 데이터 기준, 정의 버전과 결과가 고정되어 같은 기록을
언제 다시 열어도 같은 판단을 확인할 수 있다.

**Why this priority**: 사후 정보를 섞으면 실제 당시에는 알 수 없었던 이유로 구간을 선택하는 오류가 생긴다.
데이터와 정의 버전을 고정해야 설명을 검증하고 같은 판단을 재현할 수 있다.

**Independent Test**: 이후 크게 수정된 경제 지표와 사후 확정된 사건 정보가 포함된 시험 데이터를 사용해
과거 후보 종료 시점에 공개된 값만 근거에 나타나는지 확인한다. 동일한 입력·정보 기준 시점·데이터 기준·
유사성 정의 버전으로 검색을 반복해 결과 구간, 점수, 근거와 순서가 완전히 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 후보 구간 종료 뒤 수정된 지표 값, **When** 해당 후보의 유사성을 평가하면, **Then** 후보 종료
   시점에 이용 가능했던 값만 사용되고 이후 수정값은 판단 근거에 포함되지 않는다.
2. **Given** 사건의 영향이나 결과가 후보 구간 종료 뒤 알려진 경우, **When** 후보 근거를 확인하면, **Then**
   종료 시점까지 공개된 사건 맥락만 사용되고 사후 결과는 유사성 점수나 순위에 영향을 주지 않는다.
3. **Given** 동일한 기준 상황, 탐색 범위, 유사성 정의 버전과 데이터 기준, **When** 검색을 다시 수행하면,
   **Then** 결과 구간, 점수, 차원별 근거와 순위가 동일하다.
4. **Given** 데이터 또는 유사성 정의가 개정된 뒤 새 검색을 수행한 경우, **When** 과거 검색 기록과
   비교하면, **Then** 각 검색에 사용된 버전이 구분되고 기존 검색의 결과는 변경되지 않는다.
5. **Given** 완료된 검색 기록, **When** 사용자가 검색 식별자로 다시 열면, **Then** 검색 입력과 결과,
   제외된 구간의 집계 및 판단 근거가 처음 완료 시점과 동일하게 제공된다.

### User Story 4 - 유사 구간을 후속 백테스트에 활용 (Priority: P4)

사용자는 근거를 검토한 유사 과거 구간 하나를 선택하여 백테스트 조건 설정(F2)의 분석 기간으로 가져간다.
정확한 시작일과 종료일, 출처 검색과 유사성 근거가 함께 전달되며, 사용자는 전략·파라미터·대상 종목 등
나머지 조건을 별도로 설정하고 확인한다. 이 기능은 백테스트를 자동 실행하거나 선택한 구간에 맞는 전략을
추천하지 않는다.

**Why this priority**: 발견한 사례를 실제 분석 흐름에 연결해야 탐색이 행동 가능한 가치를 갖는다. 동시에
탐색과 실행의 경계를 분리해야 사용자가 조건을 확인하지 않은 백테스트나 자동 추천으로 오해하지 않는다.

**Independent Test**: 검색 결과 구간을 선택해 F2 조건 설정으로 이동하고 시작일·종료일과 출처 정보가
정확히 전달되지만 백테스트는 시작되지 않는지 확인한다. 전달된 기간을 수정하면 원래 유사 구간과 달라졌다는
표시가 생기고 원본 검색 기록은 변경되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 유사 구간 하나를 선택한 상태, **When** 후속 백테스트에 활용하면, **Then** 그 구간의
   정확한 시작일·종료일이 F2의 기간 입력으로 전달되고 출처 검색과 결과 구간을 추적할 수 있다.
2. **Given** 유사 구간이 기간으로 전달된 상태, **When** 조건 설정 화면이 열리면, **Then** 백테스트는 아직
   시작되지 않았고 사용자가 전략, 파라미터, 대상, 초기 자산 등 나머지 조건을 설정·검증해야 한다.
3. **Given** 사용자가 전달된 시작일 또는 종료일을 수정한 경우, **When** 조건을 확인하면, **Then** 현재
   기간이 원래 유사 구간과 다름이 명시되고 원래 검색 구간과 근거는 변경되지 않는다.
4. **Given** 유사 시장 결과, **When** 사용자가 관련 행동을 확인하면, **Then** 전략 추천이나 자동 매매
   선택은 제공되지 않고 기간을 백테스트 조건에 적용하는 행동만 제공된다.

### Edge Cases

- 현재 상황의 최신 거래일 데이터가 아직 완결되지 않았거나 일부 비교 차원이 늦게 발표되는 경우, 정보
  기준 시점을 데이터가 모두 이용 가능한 마지막 시점으로 고정하고 제외된 최신 기간을 사용자에게 알린다.
- 과거 사건 항목의 이름은 있으나 시작일·종료일 또는 당시 이용 가능했던 근거가 확정되지 않으면 기준
  상황으로 사용할 수 없으며, 사용자가 직접 유효한 과거 기간을 지정할 수 있게 안내한다.
- 기준 구간 또는 탐색 범위가 지원 시장 데이터 범위를 벗어나거나 거래일을 하나도 포함하지 않으면 검색을
  거부하고 사용 가능한 범위를 표시한다.
- 후보 구간은 기준 구간과 겹치면 자기 자신을 유사 결과로 반환하지 않는다. 서로 다른 후보 구간끼리
  겹치는 것은 허용하되 겹치는 거래일 수와 비율을 표시하여 사실상 같은 사례인지 판단할 수 있게 한다.
- 후보 구간이 필요한 비교 차원의 데이터를 모두 갖추지 못하면 일부 차원만으로 점수를 만들어 다른 후보와
  비교하지 않고 제외한다. 제외 구간 수와 데이터 부족 이유를 검색 결과에 집계한다.
- 수정 가능한 거시 지표는 후보 종료 당시 이용 가능했던 자료가 없으면 최신 수정값으로 대체하지 않고 해당
  후보를 제외한다.
- 전체 점수 또는 모든 차원별 값이 같은 후보는 같은 순위로 표시한다. 표시 순서가 필요하면 기간 순서를
  사용하되 그것이 우열 기준이 아님을 명시한다.
- 최소 유사 기준을 통과한 결과가 하나도 없으면 빈 결과를 정상적으로 제공하고 기준을 낮춘 것처럼 결과를
  조작하지 않는다.
- 검색 결과가 요청한 개수보다 적으면 실제 충족 결과만 제공하고, 부족한 수를 기준 미달 구간으로 채우지
  않는다.
- 데이터 또는 정의가 개정되어 새 검색 결과가 달라져도 과거 검색 기록의 구간, 점수, 근거와 순위는
  소급 변경하지 않는다.
- 선택한 유사 구간이 이후 F2의 데이터 가용성 검증을 통과하지 못하면 백테스트를 시작하지 않고 F2의 거부
  사유를 보여준다. 유사성 검색 성공이 백테스트 실행 가능성을 보장하지 않는다.
- 결과 기간을 후속 조건 화면에서 수정하면 수정된 기간은 사용자 지정 구간으로 취급하고 유사 시장 검색
  결과 자체로 표시하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 기준 시장 상황을 현재 상황 또는 특정 과거 상황 중 하나로 선택할 수 있어야 한다.
- **FR-002**: 현재 상황은 적용 시장, 관찰 구간 및 검색 시점에 이용 가능한 최신 완결 데이터의 기준일로
  정의되어야 한다. 과거 상황은 적용 시장, 시작일·종료일, 거래일 수 및 해당 종료일의 정보 기준 시점으로
  정의되어야 한다.
- **FR-003**: 사용자는 과거 상황을 기간으로 직접 지정하거나, 제공되는 사건 항목 중 하나를 선택할 수
  있어야 한다. 사건 항목을 선택해도 검색 전에 정확한 기간, 시장 범위, 당시 이용 가능했던 사건 정보와
  출처 기준을 확인해야 한다.
- **FR-004**: 사용자는 유사 구간을 찾을 과거 탐색 범위와 원하는 최대 결과 수를 지정할 수 있어야 한다.
  탐색 범위는 지원 데이터 범위 안에 있어야 하고 기준 구간과 겹쳐서는 안 된다.
- **FR-005**: 모든 유사성 판단은 버전이 있는 유사성 정의를 사용해야 한다. 정의에는 비교 차원과 각 차원의
  의미, 데이터 범주, 관찰 범위, 중요도, 차원별 값을 전체 점수와 순위로 결합하는 규칙, 전체 점수의
  의미·범위·우수 방향, 최소 유사 기준, 데이터 부족 처리 방식이 포함되어야 하며 사용자가 검색 전과
  결과에서 열람할 수 있어야 한다.
- **FR-006**: 유사성 정의는 시장 가격·수익·위험 같은 시장 특성과, 적용되는 경우 금리·거시 환경 또는
  사건 맥락 중 실제 판단에 사용한 차원을 명시해야 한다. 사용하지 않은 차원을 판단 근거인 것처럼
  표현해서는 안 된다.
- **FR-007**: 검색 전 시스템은 기준 상황, 과거 탐색 범위, 최대 결과 수, 정보 기준 시점, 데이터 기준 및
  유사성 정의 버전을 사용자에게 보여주고 확인을 받아야 한다.
- **FR-008**: 후보 과거 구간의 유사성은 해당 후보 구간의 종료 시점까지 공개되어 이용 가능했던 정보만으로
  판단해야 한다. 종료 이후의 시장 움직임, 수정된 지표 값, 사후에 알려진 사건 결과를 사용해서는 안 된다.
- **FR-009**: 판단에 사용되는 각 관측값과 사건 정보는 어느 시점에 이용 가능했는지 확인할 수 있어야 한다.
  수정 가능한 자료는 후보 종료 시점에 이용 가능했던 당시 값과 그 데이터 기준을 사용해야 한다.
- **FR-010**: 동일 검색 안의 모든 후보는 같은 유사성 정의 버전, 비교 차원, 관찰 구간 구성 규칙, 데이터
  기준 및 점수 기준으로 평가되어야 한다. 필요한 차원의 데이터가 부족한 후보를 일부 차원만으로 점수화해
  완전한 후보와 비교해서는 안 된다.
- **FR-011**: 후보 구간은 기준 구간과 겹치지 않아야 하고, 같은 시작일·종료일을 가진 결과가 중복되어서는
  안 된다. 후보끼리 겹치면 각 결과에 겹치는 거래일 수와 비율을 표시해야 한다.
- **FR-012**: 검색 결과는 최소 유사 기준을 충족하는 과거 구간만 전체 점수의 우수 방향에 따라 정렬해,
  사용자가 지정한 최대 결과 수까지 제공해야 한다. 기준을 충족하지 못한 구간을 결과 수를 채우기 위해
  포함해서는 안 된다.
- **FR-013**: 각 결과는 순위, 전체 유사성 점수, 시작일·종료일, 거래일 수, 시장 범위, 기준 상황과의 시간적
  관계 및 관련 사건·시장 정보를 제공해야 한다.
- **FR-014**: 각 결과는 비교 차원별 기준 상황 값과 후보 값, 유사한 정도, 전체 점수에 미친 영향 및 근거의
  정보 기준 시점을 제공해야 한다. 점수만으로 유사하다고 설명해서는 안 된다.
- **FR-015**: 각 결과는 가장 크게 기여한 유사 요인뿐 아니라 가장 큰 차이 요인과 비교에서 다루지 않은
  주요 한계를 함께 표시해야 한다.
- **FR-016**: 모든 비교 기준 값이 같은 후보에는 같은 순위를 부여해야 한다. 동일 순위 후보의 표시 순서에
  기간 순서를 사용한 경우 이를 우열 기준으로 표현해서는 안 된다.
- **FR-017**: 기준을 충족하는 후보가 없으면 시스템은 “유사 구간 없음”을 정상 결과로 제공하고, 적용한
  탐색 범위, 최소 유사 기준과 제외 사유 집계를 함께 표시해야 한다.
- **FR-018**: 완료된 검색은 고유 식별자를 가져야 하며, 검색 기록은 기준 상황, 탐색 범위, 입력 옵션,
  정보 기준 시점, 데이터 기준, 유사성 정의 버전, 결과 구간·점수·근거·순위 및 제외 사유 집계를 보존해야
  한다.
- **FR-019**: 동일한 기준 상황, 탐색 범위, 입력 옵션, 정보 기준 시점, 데이터 기준 및 유사성 정의 버전으로
  수행한 검색은 결과 구간, 점수, 차원별 근거와 순위가 동일해야 한다.
- **FR-020**: 데이터나 유사성 정의가 개정된 이후의 새 검색은 새 버전을 명시해야 하며, 이미 완료된 검색의
  입력, 결과 및 근거를 소급 변경해서는 안 된다.
- **FR-021**: 결과에는 유사성이 정의에 포함된 제한된 차원에 대한 과거 사례의 비교일 뿐 동일한 미래의
  반복이나 성과를 예측·보장하지 않는다는 고지가 항상 포함되어야 한다.
- **FR-022**: 시스템은 유사 검색 결과를 근거로 전략, 파라미터, 거래 행동 또는 기대 성과를 추천해서는
  안 된다.
- **FR-023**: 사용자는 결과 구간 하나를 선택해 정확한 시작일·종료일을 F2 백테스트 조건 설정의 기간으로
  전달할 수 있어야 한다. 전달 정보는 출처 검색 식별자와 결과 구간을 함께 가리켜야 한다.
- **FR-024**: 유사 구간을 F2에 전달하는 동작은 백테스트를 시작해서는 안 된다. 사용자가 전략, 파라미터,
  대상 종목, 초기 자산 등 나머지 조건을 설정하고 F2 검증을 통과한 뒤 별도로 실행해야 한다.
- **FR-025**: 사용자가 전달된 기간을 수정하면 현재 기간이 원래 유사 구간과 다름을 표시하고, 원본 검색
  기록과 결과는 변경하지 않아야 한다. 수정된 기간을 원래 유사 시장 결과로 표현해서는 안 된다.
- **FR-026**: 검색 기록과 결과는 검색을 요청한 사용자만 조회하고 후속 조건으로 사용할 수 있어야 한다.
- **FR-027**: 이 기능은 기준 시장 상황 설정, 유사 과거 구간 탐색, 판단 근거 제공과 기간 전달까지만
  제공한다. 구체적인 뉴스 표현·군집화·유사성 계산 알고리즘, 특정 데이터 공급자, 전략 추천, 백테스트
  실행, 자동 매매 및 분산 데이터 처리 기술 선택은 포함하지 않는다.

### Key Entities *(include if feature involves data)*

- **기준 시장 상황(Reference Market Situation)**: 비교의 기준이 되는 현재 또는 과거 시장 구간. 유형,
  적용 시장, 시작일·종료일, 거래일 수, 정보 기준 시점과 선택한 사건 항목을 가진다.
- **사건 항목(Event Context)**: 사용자가 기준 상황을 찾거나 확인할 때 쓰는 당시 알려진 사건 정보. 이름,
  확정 기간, 시장 범위, 설명, 정보가 이용 가능해진 시점과 출처 기준을 가진다.
- **유사성 정의(Similarity Definition)**: “유사함”의 버전된 판단 계약. 비교 차원, 의미, 데이터 범주,
  관찰 범위, 중요도, 차원별 값을 결합하는 규칙, 점수 체계와 우수 방향, 최소 유사 기준, 데이터 부족
  처리 규칙을 가진다.
- **시점 일관 근거(Point-in-Time Evidence)**: 유사성 판단에 실제 사용한 관측값 또는 사건 정보. 값과
  대상 기간, 당시 이용 가능 시점, 데이터 기준 및 어느 비교 차원에 사용됐는지를 가진다.
- **유사 시장 구간(Similar Market Interval)**: 최소 기준을 통과한 과거 후보 구간. 시작일·종료일,
  거래일 수, 시장 범위, 점수, 순위, 차원별 유사·차이 요인과 다른 후보와의 중첩 정보를 가진다.
- **유사 시장 검색(Similar Market Search)**: 완료된 검색 전체를 식별하는 기록. 기준 상황, 탐색 범위,
  입력 옵션, 정보·데이터 기준, 유사성 정의 버전, 결과 집합과 제외 사유 집계를 가진다.
- **백테스트 기간 전달(Backtest Period Handoff)**: 선택한 결과 구간을 F2 조건 설정에 연결한 기록. 정확한
  기간, 출처 검색과 결과 구간, 사용자가 기간을 수정했는지 여부를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 과거 후보 구간의 유사성 판단에 그 구간 종료 뒤 이용 가능해진 값이나 사건 정보가 사용된
  사례가 0건이다.
- **SC-002**: 동일한 입력 옵션, 정보 기준 시점, 데이터 기준 및 유사성 정의 버전으로 검색을 반복했을 때
  결과 구간, 점수, 차원별 근거 또는 순위가 달라지는 사례가 0건이다.
- **SC-003**: 제공된 유사 구간의 100%에서 사용자는 전체 점수, 주요 유사 요인, 주요 차이 요인, 차원별
  관측 근거와 그 정보 기준 시점을 확인할 수 있다.
- **SC-004**: 최소 유사 기준에 미달하거나 필수 비교 차원이 누락된 구간이 유사 결과에 포함된 사례가
  0건이다.
- **SC-005**: 검색 결과 또는 빈 결과의 100%에서 적용 시장, 기준·탐색 기간, 데이터 기준, 유사성 정의
  버전, 최소 유사 기준과 미래 반복을 보장하지 않는다는 고지를 확인할 수 있다.
- **SC-006**: 일 단위 10년 과거 탐색 범위에서 최대 10개 결과를 요청한 검색의 95%는 사용자가 검색을
  시작한 뒤 10초 이내에 결과 또는 “유사 구간 없음”을 제공한다.
- **SC-007**: 선택한 결과 구간을 F2로 전달한 사례의 100%에서 시작일·종료일과 출처 검색이 정확히
  보존되며, 전달 동작만으로 백테스트가 시작된 사례는 0건이다.
- **SC-008**: 사용성 검증에서 대상 사용자의 85% 이상이 3분 이내에 현재 또는 과거 기준 상황과 과거 탐색
  범위를 설정하고 적용될 유사성 기준을 확인할 수 있다.
- **SC-009**: 사용성 검증에서 대상 사용자의 80% 이상이 상위 결과 하나의 주요 유사 요인과 차이 요인을
  각각 하나 이상 설명하고, 결과가 미래 예측이 아닌 이유를 추가 안내 없이 설명할 수 있다.
- **SC-010**: 전략·파라미터·거래 행동 추천 또는 동일한 미래가 반복된다는 표현이 유사 시장 결과에 노출된
  사례가 0건이다.

## Assumptions

- 대상 사용자는 인증된 Thorp 사용자이며, 검색 기록의 보존 기간과 사용자 접근 정책은 기존 분석
  기록과 동일한 수준으로 운영한다.
- 초기 범위는 KRX 일 단위 시장 상황이다. 장중 상황, 해외 시장 간 유사성 비교 및 실시간 미완결 데이터는
  별도 기능으로 다룬다.
- 현재 상황의 관찰 구간에는 검색 시점에 모든 필수 비교 차원이 이용 가능한 마지막 완결 거래일까지의
  데이터를 사용한다. 최신성보다 차원 간 시점 일관성을 우선한다.
- 과거 사건 항목은 사용자의 기준 상황 선택을 돕는 선택 수단이며 필수 입력은 아니다. 사건 항목을 제공할
  데이터가 없더라도 사용자는 과거 기간을 직접 지정해 시장 특성 기준 검색을 수행할 수 있다.
- 유사성 정의는 하나 이상 제공될 수 있다. 여러 정의가 있으면 사용자가 선택하고, 하나만 있으면 적용되는
  정의를 확인한다. 정의의 실제 비교 차원, 중요도와 점수 계산 방법은 계획 단계에서 데이터 가용성과
  설명 가능성을 검증해 정한다.
- 후보 관찰 구간은 기준 구간과 같은 거래일 수를 갖는 것을 기본으로 한다. 휴장일 등으로 정확히 맞출 수
  없는 경우의 구성 규칙은 유사성 정의에 명시하고 모든 후보에 동일하게 적용한다.
- 시장 상황과 사건 맥락의 유사성은 선택된 정의에 포함된 관측 가능한 차원만을 뜻한다. 사회·정치적 사건의
  의미 전체가 같다고 주장하지 않는다.
- 결과에 표시되는 관련 사건·시장 정보는 후보 종료 시점까지 이용 가능했던 내용으로 제한한다. 종료 뒤의
  시장 성과나 사건 결말은 유사성 설명에 포함하지 않는다.
- 데이터 공급자, 뉴스 표현 방식, 군집화 또는 점수 계산 알고리즘, 저장 형식과 실행 구조는 계획 단계에서
  결정하며 특정 기술에 결합하지 않는다.
- 유사 시장 검색은 후보 기간을 찾고 근거를 제공하는 분석 보조 기능이다. 투자 조언, 전략 선택, 성과 예측,
  Out-of-Sample 검증(F6) 또는 자동 매매를 대신하지 않는다.
- 선택한 구간은 F2의 기간 입력으로만 전달된다. 실제 백테스트 실행·추적은 F1, 조건 검증은 F2, 결과
  분석은 F3의 정책과 기능을 그대로 따른다.

## Constitution Alignment

- **원칙 I·II (백테스트 실행 경계와 추적성)**: FR-023~FR-024는 유사 구간을 F2의 기간 입력으로만
  전달하고 백테스트를 자동 실행하지 않는다. 이후 실행은 F1의 독립 실행·추적 정책을 그대로 따른다.
- **원칙 III (실측 후 기술 도입)**: FR-027과 Assumptions는 뉴스 표현, 군집화, 유사성 계산 및 분산 처리
  기술을 요구하지 않는다. 계획 단계에서 데이터 가용성, 10년 범위 응답 목표와 측정 결과를 바탕으로 가장
  단순한 충족 방식을 선택한다.
- **원칙 IV (파트 경계 계약)**: 기준 상황, 유사성 정의, 시점 일관 근거, 검색 결과 및 F2 기간 전달은 이를
  생산·소비하는 파트가 공유할 계약이며, 구체적 필드와 전달 형식은 계획 단계에서 문서화한다.
- **원칙 V (결과 신뢰성)**: FR-008~FR-010이 후보 시점 이후 정보 사용을 금지하고, FR-018~FR-020이 데이터·
  정의 버전과 재현성을 보존하며, FR-021~FR-022가 과거 유사성을 미래 보장이나 추천으로 오인하지 않게 한다.
- 원칙에서 벗어나는 요구사항은 없다.
