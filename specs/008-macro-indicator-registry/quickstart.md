# Quickstart / 검증 시나리오: Spec 008

이 문서는 **구현 후 실행할 검증 절차**다. 현재 plan 단계에서 수집기·API가 이미 동작한다는 뜻이 아니다. 실제 원천 인증키·이용 승인은 팀이 별도로 확보한다. 키를 파일/로그/응답에 적지 않는다.

## 준비

1. [spec.md](spec.md)의 FR-001 17개 지표와 [research.md](research.md)의 PD-11 항목을 대조한다. 지표별 공식 원천, 통계표/항목 코드, 원/변환 단위, 과거 시작월, 발표일 제공 여부, 작성기관/계열별 상업 이용·재배포 예외, 개편 연결, 정기 재조회 `N`의 근거를 실제 응답·약관 증거와 함께 확정한다. 관세청 무역수지는 직접 제공값인지 파생값인지 확인한다. 17개 중 하나라도 미확인이면 실자료 완료 판정은 중단한다.
2. 개발 DB가 필요하면 저장소 루트에서 `docker compose -f docker-compose.dev.yml up -d postgres`로 PostgreSQL 16을 준비한다. 기존 개인 데이터가 있을 수 있으므로 볼륨 삭제·초기화 명령은 이 절차에 없다.
3. Python은 `data/requirements.txt`/`requirements-dev.txt`, Backend는 기존 Gradle 설정을 사용한다. 구현 시 초기/정기 수집 스크립트의 실제 명령과 필요한 비밀 환경변수 이름을 여기에 확정한다. 아직 존재하지 않는 스크립트 이름을 실행 지침처럼 쓰지 않는다.

009 변화 요약용 `path`는 해당 분야 기준월 `T_g=t`의 달력상 `t-2,t-1,t` 세 칸이다. `T_g`가 없으면 빈 배열이다. 지표 자체의 `latestPath`는 지표별 최신 유효월을 기준으로 하므로 `T_g`가 없어도 완결 자료 버전이 있다면 세 칸을 제공한다. 빠진 월은 null로 확인한다. 발표일 미제공과 미수신은 구분하며 수신 시각을 발표일로 표시하지 않는다.

## 정적·자동 검증 명령

```powershell
Push-Location data
ruff check src scripts tests
pytest
Pop-Location
```

```powershell
Push-Location backend
$env:THORP_REQUIRE_DOCKER = 'true'
.\gradlew spotlessApply build
Remove-Item Env:THORP_REQUIRE_DOCKER
Pop-Location
```

명령은 저장소 루트에서 실행한다. DB 통합 테스트는 Docker가 준비된 환경에서 `THORP_REQUIRE_DOCKER=true`로 실행하고 Gradle 결과의 skipped 건수를 확인한다. 단순히 빌드가 초록색이라는 이유로 DB 검증을 통과했다고 세지 않는다. 위 명령은 향후 구현 검증용이며 이 문서 작성만으로 통과했다고 주장하지 않는다.

- 17/17 실제 계열의 PD-11 항목·이용 조건 검증과 기록, 0개 미확인.
