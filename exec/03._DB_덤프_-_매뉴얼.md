## 운영 서버 덤프 생성 매뉴얼

```bash
cd /home/ubuntu/S15P21E205/infra
./scripts/backup-db.sh                # → $DATA_DIR/backup/thorp-<시각>.sql.gz (pg_dump 평문 SQL, gzip)
```

또는 직접:
```bash
docker exec thorp-postgres pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" | gzip > thorp-$(date +%Y%m%d).sql.gz
```

제출 전에 파일을 이 `exec/` 폴더로 옮긴다. `users.password_hash`는 bcrypt라 그대로 둬도 원문이 드러나지 않지만, `email_verifications`·`spring_session*`은 비워도 된다.

## 복원

빈 PostgreSQL 16에 넣는다. 덤프는 스키마 포함 평문 SQL이다.

```bash
docker compose -f infra/docker-compose.prod.yml --env-file infra/.env.prod up -d postgres
gunzip -c thorp-<YYYYMMDD>.sql.gz | docker exec -i thorp-postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1
```

- 덤프에 `flyway_schema_history`가 들어 있으므로 백엔드(prod 프로필, `ddl-auto=validate`)가 그대로 기동한다. 마이그레이션이 더 있으면 기동 시 Flyway가 이어서 적용한다.
- 시장 자료 표(`dataset_version`·`daily_price`·`daily_index`·`corporate_action`·`data_gap`)는 **INSERT 뒤 UPDATE/DELETE/TRUNCATE가 트리거로 막힌다**. 복원 중 이미 행이 있는 DB에 넣으면 실패하므로 반드시 빈 DB에 넣는다.
- 로컬 개발 DB(local 프로필, Hibernate가 스키마 생성)에 넣을 때는 스키마가 달라 `data/sql/load-local-dump.sh <덤프.sql>`을 쓴다(Flyway 순서로 스키마를 세운 뒤 적재).
