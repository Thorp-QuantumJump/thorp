# 백테스트 계산 스펙 (v0.1.1)

백테스트 엔진이 "무엇을 어떻게 계산하는지"를 고정한다. 이 문서가 기준이며,
`worker/src/worker/engine.py` 구현과 어긋나면 문서를 먼저 고치고 코드를 맞춘다. (SDD)

## 1. Job 1건의 정의

성능 측정과 분산 처리의 **작업 단위**를 아래로 고정한다.

> **Job 1건 = 전략 1개 × 파라미터 1조합 × 유니버스 전체 × 기간 전체**

- 유니버스(종목 목록)와 기간은 Job 안에서 고정된다. 종목이 10개여도 Job은 1건이다.
- v0.1.2의 "알고리즘 20개 × 파라미터 전 조합"은 **Job 수가 늘어나는 것**이지
  Job 1건이 무거워지는 것이 아니다. → 분산 처리의 대상은 Job 단위 병렬화다.

이 정의를 바꾸면 baseline 측정치와 분산 측정치를 비교할 수 없다.

## 2. 입력 데이터

- 일봉 OHLCV, 컬럼 표준: `date, open, high, low, close, volume` (`data/CLAUDE.md`와 동일)
- index: `date` (DatetimeIndex, 오름차순, 중복 없음)
- 종목별로 별도 DataFrame. 결측 거래일은 채우지 않는다(거래정지일은 그대로 둔다).

## 3. 신호 → 포지션 (look-ahead 차단)

전략은 **당일까지의 데이터만** 사용해 당일 신호를 만든다. 엔진은 그 신호를 **다음 거래일**에
적용한다.

```
position[t] = signal[t-1]        # shift(1)
```

당일 신호를 당일 수익률에 적용하면 미래 데이터를 쓴 것이 되어 성과가 부풀려진다.
이 `shift(1)`은 엔진이 책임지며, 전략 구현에서 중복으로 shift 하지 않는다.

포지션 값의 의미: `1.0` = 해당 종목 풀 매수, `0.0` = 현금. (v0.1.1은 공매도 없음)

## 4. 수익률과 거래비용

```
asset_return[t] = close[t] / close[t-1] - 1
turnover[t]     = |position[t] - position[t-1]|
cost[t]         = turnover[t] × cost_bps / 10000
net_return[t]   = position[t] × asset_return[t] - cost[t]
```

- `cost_bps` 기본값 **10bp(0.1%, 편도)**. 위탁수수료 + 슬리피지 + 증권거래세를 합친 단순 근사값이다.
- v0.1.1 단순화 사항 — 추후 정교화 대상:
  - 매수/매도 비대칭(거래세는 매도에만 부과) 미반영
  - 체결가는 종가 기준, 호가 스프레드/거래량 제약 미반영
  - 배당 미반영

## 5. 포트폴리오 합성

유니버스에 종목이 여러 개면 **동일 가중(equal weight)** 으로 합성한다.

```
portfolio_return[t] = mean(net_return[t] over tickers)
```

- 종목별로 독립 계산 후 평균. 리밸런싱 비용은 종목별 `cost`에 이미 포함된 것으로 본다.
- 거래일 합집합을 기준으로 정렬하고, 특정 종목에 값이 없는 날은 그 종목을 평균에서 제외한다.

## 6. 성과 지표

| 지표 | 정의 | 비고 |
|---|---|---|
| `total_return` | `equity[-1] - 1` | `equity = (1 + portfolio_return).cumprod()` |
| `mdd` | `min(equity / cummax(equity) - 1)` | **음수**로 저장 (-0.234 = 최대 23.4% 하락) |
| `sharpe` | `mean(r) / std(r) × √252` | 무위험수익률 0 가정, `std`는 표본표준편차(ddof=1) |
| `trade_count` | 포지션이 변한 날의 수(전 종목 합) | 진입·청산을 각각 1회로 센다 |

- 연율화 계수 **252** (KRX 연간 거래일 근사) 고정.
- `std(r) == 0` 이거나 관측치가 2개 미만이면 `sharpe = 0.0`.
- 유효 거래일이 0일이면 모든 지표 0, `total_return = 0.0`.

## 7. 결정론(재현성)

동일한 입력(같은 데이터 스냅샷, 같은 파라미터)은 **항상 동일한 지표**를 낸다.
난수를 쓰지 않으며, 합성 데이터 생성기만 시드 고정 난수를 쓴다.

baseline 실행 결과와 분산 실행 결과의 지표가 일치해야 성능 비교가 의미를 갖는다.
(같은 답을 더 빨리 내야 의미가 있다.)

## 8. 전략: MOMENTUM (v0.1.1 고정 알고리즘)

```
momentum[t] = close[t] / close[t - lookback_days] - 1
signal[t]   = 1.0 if momentum[t] > 0 else 0.0
```

- `lookback_days` 기본 120. 데이터가 부족한 초기 구간은 `signal = 0.0`(현금).
- 파라미터 스윕 시 `lookback_days`를 바꿔 Job을 여러 건 만든다.
