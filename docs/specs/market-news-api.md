# 시장 흐름 뉴스 API 계약

012 시장 흐름 뉴스 묶음이 제공하는 외부 API의 기준 문서다. 기계가 읽는 계약은
[`specs/012-market-news-digest/contracts/openapi.yaml`](../../specs/012-market-news-digest/contracts/openapi.yaml)이고
응답 예시는 같은 폴더의 `examples/*.json`이다. 이 문서와 계약이 어긋나면 계약을 기준으로 하고 이 문서를 고친다.

근거: [spec.md](../../specs/012-market-news-digest/spec.md), [plan.md](../../specs/012-market-news-digest/plan.md),
[data-model.md](../../specs/012-market-news-digest/data-model.md).

## 경로와 봉투

외부 경로의 `/api`는 프록시가 제거하므로 Spring controller 매핑은 `/market-news/...`다.

| 외부 경로 | controller 매핑 | 용도 |
|---|---|---|
| `GET /api/market-news/digests` | `/market-news/digests` | 현재·섹터·과거 뉴스 묶음 조회 |
| `GET /api/market-news/articles/export` | `/market-news/articles/export` | 허가 범위 기사 메타데이터 내보내기 |

응답은 기존 `HttpApiResponse<T>` 봉투를 그대로 쓰고 JSON 필드는 camelCase다. 모든 시각은 UTC ISO-8601이다.

## 상태 네 가지 (spec FR-014·FR-016)

`READY`, `EMPTY`, `STALE`, `PREPARING`은 **모두 HTTP 200**이다. 외부 뉴스원 장애를 오류 응답으로 바꾸지 않는다.
판정 순서는 아래와 같고 앞 조건이 먼저 걸리면 뒤를 보지 않는다.

1. 허가된 매체가 하나도 없으면 `PREPARING`
2. 허가된 매체는 있지만 표시할 자료가 없으면 `EMPTY`
3. 표시할 자료가 있고 `lastUpdatedAt`이 현재보다 30분 이상 오래됐으면 `STALE`
4. 그 밖에 표시할 자료가 있으면 `READY`

`lastUpdatedAt`은 활성화되고 현재 노출 가능한 뉴스원들의 마지막 성공 시각 중 가장 최근 값이다.
최초 수집 전이면 `null`과 함께 아직 수집되지 않았다는 상태 메시지를 반환한다.
STALE 기준 30분은 서버 설정으로 조정할 수 있다.

## 노출 모드

노출 모드는 서버 설정이 정하며 **클라이언트가 고를 수 없다**. query parameter로 내부 모드를 요청하는 경로를 두지 않는다.
공개 모드에서는 회신이 없거나 불허인 매체의 항목이 어떤 형태로도 응답에 들어가지 않는다.

허가·미허가 매체가 섞인 묶음은 조회 시점에 허가된 기사만으로 대표 기사·대표 제목·사실 요약·매체 수·최근성·정렬을
다시 계산한다. 저장된 묶음 행의 값은 전체 멤버 기준이며 공개 응답에 쓰지 않는다.
허가된 기사가 남지 않거나 남은 기사로 요약 조건을 만족하지 못하면 그 묶음을 응답에서 빼고 다른 묶음으로 채우지 않는다.

## 조회 parameter

- `sectorId`는 선택이며 **spec 001이 소유하는 외부 식별자**다. 012는 섹터 마스터를 만들지 않고 값을 참조만 한다.
  형식이 잘못되었거나 등록되지 않은 값은 400으로 거부한다. 001의 대응표가 아직 비어 있으면 섹터 지정 조회는 정상 `EMPTY`를 반환한다.
- `from`·`to`는 과거 조회용이며 둘 다 있어야 한다. 한쪽만 오거나 역전됐거나 요청 구간이 93일을 넘으면 400이다.
- 과거 조회는 발행 시각이 검증된 기사만 포함한다. 발행 시각 미확인 기사는 과거 사례에 연결하지 않는다.

### 세 가지 기간 경계는 서로 다르다

| 경계 | 값 | 뜻 |
|---|---|---|
| 요청 구간 상한 | 93일 | 012가 응답 크기와 질의 비용을 묶으려고 정한 값. 자료가 있다는 뜻이 아니다 |
| 외부 뉴스원 제공 범위 | 외부가 정함 | 012가 통제하지 않는다. 이 범위를 근거로 커버리지를 주장하지 않는다 |
| 보관 종료 시점 | 2026-11-07 | 저장된 메타데이터의 삭제 시점. 조회 상한과 무관하다 |

실제로 반환되는 범위는 세 경계와 실제 수집분의 교집합이며, 자료가 없는 구간은 정상 `EMPTY`다.

## 응답에 없는 것

- 기사 본문·HTML·이미지: 어떤 schema에도 필드를 두지 않는다. 원문은 매체 링크로만 연결한다.
- GDELT Tone, 전망·판정·투자 시사점·수익 원인을 단정하는 문구.
- 뉴스원·API 이름 선택지, 서버 설정, 노출 모드 전환.
- 인증 정보, 뉴스원 접근 주소, URL query string, 외부 응답 원문.

## 식별자

`articleId`와 `digestId`는 대상의 고유한 값에서 결정론적으로 유도한 32자 문자열이다.
같은 기사를 다시 수집해도 같은 식별자가 나오며 내부 저장 순번은 노출하지 않는다.
서로 다른 대상이 같은 식별자를 갖는 충돌은 저장 단계에서 감지해 기존 기록을 덮어쓰지 않고 해당 항목을 제외한다.

## 내보내기 API (spec FR-017)

`GET /api/market-news/articles/export`는 기간·섹터 필터와 cursor pagination을 받는 JSON API다.
페이지당 최대 500개를 반환하고, 매체별 최신 회신에서 허용된 필드만 투영한다.
회신이 없거나 불허된 매체의 항목과 기사 본문은 어떤 경우에도 반환하지 않는다.
spec 006의 기사 내보내기는 저장소를 직접 조회하지 않고 이 API를 사용한다.

## 오류 응답

| 상태 | 쓰는 경우 | 쓰지 않는 경우 |
|---|---|---|
| 400 | 잘못된 기간, 미등록·형식 오류 `sectorId`, 잘못된 cursor·limit | — |
| 500 | 내부 오류 | 외부 뉴스원 장애, 빈 뉴스, 수집 지연 |

뉴스 수집 지연·실패·빈 자료는 뉴스 전용 상태로만 노출하고 서비스 전체 상태 점검을 비정상으로 만들지 않는다.
뉴스 신선도는 전용 health indicator로 노출하며 전체 health 집계에 넣지 않는다.

## 실 뉴스원 검증 정책

실제 외부 뉴스원을 호출하는 검증은 **명시적으로 켤 때만** 수행한다. 기본 테스트는 로컬 fixture만 쓴다.

- 실제 매체 항목이 등록되기 전에는 등록표를 비운 채 fixture로 구현과 내부 검증을 진행한다.
  이때 공개 조회는 `PREPARING`이다.
- 매체 허가 회신(PD-15)은 **공개 게이트**이며 구현이나 내부 검증을 막는 조건이 아니다.
- 실 호출 검증도 공통 HTTP 보안 경계를 그대로 통과한다. HTTPS와 등록된 host만 허용하고,
  redirect 최대 3회를 hop마다 다시 검사하며, 연결 5초·전체 20초·응답 10MiB·허용 content-type을 적용하고
  XML 외부 엔티티 처리를 비활성화한다.
- 외부 뉴스원의 호출 간격과 재시도 제한을 지킨다. 429·503은 `Retry-After`를 우선한다.
