# 배우기 첫 원고

`articles.json`은 spec 013의 아홉 글과 열네 용어 설명을 담은 게시 원고다.
2026-09-18에 운영 관리 화면으로 저장·게시하고 공개 화면에서 확인했다.

## 원고 기준

- 기존 아홉 `articleId`와 열네 `termId`, 읽는 순서를 유지한다. PD-16의 팀 확정을 대신하지 않는다.
- 글마다 질문 하나와 가상의 계산 예 하나를 중심으로 설명한다. 실제 과거 성과를 삽입하지 않는다.
- 본문의 용어 블록은 `terms`의 설명을 재사용한다. 각 용어는 소유한 글에 정확히 한 번 등장한다.
- ‘섹터 모멘텀’과 ‘최소분산’은 주제 제목으로 유지한다. 해당 용어의 표시 이름과 본문에서는 실제 운영 전략 이름 ‘흐름을 따라 배분하기’, ‘전체 변동성을 줄이도록 배분하기’를 쓴다.
- 모든 진입 예시는 반도체(`SEMICONDUCTOR`)·은행(`BANK`) 절반씩이다. 투자 권고나 자동 전략의 계산 결과가 아닌 학습용 입력값이다.
- 외부 참고 자료는 각 글의 `sources`에 남긴다. 외부 자료의 성과·가격·그래프를 복제하지 않았다. 수익·손실의 산술 예시는 자체 작성이다.

## 게시 절차

1. 운영 관리 권한이 있는 계정으로 로그인한다. 관리 경로는 `/admin/learning`이다.
2. 공개 섹터 목록에서 예시 코드가 현재도 유효한지 확인한다.
3. 각 기존 글의 초안을 읽고 작성된 내용이 있는지 확인한다. 다른 사람이 작성한 초안이나 공개 판을 무조건 덮어쓰지 않는다.
4. 원고를 저장할 때 `articleId`를 제외한 글 필드와 방금 조회한 `expectedDraftVersion`을 보낸다. `contentVersion`·최상위 `articles`는 요청 필드가 아니다.
5. 저장 응답의 새 `draftVersion`으로 게시한다. 서버의 게시 전 검사가 거절한 항목은 원고나 예시를 고쳐 해결한다. 검사·권한을 우회하거나 DB를 직접 수정하지 않는다.
6. 공개 목록에 아홉 글이 순서대로 보이는지, 글 본문·예시 진입과 열네 용어의 설명이 맞는지 확인한다.
7. 실제 게시 결과와 판 번호를 기록한다. 게시하지 않은 원고를 게시 완료로 표시하지 않는다.

## 2026-09-18 게시 결과

- 게시 전 운영 `/learn`에서 ‘아직 게시된 글이 없습니다.’ 표시를 확인했다.
- 사용자가 서버에서 관리자 계정과 허용 사용자 ID를 설정한 뒤, 해당 세션의 `/admin/learning` 접근 권한을 확인했다. 비밀번호는 원고나 저장소에 기록하지 않았다.
- 공개 `/api/sectors`: 대응표 `SEM-2026-09-16-001`, `isSample=false`, 두 예시 코드 존재를 확인했다.
- 공개 `/api/strategies/registry`: 위 전략 표시 이름을 확인했다.
- 로컬 검사: JSON 파싱, 9개 글·14개 고유 용어, 용어 블록 대응, 예시 합계 1000, 글당 가상 예시 하나, 용어 길이, 현재 게시 규칙 파일의 금지 표현·결과성 숫자 패턴을 확인했다.
- 기존 아홉 글은 모두 빈 초안(`draftVersion=0`)임을 확인한 뒤 원고를 저장했다.
- 서버 게시 검사를 통과해 아홉 글 모두 `PUBLISHED`, `draftVersion=1`, 공개 `1판`이 되었다.
- 운영 `/learn`에 아홉 글이 읽는 순서대로 노출되는 것을 확인했다.
- 아홉 공개 상세 화면에서 제목·본문·게시일, 총 열네 용어 설명, 반도체·은행 예시와 ‘이 예시로 비중 비교하기’ 버튼을 확인했다.
