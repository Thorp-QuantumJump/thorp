# ADR-0007: 수집 파이프라인은 서버에 배포하지 않는다 — 자료는 로컬에서 만들어 옮긴다

- 상태: 승인 (2026-09-18) — spec 008 묶음 B 구현 시점에 001이 먼저 택한 방식을 규약으로 올림
- 대상: `data/`, `data/sql/`, `infra/docker-compose.prod.yml`, `Jenkinsfile` (Data 스테이지)
- 선행: [ADR-0001](0001-be-layered-package-architecture.md) 계층 구조
- 근거 문서: [spec 001 research](../../specs/001-etf-market-data/research.md),
  [spec 008 spec](../../specs/008-macro-indicator-registry/spec.md) FR-011·FR-017,
  [data/sql/README.md](../../data/sql/README.md)

## 배경

수집 파이프라인(`data/`)은 KRX 시세와 경제지표를 원천에서 받아 정제하고 PostgreSQL에 적재한다.
운영 배포 대상은 backend·worker·postgres·rabbitmq·kafka·nginx 여섯이고 `data/`는 그 안에 없다.
서버 워커는 `MARKET_DATA_URL`로 **서버 PostgreSQL에서** 자료를 읽을 뿐 수집하지 않는다.

001(ETF 시세)이 이 상태로 먼저 운영에 들어가면서 로컬에서 만든 자료를 서버로 옮기는 절차를
`data/sql/`에 만들었다. 008(경제지표 등록·수집)이 두 번째 수집 대상이 되면서 "008도 같은 방식으로
갈 것인가, 아니면 008부터 서버에서 돌릴 것인가"를 정해야 했다. 008은 001과 달리 **정기 재조회**를
요구한다(FR-017: 새 발표분과 최근 N개월을 다시 받아 개정을 잡는다).

## 결정

### D1. `data/`를 운영에 배포하지 않는다. 자료는 로컬에서 만들어 서버 DB로 옮긴다

- 수집·정제·발행은 개발자 장비에서 돌리고, 결과만 `data/sql/` 절차로 서버 PostgreSQL에 적재한다.
  서버에는 수집 코드도 원천 인증키도 두지 않는다.
- 008도 같은 경로를 쓴다. 008용 내보내기·적재 절차를 `data/sql/`에 001과 나란히 둔다.
- 버린 대안:
  - **`data` 컨테이너를 prod compose에 올리고 cron으로 돌린다** — 가장 자동적이지만, 돌릴 수집
    실행부가 아직 없는 시점에 컨테이너와 키 배포만 먼저 생긴다. EC2 자원도 늘어난다.
  - **Jenkins 정기 job으로 돌린다** — 서버 상주 없이 주기 실행이 되지만, 세 인증키를 Jenkins
    credentials로 옮겨야 하고 자료가 서버 DB로 가는 경로가 두 벌이 된다(사람이 옮기는 001,
    Jenkins가 옮기는 008).
- 결과: 자료가 서버로 가는 경로가 하나로 유지된다. 대신 **정기 재조회가 사람 손에 달린다**(D2).

### D2. 정기 재조회는 자동 실행이 아니라 사람이 돌리는 절차다. 대신 낡음이 드러나게 한다

- FR-017이 요구하는 것은 "정기 재조회"이지 "자동 실행"이 아니다. 008 지표는 전부 월별이라
  주기가 월 단위이고, 일별인 001보다 오히려 수동 부담이 적다.
- 사람이 잊으면 자료가 낡는다. 그것을 막지는 못하므로 **드러나게** 한다 — 조회 응답이 마지막 갱신
  시각과 수집 성공·실패·자료 없음 상태를 싣고(FR-011·FR-023), 오래된 자료를 최신으로 표시하지
  않는다. 원칙 VI가 요구하는 것이 "빠뜨리지 않는 것"이 아니라 "빠뜨린 것을 감추지 않는 것"이다.
- 버린 대안: 자동 실행을 전제하고 낡음 표시를 생략 — 자동화해도 원천이 멈추면 자료는 낡는다.
  표시는 어느 쪽이든 필요하다.

### D3. 이 결정은 실측 전까지만 유효하다

- 수집을 몇 달 돌려 재조회 빈도와 소요를 실측한 뒤(T073) 자동화를 다시 판단한다. 원칙 IX가 정한
  대로 실행 한도와 운영 방식은 실측으로 정하고, 기능이 늘었다는 사실만으로 인프라를 먼저
  세우지 않는다.
- 다시 판단할 시점의 신호는 둘이다. 사람이 재조회를 거르는 일이 반복되거나, 재조회 한 번에 드는
  시간이 사람이 지켜보기 어려운 수준이 될 때다.

## 인증키

세 키(`ECOS_API_KEY`·`KOSIS_API_KEY`·`DATA_GO_KR_SERVICE_KEY`)는 이미
`infra/docker-compose.prod.yml`이 backend로 넘긴다. 그것은 backend의 `market` 모듈이 쓰는
것이고, **008 수집은 그 키를 서버에서 쓰지 않는다** — 수집이 로컬에서 도는 한 키는 개발자
장비의 `.env`에만 있으면 된다. D1을 뒤집을 때 비로소 서버로 옮기는 문제가 생긴다.

관세청 키는 공공데이터포털이 URL 인코딩된 형태로 발급한다(`%2F`·`%3D` 포함). HTTP 라이브러리의
질의 인자로 넘기면 다시 인코딩되어 `403`이 오므로 주소에 그대로 붙인다. 키가 틀린 것으로 읽기
쉬운 실패라 여기 적어 둔다.

ECOS 인증키는 발급일로부터 2년 만기다(FR-018a). 만료되면 수집이 끊기므로 만료 전 재확인이
필요하다(T057).
