# ADR-0008: 화면 맥락 도우미는 외부 LLM을 GMS 게이트웨이로 부른다 — 별도 AI 서버를 두지 않는다

- 상태: 승인 (2026-09-24) — spec 015 착수 전 팀 합의를 규약으로 올림
- 대상: `backend/src/main/java/com/ssafy/thorp/assistant/`, `infra/docker-compose.prod.yml`(환경 변수), `.env.example`
- 선행: [ADR-0001](0001-be-layered-package-architecture.md) 계층 구조
- 근거 문서: [spec 015](../../specs/015-context-assistant/spec.md), [계약](../../specs/015-context-assistant/contracts/assistant-api.md), [constitution](../../.specify/memory/constitution.md) 원칙 III·VI·IX

## 배경

결과 화면에서 사용자가 자연어로 결과의 값을 묻고 근거와 함께 답을 받는 기능(spec 015)은 자연어를 이해하고 한국어로 설명하는 모델이 필요하다. 자체 모델을 두거나 학습할 여건은 없다. SSAFY가 제공하는 GMS 게이트웨이 키가 있고, 이 게이트웨이는 `api.openai.com`을 중계한다(`https://gms.ssafy.io/gmsapi/api.openai.com/v1/chat/completions`).

이 기능은 값을 계산하지 않는다 — 서버가 결과 응답에서 읽은 값을 모델이 설명만 한다. 그래서 모델에 요구되는 것은 한국어 설명, 구조화 출력(strict JSON Schema), 함수 호출(도구 요청)이고 깊은 추론은 아니다.

## 결정

### D1. 별도 AI 서버를 두지 않는다. Spring 백엔드의 `assistant` 도메인이 서버 키로 GMS를 부른다

- 새 코드는 `backend/.../assistant/` 한 도메인(ADR-0001 4계층)이다. `ai/` 폴더, Python 서비스, 벡터 DB, 프론트 SDK를 두지 않는다.
- 우리가 하는 일은 넷이다: 프롬프트(리소스 파일 하나), 근거 팩 구성, 도구 정의·실행·검증, 답변 검증·치환.
- 버린 대안:
  - **브라우저가 키로 직접 호출** — 키가 노출되고, 근거·도구·검증을 서버가 통제할 수 없다.
  - **별도 Python AI 서버** — 돌릴 모델 코드가 없는데 서비스와 배포 대상만 늘어난다. 백엔드가 이미 결과 조회 권한과 토큰 판정을 갖고 있어 그 옆이 자연스럽다.

### D2. 모델은 `gpt-5-mini`, 형식은 Chat Completions

- GMS 예시가 확인해 준 형식이 Chat Completions다. `tools`(function, strict), `tool_choice:auto`, `parallel_tool_calls:false`, `response_format:{type:json_schema, strict:true}`, `store:false`를 요청마다 명시한다.
- `gpt-5-mini`를 고른 이유: 이 일은 설명·구조화 출력·함수 호출이고 추론 깊이가 아니다. 15초 예산 안에 최대 3번 왕복해야 해 응답 속도가 중요하다. 최상위 모델은 느리고 과하며, `nano`급은 자리표시자 규칙을 어기는 답이 늘어 검증에서 버려진다.
- 모델명·주소는 코드에 고정하지 않고 `THORP_ASSISTANT_MODEL`·`THORP_ASSISTANT_BASE_URL`이다. 어댑터는 `AssistantModelPort` 뒤에 있어 Responses API나 다른 제공업체로 바꿀 때 어댑터만 교체한다.

### D3. 자료 처리 조건 — 통제하지 못하는 것은 보내지 않는 것으로 갈음한다

- 질문과 근거 팩은 GMS를 거쳐 원 제공업체로 간다. **게이트웨이와 제공업체의 보존·학습·처리 지역 정책은 우리가 통제하지 못한다.** `store:false`는 대화 저장 여부이지 학습 미사용 보장이 아니다. 별도 ZDR 계약은 하지 않는다.
- 그래서 규칙은 셋이다:
  1. 식별자·개인정보를 보내지 않는다 — 공개 토큰, `backtestId`, 계정·이메일, 브라우저 상태는 프롬프트·도구 인자·이력·로그 어디에도 없다. 근거 ID는 요청마다 `F1..`로 새로 매겨 결과 필드 이름도 노출하지 않는다.
  2. 사용자가 질문에 적은 내용은 그대로 전달된다. 서버가 걸러 내지 않는다(걸러 낼 수 없다). 첫 전송 전에 "질문과 답변에 필요한 화면 자료가 외부 AI 처리 서비스로 전달됩니다"를 보이고, 전송은 사용자가 제출할 때만 한다.
  3. Thorp는 질문·답변 원문을 저장하지 않는다. 운영 로그는 페이지 종류·상태·라운드 수·지연·토큰 사용량만이다.
- GMS 운영 정책이 바뀌거나 문서가 생기면 이 절을 갱신한다.

### D4. 비용 상한은 두지 않는다. 무분별·악의적 사용은 한도로 막는다

- 금액 상한을 두지 않는다(팀 합의). 대신 설정값 한도를 둔다: IP별 분당 8회, 결과 토큰별 분당 5회, **하루 전체 1,000회**, 질문 300자, 요청당 도구 라운드 2회·팩 60개, 서버 15초. 하루 전체 상한은 IP를 바꿔 가며 돌리는 경우에도 하루 비용이 무한히 커지지 않게 하는 안전핀이다.
- 숫자는 실측 후 조정한다(원칙 IX). 단일 인스턴스 메모리 한도는 보안 경계가 아니며 다중 인스턴스 전에는 공유 저장소가 필요하다 — 코드에 `// ponytail:` 주석으로 남긴다.

### D5. 키는 서버 환경 변수, 장애는 사용자에게 문구로

- `THORP_ASSISTANT_API_KEY`는 서버 환경 변수에만 있다. 키·모델·주소 셋은 prod에서도 **빈 기본값**(`${THORP_ASSISTANT_API_KEY:}`)이다 — 다른 prod 설정처럼 기본값 없이 두면 미설정 시 기동이 실패하는데, 이 기능의 요구는 "없으면 기능만 꺼진다"다. 하나라도 비어 있으면 `capabilities.enabled=false`이고 기동은 정상이다.
- 모델 장애·시간 초과·응답 검증 실패는 사용자에게 "지금은 질문에 답할 수 없어요. 잠시 후 다시 시도해 주세요."와 재시도 버튼으로 보인다. 자동 재시도는 없다. 다른 자료로 대체 답변하지 않는다. 결과·배우기·시장 흐름 화면과 API는 영향받지 않는다.

## 결과

- 외부 호출 경로가 하나(`THORP_ASSISTANT_BASE_URL`), 새 배포 대상이 없다. 기능은 플래그 `RESULT`로 켜고 끄며 품질 관문(spec SC-001~SC-004)을 넘긴 뒤에만 켠다.
- 모델이 결과에 접근하는 경로는 서버가 정한 읽기 도구 다섯 개뿐이고, 도구는 요청의 결과에 묶여 식별자 인자가 없다. 답의 숫자·날짜는 서버가 채운 값만이다.
- 이 결정은 결과 화면 1차에 대한 것이다. 배우기·시장 흐름으로 넓히거나 제공업체·모델을 바꾸면 이 ADR을 개정한다.
