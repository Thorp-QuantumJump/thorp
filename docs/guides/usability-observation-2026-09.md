# 사용성 관찰 진행 문서 (2026-09 회차)

PD-14가 정한 **한 회차**의 진행 서식이다. 002·003·005·010의 사용성 성공 기준이 이 관찰의
일부이므로([specs/README.md](../../specs/README.md) "공통 검증·완료 규칙") 회차를 나누지 않고
같은 참여자에게 과제를 나눠 준다.

**이 문서는 합격 판정표가 아니다.** 각 spec의 기준은 합격 비율을 두지 않고 **기록과 조치까지만**
요구한다. 채워야 하는 것은 "몇 명이 통과했다"가 아니라 "누가 어디서 막혔고 무엇을 고쳤다"다.

## 참여자

전략을 검증하려는 개인 **6~8명**.

**이 인원은 오류를 찾기 위한 시작 규모이며 수요를 입증하는 표본이 아니다.** 결과 문서에 이
문장을 반드시 남긴다 — 빠지면 관찰 결과가 "쓸 사람이 있다"는 근거로 읽힌다(원칙 VI).

진행자는 화면을 설명하지 않는다. 참여자가 물으면 그 사실을 기록하고, 그것이 곧 '막혔다'다.

## 사전 준비

- [ ] 관찰 대상 화면이 **실제 자료로** 도는지 확인한다. 008 적재와 010 사전 계산이 돌지 않으면
      화면이 비어 과제를 수행할 수 없다.
- [ ] 예시 자료 표시(`versions.sampleData`)가 켜져 있지 않은지 본다. 켜져 있으면 참여자가 보는
      값이 지어낸 값이고, 그 위에서 관찰한 오해는 화면 탓인지 값 탓인지 가릴 수 없다.
- [ ] 참여자별 기록지를 준비한다(아래 서식).
- [ ] 회차 일정을 003·005 담당자와 함께 잡는다.

## 무엇을 '막혔다'로 세는가

002 SC-004의 정의를 모든 과제에 그대로 쓴다. 한 참여자가 어느 단계에서 다음 셋 중 하나에
해당하면 그 단계에서 막힌 것이다.

| | 판정 |
|---|---|
| 가 | 진행자에게 도움을 청했다 |
| 나 | 도움 없이는 그 단계를 끝내지 못했다 |
| 다 | 의도와 다른 값을 넣은 채 다음으로 넘어갔고, 관찰 뒤 확인에서 그 사실이 드러났다 |

**(다)를 세려면 관찰 뒤 확인이 필요하다.** 과제가 끝난 뒤 "어떤 값을 넣으려 했는지" 물어
화면에 남은 값과 견준다. 이 질문을 빼면 (다)는 영영 0건으로 남는다.

**같은 단계에서 두 명 이상이 막히면 그 화면을 고친다.** 고친 뒤 같은 시나리오를 다시 관찰해
두 명 미만일 때 끝낸다(003 T074a).

## 과제

순서를 이대로 둔다. 뒤 과제가 앞 과제의 화면을 지나기 때문이다.

### 과제 1 — 섹터·비중 (002 SC-004)

> 섹터를 골라 비중을 정하고 다음 단계로 넘어가세요.

관찰 단계: 섹터 선택 → 비중 수정 → 합계 맞추기 → 다음 단계 이동.

### 과제 2 — 전략 고르기 (003 SC-006)

> 전략 하나를 고르고 분석을 요청하세요.

단계별로 막힌 인원을 센다.

### 과제 3 — 결과 읽기 (005 SC-002·SC-007·SC-010)

셋을 각각 준다.

1. > 상세를 열지 않고 이 세 숫자가 무슨 뜻인지 말해 주세요.
2. > 손실이 가장 커진 때와 거래 내역, 비용 가정을 찾아 주세요. (진행자 도움 없이)
3. > 이 인쇄물에서 기준과 비교 대상을 구분해 주세요. (회색조 인쇄물을 준다)

3번은 색만으로 구분되는 자리를 찾는 과제다. 회색조 인쇄물을 미리 뽑아 둔다.

### 과제 4 — 경제환경 탐색 (010 SC-008)

> 지금과 고용환경이 가까운 과거를 찾고, 물가에서 다른 점을 설명해 주세요.

**참여자별로 둘을 적는다.**

| 물음 | 왜 보는가 |
|---|---|
| 종합 비교를 열지 않고 분야 탐색만으로 과제를 끝냈는가 | 종합 비교는 선택이다. 그것을 열어야 끝난다면 분야 탐색이 제 역할을 못 하는 것이다 |
| 분야 유사성을 경제 전체의 일치로 오해했는가 | "고용이 비슷하다"를 "그때와 경제가 같다"로 읽으면 이 화면이 하지 않겠다고 한 단정을 사용자가 대신 한 것이다 |

### 과제 5 — 배우기에서 진단으로 (선택)

입문자가 섞여 있으면 학습 → 진단 이동도 관찰한다. PD-14가 "필요하면"으로 둔 항목이라
하지 않아도 되며, **하지 않았으면 하지 않았다고 적는다.**

참여자마다 한 벌 채운다.

```

  섹터 선택      막힘 없음 / 가 / 나 / 다      메모:
  비중 수정      막힘 없음 / 가 / 나 / 다      메모:
  합계 맞추기    막힘 없음 / 가 / 나 / 다      메모:
  다음 단계      막힘 없음 / 가 / 나 / 다      메모:
```

## 결과 문서

관찰이 끝나면 spec마다 결과를 남긴다. 한 파일에 몰지 않는 이유는 각 spec의 task가 자기 폴더
아래 결과 문서를 요구하기 때문이다.

빈 틀을 미리 만들어 두었다. 회차가 끝나면 그 파일을 채운다.

| spec | 남길 곳 | 닫히는 task |
|---|---|---|
| 003 | [usability-2026-09.md](../../specs/003-strategy-settings/usability-2026-09.md) | T074a |
| 005 | [usability-2026-09.md](../../specs/005-result-comparison/usability-2026-09.md) | T083a |
| 010 | [usability-2026-09.md](../../specs/010-economic-regime-search/usability-2026-09.md) | T155 |

010은 `quickstart.md`의 실행 기록에서 그 파일을 가리킨다. 실행 기록에 관찰 결과를 통째로 옮겨
적으면 같은 내용이 두 곳에 남고 한쪽만 고쳐진다.

각 결과 문서에 반드시 들어가야 하는 것.

- [ ] 참여자별 기록(막힌 단계와 오해 유형을 **말한 대로**)
- [ ] 두 명 이상이 막힌 단계와 **그래서 무엇을 고쳤는지**
- [ ] 고친 뒤 다시 관찰한 결과(003 T074a)
- [ ] **관찰하지 않은 항목은 "관찰하지 않음"으로.** 빈칸을 남기면 다음 사람이 통과한 것으로
      읽는다
- [ ] 이 인원이 오류 발견 규모이지 수요를 입증하는 표본이 아니라는 문장

## 회차 뒤에 남는 일

관찰만으로는 PD-14가 닫히지 않는다. PD-14는 참여자·과제·일정·관찰 기준을 정하는 결정이고,
이 회차를 돌린 뒤 실제로 쓴 값으로 [specs/README.md](../../specs/README.md)의 PD-14 행을
갱신해야 확정된다.
